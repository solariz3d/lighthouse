# P-D103-SHADOW — C (CHARLIE), D103 packet 2, on D — Jev as a second judge beside L0 and L3

**Packet:** a sidecar that reads the overseer verdict ledgers, reconstructs the judged input, asks Jev the same question
with the same answers, appends to its own ledger, and reports agreement per judge with a denominator. It never touches
the overseers. **Uncommitted. No live Jev call made.**

## 0 · THE ANSWER

1. **FINDING: the judged input cannot be reconstructed faithfully from the verdict ledgers, so I did not approximate
   it.** A verdict row carries `job_id`, `session_id` and timestamps, but **not the input**. The input lived only in the
   job file, and the worker **deletes** that file after judging (`l2-overseer-worker.js:144`). I measured rebuilding it
   from the session transcript, using the hooks' own extraction cut at the job's `created_at`, against the only ground
   truth on disk (job files not yet consumed): **L2 0 of 2 identical, L3 3 of 5.** In all four failures **the judged
   text is in no line of the session's own transcript**, even by a loose substring search. One is in a *different*
   session's transcript. Scoring Jev on rebuilt input would be agreement over different texts.
2. **What was built instead, faithful by construction:** `consonance/tools/jev-shadow.js` **captures each job file
   before the worker deletes it**. It stores the EXACT prompt the overseer is about to receive, built by the installed
   worker's own builder. The shortest-lived L2 job measured was 8.3 s (median 29.4 s, n = 538), and a 3 s poll
   catches it. Then `shadow` pairs a capture with its verdict by `job_id`, asks Jev with the overseer's own answer set,
   and appends to its own ledger. `report` gives agreement per judge with its denominator.
3. **The overseers are untouched.** It writes nothing under `~/.claude/shell`; job files were checked identical in
   name and mtime after a real capture pass. No hook was edited and no install was run. **The L3 worker is never
   loaded**: it runs `main()` when required, and loading it would make this tool act as the L3 worker and consume a
   real job. Its two prompt functions are compiled from the installed file's source instead.
4. **Tests 22 / 0**, plain and serial. **Mutants 15 applied / 15 caught / 1 NOT APPLIED** (deliberately; §4). One
   **real defect was found and fixed** on the way (§3.2).
5. **Cost, stated before any live run:** the dry run over what is eligible now is **5 calls, about 16,646 tokens,
   about $0.0007**. At the busiest day on record (233 L2 + 302 L3 verdicts) shadowing everything would be about
   **$0.19/day**. **Not run:** the key is not in this pane (the same reason as D102).
6. **For deployment, not mine:** `capture --watch 3` has to run continuously to see anything, and the store needs a
   home (§5).

## 2 · THE SIDECAR, `consonance/tools/jev-shadow.js` (286 lines, sha256 `6a8aa18d5c9711c4`)

| verb | what it does | touches the network |
|---|---|---|
| `capture --store <dir> [--watch <s>]` | copies each new job's EXACT prompt to `<store>/captures/{l2,l3}/<job_id>.json`, with `discipline_sha256` and `worker_sha256` | no |
| `shadow --store <dir> --max-calls <n> [--dry]` | pairs captures with verdict rows by `job_id`; asks Jev about the unshadowed ones, oldest verdict first; appends to `<store>/shadow.jsonl` | yes, capped |
| `report --store <dir>` | agreement per judge: `n`, `agree`, `rate` (null when n = 0), `refused`, and the overseer/Jev confusion pairs | no |

- **The prompt.** L2's comes from the installed worker's exported `buildOverseerPrompt`, whose main is guarded.
  L3's comes from `formatTurns` + `buildOverseerPrompt`, extracted as source from the installed file and compiled
  alone. **If either cannot be found, or the discipline file is missing, capture REFUSES**, because a prompt built any
  other way is not the one judged.
- **The question** is the overseer's answer set. L2: `verdict` drift | clean | abstain. L3: `trajectory` stable |
  deepening | quiet_spiral | crisis, plus `recommendation` none | slow | name | refer_to_human. The state is the
  captured prompt byte for byte. **The option descriptions quote the prompt** where it defines an option, and otherwise
  say *"as the discipline in the state defines it"*. **I did not write definitions**, per the plan's P2 (the schema is
  the claim). This is still a schema, and it should be registered before any rate is read as evidence (§6).
- **Inherited from `jev-ask.js` `ask()`, not re-implemented:** key from env only, scrubbed; loud refusal without a key;
  the ten-pattern secret scan plus the key's own value. **A secret refusal is item-level**: recorded once with pattern
  names only, and never retried. **Every other refusal stops the run** (§3.2).
- **Idempotent:** a `(judge, job_id)` in the ledger is never asked again, and a capture is never rewritten.
  **Hard cap:** `--max-calls` is required, at least 1 and at most 500 per run. A gateway failure stops the run and
  writes no row, so the item is retried next run.
- **Counted, never asked:** `uncaptured`, verdicts whose input is gone (today **6,422 L2 and 8,044 L3**: every verdict
  before capture existed); and `pending`, captures whose verdict has not landed yet.
- **The store has no default.** Captures hold conversation text, and an unplaced file under the data dir makes
  `close.js --check` refuse (the same reasoning as D102's ledger).

## 3 · TESTS, with `fetch` stubbed and a fixture shell dir built from COPIES of the repo's real workers

`node --test consonance/tools/jev-shadow.test.js` → **22 / 0**; `--test-concurrency=1` → 22 / 0. Red first: before
the module existed, the file failed with `Cannot find module './jev-shadow.js'`.

**What the tests pin:**
- **capture:** the L2 prompt equals the real builder's output; the L3 prompt is built **and the L3 job file still
  exists** (proof the worker never ran); idempotent; writes nothing into the shell dir; refuses when the builder is
  missing, when the discipline is missing, and when there is no store.
- **shadow:** pairs by `job_id`, recording both answers, usage and cost; the answer sets exactly as the overseers';
  the state equals the capture byte for byte; idempotent; the cap is hard (5 eligible, cap 2 → 2 calls, then 2
  more); the cap is required and bounded; no key refuses before any call; the secret item is refused, recorded
  **once across two runs**, and the run goes on; a non-secret refusal stops the run and retires nothing; a gateway
  failure stops the run and writes no row; uncaptured and pending are counted and not asked; `--dry` asks nothing and
  states calls and estimated cost.
- **report:** the rate uses its denominator with refusals kept apart (`{n: 3, agree: 2, rate: 2/3, refused: 1}`), and
  n = 0 gives a null rate.
- **CLI:** exit 2 with no store, and with no key.

**3.1 Two of my own tests were wrong and were corrected, both this lap and both new:**
- The builder-missing test expected the name `buildOverseerPrompt`, but the refusal correctly named the first missing
  function, `formatTurns`.
- **The "never retried" test asserted zero calls on a second run.** A refused item makes no call either way, so
  **mutant 8 survived** it. It now asserts one refused row after two runs, and the mutant is caught.

**3.2 A real defect, found while designing the mutants, then fixed and pinned.** The shadow loop treated **every**
`Refusal` from `ask()` as the secret scan and recorded it against the item permanently. A run-level refusal (a
corrupted capture's empty state, or a key problem arriving through `ask()`) would have **silently retired good
verdicts forever**. Now only a refusal whose message is the secret scan's is item-level. The test "a refusal that is
NOT the secret scan stops the run and retires nothing" pins it, and mutant 6 (the pre-fix code) is caught.

**Whole suite, plain:** `node consonance/tools/js-suite.js` → **110 green · 3 failed · 0 silent · 1 canary · 1 not-run
(of 115)**, with `jev-shadow.test.js` and `jev-ask.test.js` both `ok`. The three failures are the known ones:
`carrier-drift.test` and `gen-consumer.test` (the absent `review/` on D) and `stick-waiter` (A's `3d89dfb`).

## 6 · NOT VERIFIED, and what an agreement rate would NOT mean yet

1. **No live Jev call.** The cost is stated above; the key is not in this pane.
2. **Capture coverage at real traffic.** n = 2 in a quiet window. The shortest job lifetime (8.3 s) against a 3 s poll
   says a miss should be rare. That is inferred, not measured. `vanished` counts misses as they happen.
3. **The discipline race.** `METHOD.md`/`WELFARE.md` is read at capture, seconds before the worker reads it. An edit in
   that gap would make the capture differ from what was judged. `discipline_sha256` is recorded, but not compared to
   anything the worker records (the worker records nothing).
4. **The schema is unregistered.** The option descriptions are mine, quoting where possible. Per the plan's P2/P3, any
   agreement rate is a scorer's output only after the schema is frozen by a registration with its own falsifier.
   Until then it is a number, not evidence.
5. **The plan's §7 rule** (*"a scorer reads committed files, never live transcripts, because transcripts hold other
   people's material"*) and this packet pull in opposite directions: the overseer's input IS a transcript excerpt. The
   overseers already send those same excerpts to a model on every turn, and the keeper's 12:55 ruling covers what the
   vendor keeps. **Named here for the keeper, not decided by me.**
