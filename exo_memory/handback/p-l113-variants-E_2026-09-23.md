## 4 · WHAT CHANGED IN THE HARNESS THIS LAP — my own files, and each change is why the run could happen

`consonance/tools/jev-variants.js` (+82 / −15, sha256 `a4170f58…`) and its test (+37 / −0, `69f5543a…`):
1. **`--unit-shas <file>`:** a given unit set matched by `sha256(prompt)` over every capture, whatever its stamp, in the
   given order. A missing sha gets a `missing-capture` row and is never silently dropped.

3. **The 403 stop rule** above.

   transcript, 26 units the librarian's ~80 MB and 7 units Main's ~300 MB. Now each unit keeps the 2 MB before its turn's
   own row, growing to 8 MB if the opening prompt is not inside.
5. **The console prints status only.**
6. **The run refuses to append** to an existing rows file.

**Tests: 35 / 0.** Mutants, under C's heavy-run lock (`hold({cmd:'jev-variants.mutants (E, L113)'})`,
`scratchpad/l113/mutants.js` sha256 `7418f307…`): **25 · applied 25 · caught 24 · NOT APPLIED 0.**
- **The survivor is equivalent in practice:** "the window keeps its partial first line". A line cut mid-row is never a
  whole JSON object, so the parser's own `try/catch` discards it whether or not the window drops it first.
- **One more mutant was DROPPED as equivalent:** "a parentUuid can match as the row". A row naming `end` as its parent
  always comes after `end` in an append-only transcript, and the search takes the first match.
- **Both are named rather than chased with fixtures no transcript can produce.**
- **A real gap the mutants found and I fixed:** "the window is the whole file" survived at first, because my test
  compared a string's character count with a file's byte size, and the fixture's em dashes make those differ. It now
  compares bytes.
