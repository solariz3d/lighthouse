## a · Test discovery (t180 repo)

**What the bare `node --test` picks up, and why.** With no arguments, Node 24's runner globs its default patterns,
which include `**/*_test.js` as well as `**/*.test.js` and `**/test/**/*.js`. So it runs:
- the four `test/*.test.js` files;
- `scripts/platform_test.js` and `scripts/build_platform_test.js`, because of the `_test.js` suffix. Each counts as
  one "test" that passes when the script exits 0.

checked: `node --test --test-reporter=tap` → tests 74; the TAP lines `ok 1 - scripts\\build_platform_test.js` and
`ok 2 - scripts\\platform_test.js`. The per-file sum is 22 + 22 + 13 + 15 = 72.

**The packet's exact script does not work here, so I deviated.** `"node --test test/"` fails on Node v24.14.1: the
runner takes `test/` as a file to run, not a folder.
- checked: `node --test test/` → `✖ test … 'test failed'`, exit 1.
- In a temp copy, through `npm test`: `node --test test/` → exit 1; `node --test "test/*.test.js"` → exit 0;
  `node --test "test/**/*.test.js"` → exit 0.
- **So `package.json` is:**

      { "scripts": { "test": "node --test \"test/*.test.js\"" } }

  That is one script and nothing else: no dependencies, no other fields. The quoted glob is expanded by Node itself, so
  it works the same under npm's `cmd.exe` on Windows and under a POSIX shell.
- checked: `npm test` → `tests 72 · pass 72 · fail 0`. The TAP output has no `scripts\\` entry.

**Would renaming be better?** Yes, as a second step, not this lap. Renaming the two scripts off the `_test.js` suffix
(e.g. `platform-test.js`, `build-platform-test.js`) would make the bare `node --test` honest too, and would stop it
rebuilding `out/` on every run. The plan's Rule 4 says "node --test", and a reader typing that today gets 74. I did
not rename: A is editing `scripts/build_platform_test.js` this lap, and the packet forbids it.
