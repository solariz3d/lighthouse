## The plan's API shape — checked against OpenRouter's docs before building (no call to the API, only the docs pages)
Sources: openrouter.ai/docs/guides/community/jev.md, …/jev-tutorial.md, and the API reference page for `POST /api/alpha/decisions` (`…/alphadecisions/submit-a-decisions-questions-and-answers-request.md`). **The plan's shape is right; two details it did not spell out, both handled:**
- **OpenRouter's yes/no type is `noul`, not `boolean`, and its answer is `{ type: 'noul', noul: <p> }`.** jev-ask's schema vocabulary is `boolean` | `choice` | `score` and its boolean answer is `{ probability }`. On the openrouter route a `boolean` question is sent as `noul` (criteria `{true, false}` and instructions unchanged) and a `noul` answer is mapped back to `{ type: 'boolean', probability }`; `choice` and `score` pass through. **D162's sealed schema is choice-only (`q3`), so it is untouched by the translation** (tested: its questions go out unchanged).
- Documented response: `{ id, model, provider (string), answers, usage: { input_tokens, output_tokens, cost? } }`; documented error statuses include 400, 401, 402 ("Insufficient credits"), 403, 404, 413, 429, 500, 502, 503, 524, 529. `state` may be a string (jev-ask sends a string).
- I did **not** refuse the plan: the shape matches. Note the docs name `~typesafe/jev-latest` as the alias; the code pins `typesafe/jev-1.13`, as ordered.

## What changed — `consonance/tools/jev-ask.js`
- **Route selection is explicit, never silent.** `ask({ route })` and the CLI `--route vercel|openrouter`. With no route named the route is **vercel, exactly as before** (jev-judge / jev-shadow and their suites speak it, and all 199 of their tests pass untouched). **Nothing switches by which key is present:** an `OPENROUTER_API_KEY` alone with no route named is refused ("no AI_GATEWAY_API_KEY … name the route, --route openrouter") and nothing is sent. An unknown route name (`open-router`, `OPENROUTER`, `''`, `null`) is refused, never defaulted. Each route reads ITS OWN variable only (the openrouter route does not fall back to `AI_GATEWAY_API_KEY`).
- **Request (openrouter):** `POST https://openrouter.ai/api/alpha/decisions`, body exactly `{ model: 'typesafe/jev-1.13', state, questions, provider: { data_collection: 'deny' } }`, `Authorization: Bearer <OPENROUTER_API_KEY>` in the header only (a printed `--dry` request carries a placeholder naming the variable). The Vercel body is still exactly `{ model, state, questions }`.
- **Response mapping:** `id` → `generationId`; `usage` → `{ inputTokens, outputTokens, cost }`; `cost` as a string (null = NOT REPORTED, never 0); the **resolved** `model` and the `provider` recorded; result gets `route: 'openrouter'` (the Vercel result's keys are unchanged: tested). The ledger row gains `route`.
- **A wrong resolved model REFUSES loudly (exit 2, a `Refusal`):** the check runs before anything is read as an answer; the message names the model it saw and the generation id (so the accounts can find the spend) and says the answers are discarded. It requires `typesafe/jev-1.13-<suffix>` (`/^typesafe\/jev-1\.13-[A-Za-z0-9._-]+$/`): the bare pin `typesafe/jev-1.13`, `jev-1.12-…`, `jev-1.130-…`, an alias, another provider, a missing or non-string model are all refused. **A dated 1.13 suffix of any form is accepted** (the next patch release is not a fallback).
- **402 / 403 / 429 / 5xx / a non-JSON body / a missing or wrong-typed answer → `GatewayError` (exit 1), no answer invented.**
- **Redaction and the secret scan cover `sk-or-…` and `vck_…`:** two new named patterns (`openrouter-key`, `vercel-gateway-key`; the existing `openai-style-key` already happened to match `sk-or-`, so the new ones are named so a refusal says which). The exact-key check now covers BOTH routes' keys on either route. `scrub` removes the key's own value (placeholder names the variable) AND any key-shaped token (`sk-or-…`, `vck_…`) from every message, including a gateway error body that echoes one; the CLI scrubs stdout and stderr. The Vercel route is kept as a dated trace in the header, citing the plan.
