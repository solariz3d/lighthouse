## 1 · THE SOURCE — one, the app's own rows at both ends. Nothing invented

- **Queued:** `gate_or_queue` (`main.rs:10189`) writes `QUEUED -> <id8> (<n> waiting, <gate>): <label>`.
- **Taken:** `drain_inboxes` writes `WITHDRAWN NOT DELIVERED -> <id8> (…): <label>` (`:10321`) or
  `DELIVERED -> <id8> [<note>]: <label>` (`:10338`), with **the same label** the queue stored (`Queued.label`, `:9945`).

**Those are the only three writers of those prefixes** (grep over `src/*.rs`). So "delivered" **is** recorded, as a drain row
pairing its QUEUED by (receiver, label). There is no P-INBOX file to read: the queue itself lives in memory (`Inbox`). **Measured
on L's board** (`node` over `board.jsonl`): 258 QUEUED, **256 paired with their drain row, 0 orphan drains, 2 unpaired.**

**Both unpaired rows predate a later launch** (09-08, 09-14). A restart drops the in-memory queue **with no row**, so a ring
queued before a restart never drains and is never recorded as lost. The last launch is read from `<data>/stick-waiter.lock`
`at`, the waiter `main.rs` starts first thing in `main` (`start_exit_waiter`). **It is a proxy:** `APP_STARTED_AT` is held in
memory only. **Without that filter, today's pulse would print `QUEUED 6fe15f0a 21470m, chair 12733m` for ever. With it, today's
real line is clean.** If the lock is absent, nothing is excluded, so the error runs toward printing, never toward silence.

## 2 · THE THRESHOLD — measured, and it moved off the spec for the bounded gates

The waits on L's board, split by the gate each ring queued behind (every paired QUEUED→drain):

| gate | n | median | p90 | max | > 3 min |
|---|---|---|---|---|---|
| `stamp=ready` | 135 | **240 s** | **240 s** | 1,133 s | 116 |
| `stamp=working` | 67 | 140 s | **968 s** | **2,119 s** | 32 |
| `prompt not idle`, `NO STAMP`, `STALE` | 54 | ≤ 240 s | ≤ 240 s | 240 s | 36 |
| **all** | 256 | 240 s | 378 s | 2,119 s | **184 (72%)** |

**Why it splits:** the app's own hold rule, `main.rs` `drain_decision`. Behind **`stamp=working` the hold is UNBOUNDED**
(`PaneGate::Working => Drain::Hold`): the ring waits until that seat's turn ends, which is where tonight's stalls were (p90 16
min, max 35 min). **Every other gate is force-delivered at `MAX_HOLD_MS` (240 s, `:9533`)**, which is why so many sit at exactly
240.

**So:** `stamp=working` prints after **3 minutes**, the spec's number, where it means something. Every other gate prints only
**past the bound plus a drain tick, 5 minutes**, when the forced delivery should already have happened, so anything still
waiting is abnormal.

**The spec as written, 3 minutes on every gate, fires on 184 of 256 rings (72%)**, most of them in their last minute before the
app delivers them itself. That is BUILDING.md's wallpaper failure (the 345 prints). **The split fires on 32 + 7 = 39 of 256
(15%)**, all of them real long waits.

**Deviation, argued, and one constant to flip back:** `QUEUED_BOUNDED_MS`. The spec's own test, *"aged 4 min → printed"*,
holds for the stall class. Mutant Q6 is the spec-as-written rule, and a test catches it.

**And this file's §3a rule, "the axis is an event, not a duration", is kept:** the QUEUED row is the event. The duration only
separates a stall from the ordinary wait every ring to a busy seat has.

## 3 · THE LINE

    QUEUED A 4m (receiver busy since 10:00)                     one seat
    QUEUED A 5m, 2 waiting (receiver busy since 10:00)          several rings at one seat — the OLDEST sets the age
    QUEUED librarian 6m (…), chair 4m (…)                       every seat, the librarian and the chair included

- **Every holder, and no lap at all.** Clause 4 is read **before `line()`'s no-lap exit**, because a ring backs up whether or not
  a lap is open. Before, that exit returned no text.
- Seats print as their letter, or as `chair` / `librarian` for the fixed ids, or as the id if unknown.
- It is withheld in a blind window, like the rest of the cross-pane state. An unreadable board is `queue UNKNOWN`, never silence.
- **Cost, measured:** the whole reader runs in **182–218 ms** on L's real board (three runs), and the new scan in ~108 ms
  including node start. The pulse hooks allow **3 s** (`userprompt-submit.js:258`, `userprompt_pulse.py:318`).
