## 3 · THE PRINCIPLE GAP — the tool already says what should happen here, one level up

`state-sync.js:775-787`, at the **git** level:

> *FAST-FORWARD ONLY. A merge on the state tree would mean two machines wrote the same append-only file between syncs,
> and the honest answer to that is a conflict a person looks at — not a resolution this tool invents at 8am.* …
> *Refusing to merge. Two machines appending to the same ledger between syncs is the case the manifest names as its

**At the install level, the same situation is resolved automatically — by replacement.** L's `lap.jsonl` held 488 rows;
the incoming file held 419 that were a strict subset of them; `installTree` wrote the 419 and moved the 488 to the attic
without asking anyone. That is precisely *"a resolution this tool invents"*, in the one place the tool does not apply its
own rule.

grounded in the keeper's `one_house_two_machines_idea_2026-09-08.md:48`, and says nothing about append-only logs. I read
it before proposing anything, so the proposal below does not contradict a recorded decision.
