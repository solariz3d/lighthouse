## What was built (checked: `git diff --stat`, the files below)

**1. The decision**: `consonance/ui/next-move.js` `nextMove({ newerBuild, paneWorking, compactList })`. It returns `'compact' | 'restart' | 'restart-waiting' | 'none'`, exactly as the packet's §1 says.
- **Where it lives, and why:** the top bar is its only reader, and the page applies it on every poll. A `tools/` file would make the app run node for a four-line rule.
- `newerBuild` must be exactly `true`: an unknown value never asks for a restart.
- `view()` turns the facts into what each button shows; `apply()` writes that onto the two buttons.

**2. The facts**: one Rust command, `next_move_facts` (`main.rs`; async, off the event loop). The sources:
- **`newerBuild`:** whats-live.js's rule (`staleness`: "the binary on disk is newer than the running process").
  - In Rust it is `newer_build(exe_mtime(current_exe), process_start())`. `process_start` is taken first thing in `main()`, after the single-instance claim.
  - **Checked against the landing's rename:** after the running exe is renamed, `current_exe()` and `Get-Process` both still name the ORIGINAL path (`exe_probe.rs`, `exe_probe.txt`). So the path's time is the new build's once it is written.
  - Moved aside but not yet written means no file, so false.
- **`paneWorking`:** the X's own reading, `close_needs_confirm(&close_seat_gates(app))`, where any gate not Ready counts as working.
  - **Why this one:** Restart ends the seats exactly as the X does, so it uses the same reading, and Restart and the X never disagree about whether a seat is working.
  - `ui/chain-indicator.js` reads the loop's position from the board, not whether a pane is mid-turn, so it is the wrong source.
  - **The cost of the fail-safe:** a seat whose gate is Stale, Unstamped or Contradicted holds Restart in "waiting" (dimmed). That errs away from the registered failure (glowing while a pane is mid-turn). How often an idle seat on L sits non-Ready: **not counted.**
- **`compactList`:** `close_small_list()`, the same call `close_small_plan` makes for the button's own list. It takes the names close-small.js marks `cut`, plus its `big` and `warmMin`.
  - **Cost:** 166–179 ms a read, six timed runs (`compact_list_cost.txt`, and three earlier at 171/178/179).
  - **How often:** cached for 60 s (`NEXT_MOVE_COMPACT_EVERY`). Warmth is counted in whole minutes, and size changes only at a turn's end.
  - A Compact run clears the cache when it ends, so the glow does not outlive the cut.
  - A failed read gives no list (nothing glows) and is logged once per distinct error.
- The page polls every 5 s. Of the three reads, only the gates and one `stat` are fresh on each poll.

**3. ⟳ Restart**: `#restartbtn` in `#topbar .topctl`, right of "☾ Compact warm seats", **hidden unless `newerBuild`**. Its command is `restart_app(force)`:
- **Refused** while a Leave is running, while Compact warm seats is running, or with no newer build. The reason is shown in an in-app panel, and Consonance stays open.
- **A seat working:** the first call returns `{ asked, working }`, and the page asks in the app (`#restart-ask`, the close window's family: [Keep working] focused, Escape keeps working, [Restart] sends `force: true` once). The seats are read again at the click, never from a 5-second-old poll.
- **Then:**
  - starts `consonance/tools/relaunch.js --pid <this pid> --exe <current_exe> --log <data>/relaunch.jsonl`, detached, with no window, in its own process group, without `CONSONANCE_LAUNCH_ID` (the launch-id rule) or `CONSONANCE_DATA`;
  - checks the helper is still running 500 ms later (a helper that has already exited could not reopen anything);
  - then calls `leave_close_requested`, the same Leave the X's [Close] runs, so every seat is ended and saved as at any close.
- **The helper** waits until that pid is gone (bound 30 min), then opens the exe at the same path. Its outcome is one row in `relaunch.jsonl`: opened, gave up, or refused.
- **Why this and not Tauri's restart:** `AppHandle::restart` starts the new process before this one exits. The single-instance mutex (`claim_single_instance`) is held until exit, so the new copy would be refused as a second instance, and the Leave would be skipped.
- This is `dev/stick-apply.js`'s relaunch pattern. It waits on the app's own pid rather than on "no consonance.exe".
- It starts the exe directly, not `launch.ps1`. launch.ps1 rebuilds when any source is newer than the exe, so a Restart could turn into a build.

**4. The glow**: look B, as he approved it. `.topctl .btn.next-move { border-color: var(--gold-live); box-shadow: 0 0 0 1px var(--gold-live), 0 0 14px 2px rgba(255,194,74,.45) }`. No text glow, no motion; Restart's dimmed state is `opacity: .45`.
- The titles (one line each):
  - Compact: "2 seats are over 300k and worked in the last 50 minutes: compact them now".
  - Restart: "a newer Consonance is built (02:38): restart to use it; every kept seat comes back where it was".
  - Restart waiting: "…; A is working, so restart when it is done".
  - Both owed: "…; compact the warm seats first: compacting needs the app open".
- **One change to the packet's example wording:** "every seat" became **"every kept seat"**. A launch resumes kept panes and the housed seats (`ui/term.js` `restoreKeptPanes` → `resume_pane`). A cold "+ Pane" is not kept and does not come back, so "every seat" would be untrue.

**5. Not touched:** the window's own X, close-small's rule, the loop aura. Compact keeps its own title whenever it is not the move.

## Addendum, 09:4xZ: pane C's line fixed (`p-l233-read-C_2026-11-25.md`), and one more case found while fixing it

**C's line** (checked): when the exe could not be opened, the helper logged `"opened"` and exited 0. Consonance would close and stay closed, and `relaunch.jsonl` would say it had opened.
- **The fix.**
  - The helper now checks that the exe exists before it spawns.
  - `defaultLaunch` returns the child's pid. A spawn that started nothing gives no pid.
  - `runRelaunch` then writes `outcome: "not-opened"` with the exe and the reason, and exits **3**.
  - The reason is "nothing at the path", or "the exe could not be started (…)".
  - The exit-code comment at the top of the file names code 3.
- **One difference from the order's wording:** `defaultLaunch` returns `{ pid, error }`, not a bare pid, so the row can carry the spawn's own reason.

**Found while fixing it** (checked on L): for a file that **exists but is not a program**, Node's `spawn` **throws** (`spawn UNKNOWN`). It does not return a child with no pid. So with C's fix alone, the helper would crash with exit 1 and write no row at all. `defaultLaunch` now catches the throw and returns its message as the reason.
