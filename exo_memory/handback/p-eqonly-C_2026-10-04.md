## 8 · AMENDMENT (the chair, 10:06): SAVE KEEPS THE PREVIOUS VERSION — commit `2a2b187`

The keeper lost TEST 1 to one Close, with no copy from before it. **Commit `2a2b187eb66c91e89a5028c02f9203dd184b4e35`** (`git -C …\c-eqonly-wt log --oneline -1`), 9 named paths, on `fb44284`.

**What it does:**
- **Save:** native `save_track(name, text, stamp)` first MOVES the file it is about to overwrite (`fs::rename`; never a copy and delete) to
  `track-backups\<name>.<yyyy-mm-dd_hhmmss>.t180track`. The stamp is the page's LOCAL time (`localStamp()` in `app/index.html`), and
  Rust checks it is exactly that form; with none, Rust uses UTC. If the new text then fails to write, the moved file is renamed back.
- **Prune:** the newest **20** per track are kept. ONLY files in exactly that stamped form (`<name>.<stamp>[_n].t180track`) are counted or
  removed, so the keeper's hand-made `eq-TEST 1.2339-closed.t180track`, other tracks' backups, and a track whose name only starts the same
  are never touched. **Nothing else in the code deletes anything.**
- **`shell.backupNow(reason)`** (`app/core/coreshell.js`), the ONE function for B. It writes the document AS IT IS NOW (native
  `backup_track`), under `eq-<saved name>`, or `eq-unsaved` for an unsaved track. It resolves `{ file, reason }`, resolves `null` with no
  native side, and REJECTS on a failed write so the caller can refuse its operation.
- **The Close button** (`app/core/panel.js` `closeKept`) awaits `backupNow('before Close the loop')`. **If the copy fails it does NOT close**
  and says so. B's D242 Close takes this call over (B owns it).
- **"Previous versions…"** (`<select id="versions">` beside Open…; `shell.listVersions()` / `openVersion(file)`): lists the open track's backups.
  - Order: the stamped ones newest first, then the hand-made ones.
  - Each shows its time, length and closed/open; a hand-made one shows its file name instead of a time.
  - Choosing one opens it **as an unsaved copy** (no name), so a Save cannot overwrite the current file by accident.
