### B. The anti-inertness clause shares the failure mode it guards against

This is the sharpest thing I found, and it is a *strengthening* of BRAVO's best catch rather than a
refutation of it. The finding — a guard against dead pointers that was green because it could not see
the pointers — is real, and the fix (`DirsGuard::take()` + `set_dirs(&get_state())`) is right.

**But the clause added so it "cannot go quietly inert a second time" is itself gated on the thing
that breaks:**

```rust
if read_curation().is_some_and(|c| c.topics.len() > c.missing_doc.len()) {
    assert!(checked > 0, "the topic map resolves on disk but no line of it reached the intake");
}
```

In the exact failure state BRAVO describes — `DIRS` unset, `data_dir()` falling back — **`read_curation()`
returns `None`, the condition is false, and the assertion is skipped.** Verified structurally:
`~/.consonance/` **has no `resonance/` directory at all**, so the fallback yields `None`, not a
partial read.

**So if `set_dirs(&get_state())` is ever removed or stops resolving, the test goes green and silent
again, and the guard-on-the-guard goes silent with it.** It cannot distinguish *"this machine
legitimately has no curation"* from *"a curation exists and I resolved the wrong directory"* — which
are precisely the two cases that had to be told apart. A form that would bite: assert on the
**configured** resonance path from `get_state()` (independent of `data_dir()`'s fallback), and require
`checked > 0` whenever that path exists.

Filed as an observation on a test that currently passes and currently checks 12 real topic documents.
**I did not change it; `main.rs` is BRAVO's and out of my scope.**
