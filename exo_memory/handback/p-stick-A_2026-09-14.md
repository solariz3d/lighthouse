## 1 · THE TWO QUESTIONS §2 PUT TO A, ANSWERED

### Exit codes — the `EXIT` table in the source, beside the codes, identical with and without `--json`

    0  it ran; no seat stopped        NOTHING_TO_DO · REHEARSED (would carry) · CARRIED (--apply, verified whole)
    1  it ran; ≥1 seat did not carry  STOPPED (a row's stops is true) · FAILED (written, did not verify; wins)
    2  it did not run                 CANNOT_RUN · APP_RUNNING      — nothing read, nothing written, rows []
    3  it broke part-way              CRASHED                       — with --apply, some seats MAY be written

The four states the packet named — *nothing to do*, *done*, *a seat refused*, *could not run* — are
codes 0/0/1/2, told apart inside 0 by `outcome`. **Code 3 is new and it is not decoration:** before it, an
exception mid-`--apply` (for example the receipt `writeCarried` deliberately throws on when it is
corrupt, *after* the seat has been written) printed a stack trace and exited **1** — indistinguishable from
*"a seat refused"*, which tells a launcher nothing was written when something was.

**APP_RUNNING moved from exit 1 to exit 2.** It never read a seat, so reporting it as a seat refusal was
wrong. The three stick scripts branch only on `≠ 0`, so none of them changes behaviour.

### Does a REFUSED row stop the whole run? — **No. Only its own seat.**

With `--apply`, every other seat that can carry **is carried in the same run**, each verified whole on its
own, and the run exits 1 / `STOPPED`. Tested with two seats (`a REFUSED row stops ONLY its own seat`).
**The tool does not implement "carry nothing if a fixed seat refuses"**, and never has — `applyImport`
walks rows independently. So E's §3.3 order is load-bearing: read the rehearsal's rows, decide, then spawn
`--apply` — **and read the `--apply` object's rows too**, because it re-plans from the disk and a fixed seat
clean in the rehearsal can refuse a moment later (the app appending, for one). Nothing is corrupted by that
race; it is still a seat that did not arrive, and only the second object says so.
