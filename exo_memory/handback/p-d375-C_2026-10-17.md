## 0. What it does

- **The melodies.** `app/sound.js` `MELODIES` holds the four 64-step melodies: yearning, shoegaze, occult and afterglow, each `{ title, steps }`, frozen.
  - Each step is `[bass, chord of four, melody note]`.
  - They're copied from `G:\Consonance-tools\b9\mel9.js` as data, since the app can't read G:.
  - checked: `scratchpad/d375/same.out` → "sound.js MELODIES equal mel9.js STEPS and titles, all four: true".
  - A guard at load throws if the melodies aren't the four of 64 steps that `MELODY_NAMES` names.
- **The pick, one per launch.** `createSound(win, { pick = Math.random })` draws the melody once, when the player is made, and saves nothing.
  - The app makes the player once, at page boot: `app/index.html:396`, the only caller.
  - The player exposes `melody`, and hands it to the engine (`engineFor(ctx, { melody })`).
  - A draw outside 0 ≤ r < 1, or a non-number, is refused loudly.
- **The engine.** `createEngine(ctx, { melody })` refuses an unknown name and takes the first melody when none is given (renders, the bands).
  - `step(i, soft)` plays that melody's step `i mod 64`; place walks forward and undo back, as before (the player's `stepOf` now wraps at 64).
  - The synth fallback plays the same melody.
  - The loop close is unchanged.
- **The slots.** Each melody plays on its own slots, `place_<name>` and `undo_<name>`.
  - `SAMPLES.file` maps every slot to a file, and today all four melodies map to `place` and `undo`.
  - `SAMPLES.slots` stays the list of FILES fetched: the same four, so the player's loading is unchanged.
  - `ref` and `gain` stay keyed by file, since they're properties of a recording.
  - **To drop E's eight WAVs in**, for each melody:
    1. point `SAMPLES.file.place_<name>` and `undo_<name>` at the new file;
    2. add that file to `slots`, `ref` and `gain`;
    3. add its sha256 to row 6.
  - The player and `soundrender` then load it with no other change, since `soundrender` now reads the engine's own `SAMPLES.slots`.
- **The tick.** `app/sounds/drag_tick.wav` is `tick_eiano_tik.wav`, byte-identical.
  - checked: `cmp` → identical; sha256 `0c63854e26167115886d2d0fc947362cdc72c82271b12e2bcb5a2cf8fe6cbfa8` on both.
  - **Gain:** E measured it as the engine's drag_tick at the existing gain of 1.852, with the file's own level set to match (`G:\Consonance-tools\b9\level_ticks.js`, E's hand-back §3). So the gain stays 1.852.
  - checked: `scratchpad/d375/bands.out`. Its five tick figures are −40.4 / −31.6 / −29.4 / −29.3 / −29.1 LUFS, equal to E's `eng_ticks4.out` Eiano row.
- `soundrender.js` takes `melody`. `app/sounds/README.md` gains the new tick row and its sha, plus a paragraph on the melody slots.
- **CHANGELOG** `[Unreleased]`, in our own words: two Changed entries (the four melodies, the new tick), and a Fixed entry for D374's climb fix, which had none until now.
