## 2. The box in §1b: as described, with one residual

### 2a. The code matches the hand-back

`finish.js`, "each free point's box":

- **A ringing share has no box.** That is a sign change of `share` against any point within ±3 seq positions in the same piece.
- **The tail has no box.** That is i ≤ 2 when the previous piece is planned, or i ≥ n−3 when the next one is.
- **Every other point is held in [min(0, share), max(0, share)].**
  - A straight's interior (share 0) is therefore boxed at [0, 0], i.e. "as laid".
  - Only its third point from a planned neighbour is free. The tail rows 4 and 9 bound it at 2°.
- **The flips' pins set `share = 0` before the box is built.** Their code runs above the box, so a pinned flip stays at 0.
- **The box is the last projection of each sweep.** So when the loop ends, the box holds exactly, and the rows and bounds are within whatever the last sweep left.

## 3. close()'s retry: only on BAD_CUP, and only once. Yes

`close.js` :304-318:

- **It catches BAD_CUP only.** `e instanceof D.CoreError && e.code === 'BAD_CUP'` retries; every other error is rethrown.
- **It retries once.** The retry calls `closeOnce` directly, never `close`, with `cupRowLeftOut: true`, and a second BAD_CUP propagates. Re-entry is guarded twice: by `!opts.cupRowLeftOut`, and by the retry dropping 'c' from `c2Channels`.
- **Finish never reaches it.** It is skipped when 'c' isn't in the asked channels, and Finish asks for `FINISH_C2`, edges only.
- **Two refinements.** Neither is a defect in the result: the second pass still runs `checkDoc` and refuses anything negative.
  1. **"Only when a cup row was asked for" is checked at the channel level.**
     - It isn't checked against a row that was actually built. With 'c' in `c2Channels`, the seam's cup row is still skipped when the cup is `held` or the seam isn't joined (:377), and `c2Pairs` may hold no 'c' pair.
     - In that case a BAD_CUP from elsewhere is solved again on the same system, and throws the same error a second time: double cost on a failing window.
     - inferred, by reading: I didn't build such a window.
  2. **Any BAD_CUP triggers the retry.** That includes the adapter's and the input's own `checkDoc` (:320). If a retry from some other cause then closes, the report's note blames the curvature row.
     - P already met this: Q13 was not caught until row 6 asserted "no fallback note".
     - Row 6 guards the adapter case. Other causes aren't guarded.
     - A tighter test is whether the throw came from a step taken with the cup row present. That's optional.
