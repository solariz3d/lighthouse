## 2 · WHAT THE CALL SHAPE RESTS ON, with sources

- **`questions` is an OBJECT keyed by name, and `answers` comes back with the same keys.** Source: Vercel's own
  evaluation page, fetched this lap (`vercel.com/docs/ai-gateway/modalities/evaluation`, last updated 2026-09-16), which
  shows `questions: { refunded: {...} }` → `answers: { refunded: {...} }`. The plan's §1 names the types but not this
  shape. "An answer missing a declared question" (plan P1) therefore means **a declared key absent from `answers`**,
  and the error names it.
- **Response fields** from the same page: `model`, `answers`, `usage: {inputTokens, outputTokens}`,
  `providerMetadata.gateway.{cost, generationId}`. **`cost` is a STRING in the docs' example** and is returned
  unchanged. **A missing cost is returned as `null`**: said, not invented, and not a failure (tested).
- **Model id `typesafe-ai/jev`, and boolean needs `criteria` plus `instructions`:** the librarian's live-call
  correction (`librarian/2026-09-21.md` 12:52). **The docs' own boolean example omits `criteria`.** The live gateway
  refused that, so the client follows the live call, not the page.
- **I require `instructions` on every type**, not only boolean. That is stricter than the docs require: every docs
  example carries it, and a question with no instructions is a question nobody can re-read. Named here so it can be
  relaxed deliberately.

## 3 · THE SECRET SCAN, named patterns

Every string that would leave the machine is scanned: `state`, each question's name, `instructions` and `criteria`.

| pattern | shape (see `SECRET_PATTERNS` in the source) |
|---|---|
| `the-key-itself` | the exact value of `AI_GATEWAY_API_KEY`, if set (≥ 8 chars). **The only exact check.** |
| `anthropic-key` | `sk-ant-` + 20+ |
| `openai-style-key` | `sk-` / `sk-proj-` + 20+ |
| `github-token` | `ghp_/gho_/ghu_/ghs_/ghr_` + 36+, or `github_pat_` + 22+ |
| `aws-access-key-id` | `AKIA`/`ASIA` + 16 uppercase or digits |
| `slack-token` | `xox[abposr]-` + 10+ |
| `google-api-key` | `AIza` + 35 |
| `private-key-block` | `-----BEGIN … PRIVATE KEY-----` |
| `bearer-token` | `Bearer ` + 20+ token characters |
| `jwt` | `eyJ….eyJ….…` |
| `secret-assignment` | a name containing `API_KEY/APIKEY/SECRET/TOKEN/PASSWORD`, then `=` or `:`, then 16+ value characters |

**Each has its own test and its own mutant.** A test also asserts that every pattern in the source has a sample, so
a new pattern with no test fails the suite. **The control:** prose that *names* the variable and the prefixes (*"The
key lives in AI_GATEWAY_API_KEY only. Tokens look like sk- or ghp_ and a Bearer header carries them."*) is **sent**,
so the scan can say no. **The test file builds every fake secret by concatenation at runtime.** This repo is public,
and a whole literal token shape in a committed file trips push protection and reads, to every scanner, as a leak.

**What it cannot see, from the header:** a secret format these ten shapes do not describe. They are enumerated, not
closed.
