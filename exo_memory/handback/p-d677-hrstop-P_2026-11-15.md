## What the stop is measured against

**The control's own time, on the same run, run the same way: each mutant is stopped at that time × 3, never under 90 s.** A stop alone is still not
a reading, because load can change during a range (O's ranges went from 404 s to 913 s over the day). So a STOPPED mutant is
counted as caught only when **an unmutated copy, run again at once under the same stop, finishes green inside it.** If that copy is stopped too,
or is not green, the row is **NOT READ (load)**: neither caught nor survived. It is printed as such, and it fails the run. The control itself runs
to completion, up to a 30-minute cap, and a stopped control is not green.

Found on the way, the same flaw from another side: run inside a test runner, the nested `node --test` inherited `NODE_TEST_CONTEXT` and exited
silently with no tally. checked: `G:\consonance-scratch\p-gate\hrstop-probe.js` → `{"pass":null,"fail":null,"hung":true}` in 41 ms. The old
rule read that as CAUGHT ("hung or crashed"). Now `run()` removes that variable and tells a stop (ETIMEDOUT) from a crash. A run that cannot
start throws, and the spawn has `windowsHide`, which it lacked.
