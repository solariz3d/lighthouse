## 2. G2: three false positives and one hole, found beyond the four cases
All three false positives name the link in the reason, so the user can see what tripped it; none touches data.
- **F1 (hole AND false positive, one cause): relative targets after a `cd` are read against the SESSION cwd, not the `cd`.** The Bash tool resets its cwd every call, so `cd <dir> && rm -rf build` is how we write it.
  - `cd <B, whose build/ holds a junction> && rm -rf build`, session cwd elsewhere: **allowed (a hole)**.
  - `cd <A, clean> && rm -rf build`, session cwd = B: **denied (false positive)**, naming B's junction.
  - With ABSOLUTE paths (our usual form) neither happens. **Fix:** carry a `cd`/`pushd` target from an earlier segment of the chain into the base of the later ones.
- **F2 (false positive): a wildcard walks its whole PARENT.** `rm -rf logs/*.log` was denied because of an unrelated junction elsewhere in `logs/`. **Fix:** expand the glob and check the matched entries only, or say plainly in the reason that a wildcard checks the folder.
- **F3 (false positive): the BODY of a heredoc is read as commands** (lines are split on `\n`). `cat > f.sh <<'EOF' … rm -rf <tree with a junction> … EOF`, a script being written, was denied. **Fix:** skip heredoc bodies when splitting.
- Not tested: a file symlink inside a tree (the machine refuses to create one, EPERM, so I could not plant it).

## 3. G1 with NO upstream, `--force`, and a clean push
Works as the packet asks, **for a repo whose remote is `origin` and has a `main`** (`g1.js`, 34 rows ok):
- **Clean push: allow.** A key (vck_, sk-ant-, ghp_, AKIA, a private-key header: each shape): **deny**, the reason `cfg/app.env:2 (gateway key (vck_))` and never the key.
- **`git push --force`, `-f origin main`, `--force-with-lease` with the key still in: deny. After the key commit is reset away: allow, allow.** A key the diff REMOVES: allow.
- **No upstream** (a new branch `feature`, `git push -u origin feature`): clean allow; with a key **deny, scanned from "the merge base with origin/main"**.
- `git -C <repo> push`, `git -C <relative>`, the PowerShell tool, a push after `status && add` in a chain: all scanned.
- Not a push (`git status`, `log`, `pull`): ignored.

**But three holes, each a push that carries a key and is ALLOWED:**
- **H1: the first push of a new repo to an EMPTY remote.** The remote has no refs, so there is no `origin/main` to take a merge base with, and the gate fails open and scans nothing (`allow-error`). The first commit held a `.env` with a key: **allowed.** This is the push where secrets most often go out.
- **H2: a remote not called `origin`, no upstream.** Only `refs/remotes/origin/*` are tried: **allowed.**
- **H3: a key ADDED in one unpushed commit and REMOVED in the next.** The gate scans the NET diff, which is clean; the key is in the history that is pushed (confirmed with `git log -p base..HEAD`). **Allowed.** **Fix:** scan every commit's added lines (`git log -p --format= <base>..HEAD`), not the net diff. This one also makes the "amend or rebase" advice in the reason matter: a later commit that deletes the line does not help.
- **Fix for H1 and H2 together:** when there is no base, scan everything reachable from HEAD that the remote does not have (`git log -p --format= HEAD --not --remotes=<that remote>`), or the whole history for an empty remote, instead of failing open.

## 4. G1 and G2's shared blind spot, `cd <repo> && git push` (the same as F1)
- `cd <repo with a key> && git push` with a session cwd that is NOT a repo (a sibling instance's is not): **allowed**, ledger `allow-error: not a git repo`. **A hole for every seat whose cwd is not the repo, which is every sibling instance**; `git -C <repo> push` is handled, `cd … && git push` is not.
- `cd <clean repo> && git push` with a session cwd that IS a repo holding an unpushed key: **denied (false positive)**, scanning the wrong repo.
- **Fix:** the same `cd` tracking as F1.
- Also, E's own named limit confirmed: `git commit -m "notes on git push"` with an unpushed key in the history is **denied** (a commit refused over the words).
