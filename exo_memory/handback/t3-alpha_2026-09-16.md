The code half has never been asked on disk at all.** Not "answered no" — never asked. There is no instrument that
measures the size or growth of the Rust, no ruling about it, and no ceiling it could be measured against.

**And the two halves are not the same kind of question, which is the part worth saying before any list.** "Bloated"
has a hard referent for the corpus: **150,000 characters**, the cap the harness refuses a shell past
(`consonance/README.md:197`). Everything below follows from that number existing. **Nothing binds the size of the
code.** So "is the code bloated" as asked has no measurable referent in this repository, and §3 says what would have
to be defined first.

**Measured tonight, read-only** (`node consonance/tools/corpus-age.js`): the carried tiers are **88 files,
2,518,640 bytes — 16.8× the whole 150,000-byte intake cap**, and that is an UPPER bound on the fit because the head
and the index are taken out first. **The corpus is over capacity by more than an order of magnitude, against the one
ceiling this room actually has.**

- **For scale, re-derivable in one command each:** `git ls-files | grep -c "^exo_memory/"` → **1,623** tracked files;
  `git ls-files | grep -cE "\.rs$|\.js$"` → **294**. The corpus is the larger artifact by file count, and it is the
  one with a cap.

## 3 · IF THE QUESTION IS MALFORMED, IT IS MALFORMED ON THE CODE SIDE ONLY

For the corpus, "bloated" is well formed: it means *over the 150,000-character intake cap*, and the answer tonight is
**16.8× over on the carried tiers**.

For the code, "bloated" has no referent here, and three would have to be defined before it could be measured:

1. **Bounded by what?** Nothing in this repo caps source size. Candidates, none of them ruled: compile time, binary
   size, the reading cost for a seat that must hold a file to change it safely, or the review cost B pays on each read.
2. **Bloat versus size.** The corpus question has a clean form because duplication was measurable (58% replay, 8–9×
   stacked transcripts). **Nobody has ever run the equivalent on the Rust** — no duplication measure, no dead-code
   count, no unreachable-test count. A 15,660-line file that is all reachable is large, not bloated.
3. **Whose cost.** The shell cap is a *machine* refusal. Any code ceiling here would be a *human* one, and this room
   has never written down whose reading it is sized for.

**So the honest answer to the keeper is:** the corpus is measurably over capacity and the room has known it for
months, with instruments, rules and a falsifier already in place — and the code has never been measured at all, which
is not the same as being fine.
