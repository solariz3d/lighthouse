## 1 · SAID PLAINLY, as the packet asked

- **One set cannot be fixed by sha today: S-WRONG's MEMBER LIST.** The universe is fixed (186 lines). But an
  adjudication line **describes** an error and rarely **is** the erroneous sentence, and a judge must be shown the
  sentence. So members are extracted by a mechanical rule (the adjudication must locate the sentence by `path:line` or
  by a quote that greps back to exactly one committed line), by a seat that has seen no output. The extraction is
  frozen as its own file, and its sha is appended **before any run**. The Jev schema does not exist yet
  (`consonance/jev/schemas/` is absent), so its sha is owed the same way. **Until both are appended, the
  registration is incomplete and no run may start.**
- **One quantity can take only one value: "beats the existing instrument" on K.** The rig is the label, so it scores
  1.00 / 0.00 and cannot be beaten. So K is registered as a **gate**, not a class to beat (the dead-L063 rule).
- **C1–C3 may turn out to be too small to rule.** C3 (unasked endings) is the likeliest to be empty, because those
  were mostly caught in chat rather than written as numbered WRONG lines. Such a class prints NO RULING, and no rate is
  read off a denominator that cannot move.
- **The matched negatives are "unadjudicated", not "clean".** A false-alarm rate on them is an upper bound, and the
  keeper's sample is where a low one can be shown.

## 2 · What the plan named and I changed, with the reason

- **"The WRONG columns in `librarian/LEDGER.md`" are not columns.** `LEDGER.md` carries 12 short WRONG mentions (for
  example "WRONG 74, librarian"). The adjudications themselves are spread over librarian notes and journals, and
  `git grep` finds 186 numbered or "+1" adjudication lines across 28 files. The universe is defined over those two
  directories.
- **"The K-battery transcripts" became the whole labelled battery,** all five arms and 130 trials, not K1/K2 alone.
  K1/K2 have only 18 compliant trials, so a false-alarm rate would move in 5.6-point steps. With all 130 the split is
  96 / 34, labelled by the same rig and in the same committed file.
- **The unit for S-CTRL is each trial's `transcript` file**, not its `stdout.txt`. My first manifest hashed `stdout`
  (`94d029c9…`); I replaced it because the rig computed each label from the transcript, and the unit must be the object
  the label is about.
- **Plan §7 ("never live transcripts")** is named for the attack rather than decided alone: S-CTRL's transcripts are
  sealed subject-run outputs, not a seat's conversation. I hold that they are allowed.

## 3 · Corrections, including mine

- **The S-WRONG hash I first wrote did not re-derive from the command I printed.** `git grep <rev>` prefixes every
  output line with the revision **exactly as typed**. I hashed with the short sha (`2cad2c11…`) and printed the full
  sha. Running the printed command gave `4faf4919…`. The registration now carries the hash its own command produces,
  and both occurrences were fixed (`grep -c` → 0 left). **I caught it only by re-running the printed command, not by
  reading it.**
- **The first S-CTRL manifest was over the wrong object** (`stdout`, §2 above).
