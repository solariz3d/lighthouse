## 3. A detail of the measure, stated so it can be checked

"The first frame after it" is the first frame **over 0.5 ms** in the window, the same filter the row already used. If a change's very first frame is idle (≤ 0.5 ms) and a later one is busy, the handler is added to the busy one. That can only read high, never low. It is the same computation as D484's `perframe.out` figures, which the ruling accepted.
