## The line: when the exe cannot be opened, the helper says "opened" and Consonance does not come back

checked: `p-l233-read-C_2026-11-25_evidence/README.txt`, row 1.
- The set-up: a dead pid (checked ESRCH first) and an exe path with no file.
- The helper exits **0** and writes one row to its log, **`"outcome":"opened"`**. Nothing was opened.

- **Why** (row 2, `spawn_err.js`). On Windows, node's `spawn` of a missing exe returns at once with `pid` undefined. The ENOENT
  arrives as an `error` event afterwards.
  - `defaultLaunch` (`relaunch.js:59-64`) swallows that event (`child.on('error', () => {})`).
  - `runRelaunch` then logs `opened` (`:79`), and `process.exit` (`:84`) ends the process before the event can fire at all.
- **What he would see:** he presses Restart (or Restart in the question), every seat is ended, Consonance closes and stays
  closed. `relaunch.jsonl`, the only place this process can speak, says it opened.
- **When it happens:** Restart is offered only while a newer exe is at the path (checked at the click, `restart_app`). The
  helper opens it only after the Leave ends, which can take seconds, or minutes with a stick waiting on his click.
  - In that window a landing can rename the exe aside and rebuild it at the path, and B's own R2 row ("moved aside, not yet
    written") is exactly that state.
  - A file still being written or locked fails the same way. inferred: that failure is also synchronous (pid undefined) on
    Windows; I did not run a locked-file row.
- **Not covered:** B's 8 helper rows have no row where the open itself fails.
- **The smallest fix (B's to make):** in `defaultLaunch`, return `child.pid`. In `runRelaunch`, when it is undefined, log
  `outcome: "not-opened"` with the reason and the exe, and exit with a new code (3). Optionally `fs.existsSync(o.exe)` first, so the
  row can say "nothing at the path".
  - The row that goes red first: the real file, a dead pid and a missing exe. It must give a non-zero exit and a `not-opened`
    row. Today it gives exit 0 and `opened`.

It should not land until that row is green. Everything else I checked is clean.
