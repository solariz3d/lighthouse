## 0 · WHAT IT IS

The keeper: *"system agnostic and just run through consonance itself no matter what hardware its running on ... jev
is a requirement for consonance"*. So judge mode is a **mode of `jev-shadow-runner.js`**, the process `main.rs`
already spawns on every launch on every machine. **No machine switch exists anywhere in it.** It ships when the runner
next starts, at the next launch or by restarting the runner by hand.

1. **Capture (every 3 s tick).** For each LIVE SEAT, if its transcript's last assistant row says `stop_reason:
   "end_turn"` (the moment the Stop hook fires) and that turn is new, it builds **now** the same input the L2 and L3
   hooks would build at that Stop, and stores the exact prompts.
2. **Ask (on the shadow cadence, after the shadow).** Each stored prompt not yet asked goes to Jev with the overseer's
   **own** answer set (jev-shadow's `JUDGES`: L2 `drift|clean|abstain`; L3 `trajectory` + `recommendation`). Each
   answer is appended to **`<store>/jev_judge.jsonl`**, every row `judge:"jev"`, `unverified:true`, `level`,
   `session_id`, `turn_uuid`, prompt and discipline hashes, model, usage and cost.
3. **Never the overseer ledgers.** `l2_overseer.jsonl` and `l3_overseer.jsonl` are never opened for writing. A test
   pins both byte-identical, and the mutant that writes there is killed (§3).
4. **One daily cap for both modes** (600): `callsToday` counts the shadow's ok rows plus judge mode's.
5. **No key:** the runner already refuses at start with one logged line and makes no call. `judgePass` also refuses
   before any call, and does so even with nothing to ask (a surviving mutant made me pin that).
6. **If judge mode cannot run** (no data dir, a hook function missing), it logs why **once** and the shadow runs exactly
   as before. It never stops the runner; a test pins this.

### How the judge's input is made — LIFTED BY SOURCE-LOADING, not copied (the packet asked which)

- **The views:** `readNarrowedView` from `dev/shell/hooks/l2-overseer.js` and `readTrajectoryView` from
  `l3-overseer.js`. **Both hook files call `main()` when loaded**, so neither is required. The functions, their helpers
  (`safeParseJSON`, `extractText`) and the L3 constants (`TRAJECTORY_TURNS`, `PER_TURN_CHARS`, read from the source as
  text) are cut out with C's exported `extractFunction` and compiled alone. **No copy lives in my file**, so a change
  to the hook's function is followed automatically. A function that goes missing is a Refusal, which turns judge mode
  off.
- **The prompts:** the L2 worker's exported `buildOverseerPrompt` is **required**, since it has a `require.main` guard.
  The L3 worker's `formatTurns` + `buildOverseerPrompt` are source-loaded, because that worker has no guard: the same
  reason `jev-shadow.js` compiles it alone.
- **From THIS checkout, not the installed copies.** The shadow deliberately reads the installed workers, because it
  compares against the installed judge. Judge mode must be the same on every machine, so it reads the repo. Likewise
  the disciplines: `METHOD.md` and `WELFARE.md` at the checkout root. The workers read `~/Desktop/lighthouse/…`, a
  literal that names D's layout.
- **Faithfulness is tested, not asserted:** the L2 prompt judge mode stores is **byte-identical** to what the repo's
  worker builds from the hook's own view of the same transcript.

### The seats — the app's own list, not a hook

## 4 · AN INCIDENT OF MY OWN — a test sent a real prompt to the gateway, under a fake key

**What happened.** C's CLI test *"the process exits 0 by itself when the app it watches exits"* spawns the real
`main()` with a fake key, using `cliEnv`, which spreads `process.env`. **This pane's environment carries
`CONSONANCE_DATA=C:\Consonance\data`.** With my new defaults, `main()` pointed judge mode at the real roster and the
real transcripts. In that test's store (`%TEMP%\jev-runner-Bp1Hs8`) judge mode **captured four real seat turns** (Main,
the librarian, B, and one more), and the judge pass **sent at least one real prompt to the Vercel gateway with the fake
test key**:

    2026-09-22T08:52:54.635Z judge error (next cadence retries): gateway returned HTTP 401: {"error":{"message":"Authentication failed",…}}

**What it cost:** authentication failed, so no model ran and nothing was billed. But **real conversation text left
this machine under a test**, over TLS, to the provider the keeper chose for Jev. I cannot recall it; the gateway
received it and refused it. **The keeper should know this happened.**

**What I did:**
1. **Deleted that test store** (4 capture files of real conversation, which I had created).
2. **Scanned every other test store** for real seat ids or a 401: none, then and after the re-runs.
3. **Made `cliEnv` hermetic:** `CONSONANCE_DATA` and `CLAUDE_PROJECTS_DIR` now point at an empty temp dir.
4. **Added one assertion** to that CLI test: its store must hold no `judge-captures`.
5. **Made `run()` safe by construction:** judge mode is on only when handed BOTH a data dir and a projects dir. Every
   direct `run()` test gets neither unless it builds a fixture world, so none of them can reach the real seats.

**The lesson, which I'll carry:** a new default that reads the real world has to be checked against every existing
test that runs the real entry point. The env those tests inherit is this pane's, not a clean one.
