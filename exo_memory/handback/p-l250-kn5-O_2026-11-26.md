The packet carried B's rule (`kn5road.js` in the L243 evidence): a mesh is a surface when the **run of letters** after its leading digits equals a key.
On L that rule misses road wherever a valid key holds a `-` or `_`: a key spelled like `TARMAC-X` names meshes like `21TARMAC-X011`, and a run of
letters can never equal it.

  - checked: `node evidence/survey_rules3.js` → `"run":19092220` against `"all":30781955` triangles over all 61 layouts.
  - checked: `node evidence/survey_rule.js` → all 5,448 disagreeing meshes are that one case (shape A: the valid key holds a non-letter);
    there are 0 cases of a longer word being taken for a shorter key.
- **The reader's rule:** a mesh is valid track when its name, after one or more leading digits, **starts with** a valid key (case-insensitive).
  Stripping exactly one digit instead finds almost nothing (12.2M of 30.8M), because names like `01ROAD` and `21ROAD` are common.
- **inferred, not read from AC's code:** that this is AC's own rule. It is the simplest rule every installed layout agrees with. Those 30 layouts
  are installed and drive, so AC must be matching more than a run of letters.
- **For B's three references** the rule adds 531, 1,287 and 1,287 triangles. The kn5 reading itself is unchanged (next section).

This is not a refusal. The kn5 format and surfaces.ini say what the packet assumes. Only the matching rule in the first look was narrower than AC.

## The bytes the page gets, and a decoder for B

Little-endian, every block 4-aligned, so typed arrays lie over the one ArrayBuffer without a copy. The format is in `kn5road.rs`'s header:

    "T180ROAD" · u32 format 1 · u32 J · J bytes of JSON, space-padded to a multiple of 4:
        { files, missing, meshes, triangles, vertices, keys: [the valid keys], surfaces: "layout" | "track" | "defaults" }
    u32 B batches, then each: u32 nv · u32 ni · f32 positions[nv*3] (AC's own metres and axes) · u16 indices[ni] · 2 zero bytes when ni is odd

- Batches hold at most 65,536 vertices, so the shadow pass draws them with `UNSIGNED_SHORT` as it already does. A mesh is never split.
- **No normals are sent:** positions and indices only, as the packet says. The frame timing used up normals, as B's kn5 picture did.
- Positions are in the track's own coordinates. Placement is the Line mode's: the AI line's start onto his start, as B's kn5 picture.
- **A decoder that has read the real bytes:** `window.__decode` in `evidence/ft.js`, written from the header alone.
  - checked: it decoded all four roads in the page, 0 page errors, and the renderer's own triangle count equals the header's (below).
