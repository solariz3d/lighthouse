## 2. The rule (test/inner_run.js)

- **Native:** a file-level `not ok` with `exitCode >= 0xC0000000` (a Windows exception status), or with a fault signal (SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGABRT).
- **Exit 1 is not native.** It is a failing test, or a module that throws on load, and a mutant that breaks loading is a real catch, as before. core_xsec's runner accepts a SyntaxError with 0 tests as a catch, and that path is untouched.
  - This is narrower than the brief's "a child exits non-zero". Reading every non-zero exit as NOT TESTED would turn load-time catches into reds and break "every mutant caught as before".
  - What would change my mind: a native death that reads as exit 1. E's `fmt` self-kill reads exit 1, and I treat a kill as no crash.
- **"No failing subtest":** a dead file that also reported a `not ok` of its own (by `location` under that file) was tested, so it isn't reported.
- **A missing TAP copy throws** ("the inner test run wrote no TAP copy …; the mutant was NOT TESTED").
