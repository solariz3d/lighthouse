## 2. How it works, briefly

- **The whole program runs in the webview:** the document model, `resolve`, and C's geometry and E's validation when
  they mount. So no mesh data crosses IPC, during a drag or otherwise (ARCHITECTURE §9). The native side only keeps
  files, by name, in `<app data>/tracks/<name>.t180track` and `<app data>/library.t180lib`.
- **The CommonJS problem, solved without a bundler.** `src/` is CommonJS so that node runs it as-is, and the webview has
  no `require`.
  - `build.rs` mirrors `app/` and `src/` into `dist/`.
  - `app/lib/cjs.js` fetches the entry, follows its relative requires, and evaluates each file once.
  - A node built-in is refused loudly, by name.
  - Tested: the shell loaded through the loader builds a byte-identical track to the shell node loads.
- **The palette at the open end** lists the built-in words and then "My pieces" (the user's library). It has the font,
  tempo and turn pickers, Undo / Redo / Remove head, the track as a list (click, and shift-click for a run), and "Save
  selection as my piece".
  - A built-in word is placed with the pickers. A saved piece keeps its own fonts and tempos.
  - Every edit is one undo step, and a failed one changes nothing and shows the model's own message.
- **Save and open** use the canonical text. Opening starts a fresh history, so undo does not reach back into the
  previous track (tested after mutant A6).
- **The seam (`app/README.md`):**
  - Each panel directory (`preview`, `camera`, `validate-ui`, `handles`) has an `index.js` exporting `mount(root,
    shell)`.
  - The shell API is the whole contract: `getState`, `subscribe`, `sculpt`, and `beginDrag` / `dragTo` / `endDrag`.
  - A missing panel shows a "not plugged in yet" line, and the rest works.
  - The camera reads the head from C's `path.head`, not from the shell.
  - Keys are claimed in `index.html`, so two panels never bind the same one.
