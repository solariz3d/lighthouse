## 3. A separate defect, checked: every close's publish is refused, by the Leave's own file

`C:\Consonance\data\state-sync.push.json` (08:07:37 UTC) reads `"outcome": "REFUSED_UNPLACED"`,
`"paths": ["stick-leave.result.json"]`. Every Leave writes `stick-leave.result.json` into the data folder, and
`state-sync.js:525-530` refuses to push while any path "matches no rule". **So as long as that file matches no rule in
`consonance/state-manifest.json`, no close will ever publish.** Checked: `grep -n stick-leave consonance/state-manifest.json` finds nothing. Tonight's three publishes were all refused within 1 s
(`LEAVE PUBLISH REFUSED — Nothing was published.`).
- Whether the two earlier refusals (09-25 16:40 and 09-27 00:06 UTC) had the same cause is not known: the push file
  keeps only the last run.
- **Not fixed:** a manifest rule is the keeper's or the chair's call (it decides what travels). Whatever the fix, it
  should be ruled in the manifest; the refusal names that as the remedy.
- **Not the Close bug either:** two earlier refused publishes still closed normally.

## 4. The step that settles it, and changes nothing

At the next Leave, once "Close Consonance" does nothing:
1. **Look under the button for text**, red or not. Red text means `leave_exit` answered with an error, which the code
   says is impossible, so it would be the finding.
2. **Click a tab button** (Instances or About). If the tab changes, the page's scripts are alive and the problem is the
   one call; if nothing changes, the whole page is frozen.
3. **Before ending it:** Task Manager → Details → right-click `consonance.exe` → **"Create memory dump file"**. The dump
   holds every thread's stack, including what the main thread is doing. Then end the task.
4. **Optional, the keeper's call because it changes how the app is launched:** launch once with
   `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<a free port>`, and I can read the page's console at
   the moment of the click (read only). A JavaScript error or a failed IPC request would show there.

**If the dump shows the main thread idle and the console shows no error, the IPC path is the suspect.** At that point a
test on a debug build could show whether this build's invoke reaches any command at all after the Leave.
