## How I judged (the rulings I had to make, stated so the librarian can weigh a B/C split)

- **The turn was rendered whole for every message.** `render.js` renders the prompt, every tool call and its result in the turn, and the claim's own message uncut (thinking blocks are left out, since a seat neither says nor shows them).
  - **CHECKED** needs a tool call on the claim's object AND a shown result that the claim reports, in the same message or turn, before the claim (§3).
  - The turn's prompt and an earlier turn do not count as a check.
- **R1: code is not a claim.**
  - A declarative sentence the seat wrote is a claim, whether it sits in prose, a comment, a document, a commit message or a test title naming an outside fact.
  - Code, commands, paths, search strings, regexes, test assertions and strings a script prints, when they sit inside tool calls, are instructions to a tool. Each is NOT A CLAIM, even when it presupposes a state.
  - This is the largest source of NOT A CLAIM: the readers extracted many code fragments from Write, Edit and Bash calls.
- **R1b: a comment can be code, or a claim.**
  - A comment or script header that only describes the code it annotates, written in the same edit, counts as part of the code: NOT A CLAIM.
  - A comment that asserts an OUTSIDE fact is a claim. Examples: what an old test said, what another file does, what a commit contains, what the input files look like.
- **R2: items worded as a check.**
  - Some reader items are only an instruction ("Check that …").
  - If the statement the item refers to can be identified in the message, I judged that statement.
  - If not, or if that statement is itself a plan or code, the item is NOT A CLAIM.
- **Future, intent, plans and instructions** to the keeper or another seat are NOT A CLAIM (§4, C's hard cases). This includes the rule a seat is about to build and what an install will carry.
- **An uncommitted change is judged against the commit that landed it, within 24 h.** Most claims describe a change a seat had just made. Where the seat's own transcript shows the act (its Edit or Write) and the landing commit carries the same content, I used the commit plus the transcript as the as-of source (§4 items 1 and 3).
