## 1 · What I changed anyway, and why it is a pin, not a fix

The packet's invariant, *"a 'delivered' result is never returned for a text that hasn't rendered"*, was **already true in
the code** (`await_render` → `Receipt::Received` only on rendered bytes after the write offset; existing tests
`only_bytes_after_the_write_count_as_evidence`, `an_empty_needle_can_never_confirm`). But the sender-facing reply string
was chosen **inline, twice** (`librarian_call_exec`, `pane_call_librarian_exec`) with no test on it. So a future edit
could return "delivered" off `Ok(_)` from the write and every test would stay green.

- New pure fn `ring_reply(dest, receipt)`: byte-identical wording (`delivered to <dest> (rendered in its pane — not proof it
  was read)` / `written to <dest> — UNCONFIRMED (…)`). Both executors now call it. The board audit rows are untouched
  (chain-status reads `call_librarian <letter> -> LIB [Received]`, unchanged).
- New `mod ring_reply_tests`, 3 tests:
  1. Received → the exact existing words, for Main and the librarian;
  2. Unconfirmed / NotAttempted → never "delivered to", always "UNCONFIRMED";
  3. source order in BOTH executors: `gate_or_queue` (busy receiver → QUEUED + board row) → `inject_to_pane` →
     `await_render` → `ring_reply`, and no other "delivered to" string in either body.
