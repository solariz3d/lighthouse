## 1. The floor against the world (point 1)

## 4. extend's clamp against a fit that rings (point 4): the one defect

- **The guard as built:** `extend.js:163-165` clamps each side to `[max(lo, floor), cap]`, with `lo = min(0, start, target)`. Its upper end is the cap, as before. The old guard was `[0, cap]`.
  - Its job, together with "ends flat" (`:166`), was that a side asked back to 0 lands at exactly 0, so the next piece starts plain and a lap can close.
  - That still holds coming down from a positive edge. It doesn't hold coming up from a negative one, because ringing above 0 is only bounded by the cap.
- **The measurement** (`probe5.js`): one numeric transition of 40 m on a 60 m piece, after a piece that set the edge.

| case | tree | controls | ends |
|---|---|---|---|
| +45.5 → 0 | 0.4.7 and 6e2050d | 45.5, 45.5, 21.425, 0, 0, 0 | 0, slope 0 |
| **−45.5 → 0** | 6e2050d | −45.5, −45.5, −21.425, **+8.277**, −3.227, **+0.670** | **+0.670, slope 0.585** |
| 0 → −30 | 6e2050d | 0, 0, −15.874, −30, −30, −30 | −30, slope 0 |
| 0 → +30 | 0.4.7 and 6e2050d | 0, 0, 15.874, 35.457, 27.872, 30.442 | 30.442 (unchanged from 0.4.7) |

- **What it costs:** the lip flicks 8° up on its way back, the next piece is still an edge piece, and a lap that should end plain is refused at the seam.
  - checked: my first lap probe did exactly that, "EDGE_SEAM … e 0.670077°, slope 0.58461".
  - Longer: −45.5 → 0 over 200 m with a 60 m transition ends at 0.011, still over close.js's 0.01 tolerance.
- **Reach:** only a NUMERIC transition shorter than the piece rings like this.
  - checked: the same return with a map (`{ e: 40, er: 40 }`, `{ e: 20, er: 20 }`, or `{ kh: 40 }` alone) lands at 0 every time, at 60 and 200 m.
  - checked: the panel's own `extendOptions` (whole piece, or "at the start" ticked) lands at 0, at 60 and 100 m.
  - checked, by grep: no caller in `app/` or `src/` passes a numeric transition (readout.js and sharp.js pass maps).
  - So the builder as it stands doesn't reach it. The core API, its tests and any future caller do.
- **A fix, for C to weigh:** mirror the positive case. When a side's asked values (start and target) are all ≤ 0, bound its ringing above by the largest of them, instead of the cap:
  `hi = Math.max(C[ch][0], target) <= 0 ? Math.max(C[ch][0], target) : cap(i)`
  - Then −45.5 → 0 clamps to ≤ 0, its last control is 0, and "ends flat" fires.
  - A positive side's bytes don't move (row 5's guard).
  - A red-first row: the table's −45.5 → 0 case, ends at 0 with slope 0.
