## 3. What could be wrong

- **Bend's words are "left / right", not the design's "harder / straighter".** Which way is harder depends on the bend already there, and the design's §2 table itself reads "left = harder left, right = harder right". `inferred:` "left / right" is the true reading of a drag on any bend.
- **The words sit in the hover box, not at the arrowheads** (§1.2 says at the heads). One box, the handles' own style.
- **The glyph stays where the drag opened while the road under it moves** (Grab lifts the band). The page's track stands still during a drag (§0 fact i), so a page layer cannot follow the road.
- **The glyph pair's half-width is the piece's END width** (`pieceState(id).w`), not the width at the station. On a piece that widens, the marks sit a little off the edge.
- **Alt is read on pointer moves.** Pressing Alt with a still pointer changes the glyph at the next move.
- **The wheel before a press still zooms the camera.** The design's "the wheel resizes the band under the pointer before the press" is done for `[ ]` only. Today's wheel before a press is the camera's, and taking it is a behaviour change I did not make.
- **Cost:** the drag frame gains one `askOf` for the track and one string per handles frame, and a redraw only when the value text changes. `inferred:` it is within §4's 0.1–0.2 ms, and the band's per-frame filter is gone. E's measurement decides.
- **One "keeper" in a code comment** (selectionlayer.js, the band colour: "the keeper's call: kept"). The commit message has none (`git log -1 --format=%B | grep -ci keeper` → 0). Code comments in t180 already carry it (panel.js 20 at a795359). Reword it if the rule is meant to cover comments.
