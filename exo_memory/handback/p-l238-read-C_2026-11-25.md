## The line: `app/core/coreshell.js:1340` (`moveRecipe` in `renamePiece`), against the hash check at `:1320`

Rename moves the `.t180recipe`, but the moved recipe is then refused, so a renamed piece shows no numbers. Why:
- The recipe names its piece by a hash of the piece file's whole text (`piece: textHash(text)`).
- Rename rewrites that text, because the piece's own `name` field changes (`:1347`,
  `PC.serialize({ ...PC.parse(orig), name: to })`).
- `moveRecipe` copies the recipe across unchanged, with the old hash.
- `showPiece`'s check `r.piece === textHash(text)` (`:1320`) then fails.

**Its second face: a case-only Rename deletes the recipe on Windows.** In the case-only path (`:1350`, "bend" to "Bend"),
`moveRecipe` runs `saveRecipe('Bend')` and then `deleteRecipe('bend')`. On a case-blind disk those name the same file, so
the delete removes the recipe that was just written. The message still says only `renamed the piece "bend" to "Bend"`,
with no note that the numbers were lost.
