## 2. The reader file format — THE PLAN DID NOT FIX ONE, SO THIS IS NEW. It should ride in B's and C's packets.

- **One row per unit:** `U01: YES`, or a table row `| U01 | YES | …`.
  - The unit id must contain a digit.
  - The answer is `YES`, `NO` or `CAN'T TELL`. Case-insensitive, and `'` or `’` both work.
  - Bold, a leading list marker, trailing punctuation, and a reason after whitespace, `|` or a dash are all allowed.
- **Other lines are ignored:** prose, headings, a table header.
- **Refused, never guessed:**
  - a row that starts like an answer row (id then `:` or `|`) but has another answer (`U02: NOT SURE`);
  - an id answered twice;
  - a file with no rows;
  - an id in one file and not the other (both sides are named);
  - a count other than 40.
- **A hazard to put in the packet:** a prose line that begins `<something with a digit>:` is read as a row. For
  example `Q3: …` or `2026-09-27: …`. It is refused loudly, not mis-scored, but it stops the run. Readers should not
  start prose lines that way.

## 3. The formula

With n units, a the units where both readers gave the same answer, and b_k / c_k how often B / C gave answer k:

- p_o = a / n
- p_e = Σ_k (b_k / n)(c_k / n)
- **κ = (p_o − p_e) / (1 − p_e) = (n·a − S) / (n² − S)**, where S = Σ_k b_k·c_k

κ is kept as the **exact integer fraction** `num/den`, and the bars compare in integers, so a κ of exactly 0.60 or 0.40
cannot fall the wrong side through float error:

| verdict | integer test |
|---|---|
| κ ≥ 0.60 | `5·num ≥ 3·den` |
| κ ≥ 0.40 | `5·num ≥ 2·den` |
| CAN'T TELL above 25% | `ct·4 > n` |

**The order of the verdict, as the plan registers it:**
1. Either reader's CAN'T TELL **above** 25% → **NOT ANSWERABLE AS POSED**, whatever κ says.
2. Otherwise, κ undefined → **KAPPA UNDEFINED — no bar applies**.
3. Otherwise ≥ 0.60 **USABLE**; 0.40 up to 0.60 **BORDERLINE**; below 0.40 **FAILS**.

**κ undefined, and my choice for it** (the plan does not cover this case): n² = S, i.e. p_e = 1, happens only when both
readers gave one and the same answer to every unit.
- It is printed as UNDEFINED, not coerced to 0 or 1, and no κ bar is applied.
- The CAN'T TELL bar still is, so "all CAN'T TELL" from both readers reads NOT ANSWERABLE.
- If only one reader is constant, κ is defined (it is 0) and scores FAILS.
- **The librarian may rule otherwise.** I chose to report it rather than to force it into a bar.

## 4. The hand-computed example (it is in the test's comment)

10 units. (B, C) pairs: (YES,YES)×3 · (YES,NO)×1 · (NO,NO)×3 · (NO,CT)×1 · (CT,CT)×1 · (CT,YES)×1.
- B: YES 4, NO 4, CT 2. C: YES 3+1 = 4, NO 1+3 = 4, CT 1+1 = 2.
- a = 3+3+1 = 7, so p_o = 0.70. p_e = (16+16+4)/100 = 0.36.
- **κ = 0.34/0.64 = 0.53125. In integers: (70−36)/(100−36) = 34/64.** → BORDERLINE. CAN'T TELL 20% for each reader.
- Printed by the CLI on those two files (`--n 10`): `kappa … = (10*7 - 36)/(100 - 36) = 34/64 = 0.5313` ·
  `VERDICT BORDERLINE` · exit 0.
