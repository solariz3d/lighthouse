## What it does
- **Save** (`coreshell.save`): `saveDoc(eq-<name>, D.serialize(doc))` exactly as before, THEN `storage.saveUndo(eq-<name>, packHistory(...))`. A sidecar failure is caught: the track is already saved, `dirty` is false, and the status line says `saved <name>, but its undo history could not be kept (<why>)…`. A track-write failure still rejects and writes no sidecar.
- **Sidecar** `eq-<name>.t180undo` beside the track: JSON `{schema:1, kind:'core-undo', present, past:[…], future:[…]}`, every entry `D.serialize` text, the last 200 past steps and the 200 nearest future steps (`UNDO_CAP`). A `WeakMap` keeps each document's text, so a save or autosave only serializes the steps made since the last.
- **Open** (`coreshell.open`): `storage.openUndo` → if the sidecar's `present` equals the opened file text byte for byte, every entry is `D.parse`d and the history is restored (all or nothing). A mismatch → fresh history, silent. Unreadable or damaged (not JSON, wrong kind or schema, a bad entry) → fresh history plus ONE status line (`…undo history … could not be used (…): the track opened without it`); a thrown read → the same line. No sidecar, or a host without the calls → exactly today's open.
- **Autosave/restore**: the autosave record gains an optional `undo` field (same text); `restore()` uses it under the same check. There a mismatch or damage says so (it cannot legitimately differ); an older record with no `undo` restores as before, silently.
- **Native** (`src-tauri/src/lib.rs`): `save_undo(name,text)` and `open_undo(name) -> Option<String>` in the tracks folder, own extension `.t180undo` (so `track_names` never lists it and backups never touch it), `valid_name` checked, `write_atomic`. Page glue in `app/index.html` (`saveUndo`/`openUndo`; a browser gets no-ops).

## What this does NOT establish
- **No real window and no real Tauri round trip.** The JS rows use an in-memory storage; the Rust test covers the file functions on a temp folder; the `invoke` wiring (`save_undo`/`open_undo` from `app/index.html`) has not been run end to end. First real check: save a track, close the app, reopen, Ctrl+Z.
- **Size is the cost of the simple format:** one full document per step, so about 11 MB for a 46-piece track at the cap, rewritten on every Save and carried in the autosave record (at most one write per 1.5 s debounce; 23 ms measured in memory, the IPC write itself is not measured). A delta format would be much smaller but is a bigger change; not built.
- A sidecar's `present` is compared to the file's TEXT, so a file edited by hand with different whitespace has no history (silent). Intended.
- A version opened from "Previous versions…" and a fresh document still have a fresh history, as before.
