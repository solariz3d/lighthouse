## Findings
**A. (REAL, on the keeper's own lap) With the short way chosen, TEST 1 loses pairs it could save.** TEST 1 (46 pieces, closed, bank winding −4π) has a **cup piece (p46) at the end of the lap and a legacy piece (p1) at the start**, so **every wrapped run on it is refused MIXED_RUN: 1,035 of 1,035** (`real.js`). Before this change a shift-click between two pieces took the run INSIDE and, if it was one kind, it saved. Now, for **310 of the 1,035 shift-click pairs** the short way is across the line; **795 pairs were saveable before, 604 are now: 191 pairs that saved before now select the across-the-line run and refuse with MIXED_RUN, and 0 are gained** (`test1.js`). C names the general cost ("a run longer than half the lap can no longer be shift-selected") but not this one: on TEST 1 the cost is a quarter of the saveable runs.
- **A fix that keeps the keeper's choice and loses nothing:** take the short way only when the short run can be saved; when it cannot (`saveProblem` of MIXED_RUN or SEAM_RUN) and the inside run can, select the inside run (and say so in the line: "the long way round: the short way crosses the start line and cannot be saved as one piece"). That restores all 191 and changes nothing on a lap where the short way saves (the three ovals: 15 of 15 wrapped runs kept). C's own idea, a second shift-click flipping the way round, would also work; the fallback needs no extra click.
- **I did not change anything**; it is the keeper's and the librarian's call whether "Short way" means "always" or "when it can be kept".

**B. (REAL, small) The tie rule is not exact in floating point.** C's expression `total − len(from+1, to−1) < len(from, to)` compares sums of decimal lengths; an exact tie can come out as a strict "less". **Deterministic case:** lengths `[327.7, 170.3, 327.7, 257.4]`, select pieces 2 and 4 (indices 1 and 3): inside = 170.3 + 327.7 + 257.4 = 755.4, the other way = 755.4 in exact (tenths of a metre) arithmetic, and the code computes `755.3999999999999 < 755.4` → it **takes the way across the line**, against "a tie stays inside" (`tiefloat.js`; also two random cases in `attack_out.txt`). **On the keeper's real laps it does not happen:** his three ovals have 9 exact ties and all 9 stay inside, through the shell (`G-tie-real`) and by the arithmetic (`ties.js`: 4 closed laps, 1,080 pairs, 9 exact ties, 0 flipped). It needs unequal decimal lengths that happen to tie, so it is rare. **Fix:** compare in integer units of the document's own quantum (lengths are quantised to 1e-4 m) or with an epsilon: `… < len(from, to) − 1e-6`.

**C. (INFO, not C's change, but it decides what a wrapped save of a wound lap is worth) Wound pieces are not "straight" for the export's grid.** `startLayout` in `coreshell.js` accepts a straight when `|roll| ≤ 0.5°`, with no reduction modulo 2π, so a straight carrying −2π of bank is "banked". A whole-roll lap rotated by saving and re-adding runs (or built by hand: both refuse identically) cannot place its grid: "not exported: the track has no straight word to put the grid on". It does not affect any lap of the keeper's today (TEST 1's wrapped runs refuse earlier, MIXED_RUN), and it exists without this change. **A one-line fix would be to reduce `roll` modulo 2π in `nearly`;** I did not test it.

**D. (INFO) `selectionInfo` is called on every state change and now runs `runOf`'s phi mapping for a wrapped run.** On TEST 1 (46 pieces) that is trivial; I did not time it.
