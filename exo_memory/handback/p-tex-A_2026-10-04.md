## What it does (lap items 1 to 4)
1. **The core page gets textures.** `app/core/textures.js` (new): a small road-surface control (a select, "Asphalt (made here)" / "Solid colour" / "My picture", and a PNG/JPG picker) mounted on the core page's `textures` section, last, so the preview is already listening (`app/index.html`). It builds the ONE set (`src/texture/set.js buildTextureSet`) by giving each road piece id a word-shaped record `{ id, word, font: 'flat', textures: { floor: <the look> } }`: the existing builder then does the DDS-with-mips, the `ksPerPixel` material and the budget. It announces the set as `t180:textures`, which the preview already listens for (`setTextureSet`) and which the core Export now passes: `await shell.exportTo(dir, { textures: textureSet })` (`app/index.html`, the core branch; `coreshell.exportTo` already forwarded options to `runSegments`). It follows the track: a new piece is a new segment id the set must know, so the panel rebuilds when the road pieces' ids change.
2. **The default is the asphalt preset** (`src/texmaker/presets.js:7`, canonical text), so a new or old core track exports asphalt with no clicks; the solid colour is one select away ("a solid colour is no set at all": the export is exactly today's). The choice of solid is remembered in `localStorage` (`t180.coreLook`, try/catch); a picture is not (its bytes are not kept between sessions).
3. **A tube maps all the way round** (`src/texture/flow.js`, used by the export and the preview alike): see "The seam" below.
4. **Bring-your-own stays**: a PNG/JPG is decoded on entry (a bad file or a bad name is refused by name and the road is left as it was, the very same set); nothing is bundled or copied from AC or any other author. The only texture in a default export is the maker's own render of our preset (`set.textures[0].made`; a test asserts no `solid` or foreign texture rides in the set).

## Why a new coordinate step was needed (a finding, measured)
`src/geom/mesh.js` gives every piece texture coordinates of its own: `u = arc/10`, `v = (s − the piece's first s)/10`. A core track is hundreds of 2 m chord segments (**748 segments for the 1,491 m tube oval, `segments.length` printed**), so with a texture the pattern would restart **every 2 m**. `flow.js` gives a textured core cell `v = (the row's path arc length + offset)/tileLength`, continuous through every segment and seam, and `u` from the profile's own arc length. **Gated to segments whose `word` is `core` with a textured floor slot**: a word document's coordinates and every untextured export are what mesh.js made. The preview batches get the same coordinates (`app/preview/preview.js batchesFor`; unchanged batches keep the same uvs array, so an edit re-uploads only the new pieces).

## The seam (asked for): where it sits
- **A closed tube's ring seam is at the CEILING**: the section runs `u` from `−w/2` to `+w/2` round the circumference `w` with the floor at `u = 0`; the two ends meet at the top. A ring takes a WHOLE number of repeats round, `n = max(1, round(w/10))`, spread evenly, so the two ends differ by exactly `n` and a tiling texture meets itself there: nothing is stretched beyond the rounding. Measured on the oval: w 31 → n 3 (10.33 m a repeat), w 40 → 4 (10 m), w 37 → 4 (9.25 m); the test asserts the ring spans `n` repeats and the density is even (`n/w` per metre within 1e-4·n at every vertex pair) in every row.
- **A closed ring means ψ = ±180° at both edges at both ends of the chord segment** (`seg.profile` and `seg.blend.from`: every core segment carries a `blend`, its start shape, so a first version that excluded segments with a blend excluded all of them; corrected). An open tube, a cup and a plain road keep `u = arc/10`.
- **The second seam is along, at the start/finish line**: the lap's first seam row joins the last piece to the first, `v = 0` there against `v = L/10` at the lap's end (`L` is not a multiple of the tile), so the texture restarts once per lap at the line. Unavoidable without changing the tile length to the lap; I left it.
- **The slot zone** (a closing or opening tube, where the ring is not yet or no longer closed) is not a ring, so its `u` is `arc/10` against a neighbour's wrapped `u`: a jump in the across phase there, in the zone ruling 3 already makes a red for downforce-ray-gap.
