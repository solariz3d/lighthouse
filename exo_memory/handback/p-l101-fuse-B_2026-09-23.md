## 1 · THE FUSE

**The contract:** a seat must never fail to start because an update did. Every path in the block returns, nothing
calls `exit`, and the update runs under `Invoke-Bounded`. At the bound the **whole process tree** is killed with
`taskkill /T /F`, and launch continues on the installed version. `launch.ps1` still parses with **0 errors** under
PowerShell's own parser.

**THE BOUND — 120 s, argued from a measurement:**
- A Claude Code version is **237,100,192 bytes** (`~/.local/share/claude/versions/2.1.280`). A 16 Mbit/s line downloads
  that in about two minutes.
- When nothing is new, `claude update` is only a version check. So the bound is paid only on a launch that is actually
  downloading, on a slow line.
- A killed download is retried at the next launch, and the installed version is untouched either way.
- `claude --version` measured **58–82 ms** here, so the version queries are bounded at 15 s each.

**What the fuse reads**, per the docs: `claude update` reports *"Successfully updated from <old> to version <new>"* or
*"Claude Code is up to date (<version>)"*. Outcomes are:
- `updated` or `current`;
- `failed`, on a non-zero exit or a start error;
- `timeout`;
- `skipped`, with the reason.

A `failed` or `timeout` also raises the room's own `Notify` dialog for **6 s**, which is what "says so" means in a
script run hidden, and then launch continues.

**WHEN IT DOES NOT RUN**, each written to the receipt as `skipped`:
- **Consonance is already running.** Its seats are live, and any seat restarted mid-session would pick up the new
  binary — the mixed room this exists to prevent. This guard matters because `launch.ps1:470`'s up-to-date path runs
  *before* launch.ps1's own "already running" check.
- **No `claude.exe`** at `~/.local/bin/claude.exe`, the path `main.rs:918` launches.
- **`CONSONANCE_UPDATE_FUSE=off`**, for a metered or offline machine.

**Evidence the problem is live right now**, from today's seat transcripts on L: seven seats on **2.1.280** and one
(`third-place/f495508f`) on **2.1.278**.

## 4 · FOR THE KEEPER — turning the CLI's own auto-update OFF (not applied; his to run)

**The exact key, quoted from the current official docs**
([code.claude.com/docs/en/setup](https://code.claude.com/docs/en/setup), "Disable auto-updates"):

> *"Set `DISABLE_AUTOUPDATER` to `"1"` in the `env` key of your `settings.json` file"* — `{ "env": { "DISABLE_AUTOUPDATER": "1" } }`
>
> *"`DISABLE_AUTOUPDATER` only stops the background check; `claude update` and `claude install` still work. To block all
> update paths, including manual updates, set `DISABLE_UPDATES` instead."*

**So it must be `DISABLE_AUTOUPDATER`, and it must NOT be `DISABLE_UPDATES`,** which would block the fuse's own
`claude update`. Leave `autoUpdatesChannel` as it is: per the same page it picks the channel for *"auto-updates and
`claude update`"*, so `"latest"` keeps the fuse fetching the newest version.

**Run in PowerShell — backup first, then apply, then verify:**

    $f = "$env:USERPROFILE\.claude\settings.json"
    Copy-Item $f "$f.bak-l101-autoupdate"
    node -e "const fs=require('fs'),f=process.argv[1];const s=JSON.parse(fs.readFileSync(f,'utf8'));s.env=Object.assign({},s.env,{DISABLE_AUTOUPDATER:'1'});fs.writeFileSync(f,JSON.stringify(s,null,2)+'\n')" $f
    claude doctor | Select-String 'Auto-updates'
    # the docs: the line must read  disabled (set by env: DISABLE_AUTOUPDATER)

**To reverse it, restoring the exact bytes:**

    Copy-Item "$env:USERPROFILE\.claude\settings.json.bak-l101-autoupdate" "$env:USERPROFILE\.claude\settings.json" -Force

**Proven on a copy of his real settings file, never the file itself:**
- The key is added and `autoUpdatesChannel`, `hooks` and `model` are unchanged. All nine top-level keys are kept;
  there was no `env` block, and one is created.
- **The reversal restores the file byte-for-byte** (sha256 equal).
- **The real `settings.json` was not touched** (sha256 equal before and after).
- One visible effect: `JSON.stringify(…, 2)` re-indents the file with 2 spaces. The backup keeps the original bytes.

**IF HE DOESN'T RUN IT:** the fuse still updates every launch, so each launch starts every seat on one version. But
the CLI's own background check keeps running inside live seats — *"checks for updates on startup and periodically
while running … then take effect the next time you start Claude Code"*. So **any seat restarted mid-session can come
back on a newer version, and the mixed room can still happen.** The fuse makes it rare; the setting makes it stop.
