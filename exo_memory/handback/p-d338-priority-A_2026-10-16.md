## 1. What it does
- **At startup** (`main`, right after the single-instance check, so a refused second launch touches nothing): `priority::start()` sets this process to `HIGH_PRIORITY_CLASS` and calls `SetProcessInformation(ProcessPowerThrottling)` with ControlMask `EXECUTION_SPEED` and StateMask 0.
- **WebView2 children:** a thread (`priority-sweep`) lists the processes under this one with a ToolHelp snapshot every 5 s, reads each one's class and throttling masks, and sets only the ones that differ. So a renderer that appears later is set, and one Chromium lowers (it sets hidden renderers to Idle by itself) is set again.
- **Never fatal:** every failure is one `eprintln!` line per process and reason; `start()` returns either way and Consonance starts.

## 2. The documents (read at source, 2026-10-16), and what each decided
- `SetProcessInformation`, https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation: the handle needs `PROCESS_SET_INFORMATION`; the page's own "HighQoS" example is ControlMask = `PROCESS_POWER_THROTTLING_EXECUTION_SPEED` with StateMask = 0, "turn EXECUTION_SPEED throttling off"; without an explicit setting the system infers a QoS level by its own heuristics, and ControlMask 0 is "let the system manage". So the opt-out is ControlMask set, StateMask 0, which is what the brief says, and it is a statement to the system, not a reset.
- `PROCESS_POWER_THROTTLING_STATE`, https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-process_power_throttling_state: `Version`, `ControlMask`, `StateMask`; version constant `PROCESS_POWER_THROTTLING_CURRENT_VERSION`.
- `SetPriorityClass`, https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setpriorityclass: `HIGH_PRIORITY_CLASS` 0x80, `ABOVE_NORMAL_PRIORITY_CLASS` 0x8000; "use extreme care when using the high-priority class, because a high-priority class application can use nearly all available CPU time".
- WebView2 process model, https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-model: one browser process, renderers and helpers (GPU, audio) as its group, all tied to the browser process's lifetime and one user data folder; the page names no environment option and no job-object setting for their priority (`ProcessFailed` and `CloseTask`/task-manager are its only process hooks). **So the way is "setting each child once it exists"**, and since the set of children changes, the sweep.
- `CreateToolhelp32Snapshot` / `Process32FirstW` / `Process32NextW` (Win32 ToolHelp) are used for the listing: **cited by name, not re-read for this lap**; the code follows their documented contract (`dwSize` set before the first call, handle closed after).
