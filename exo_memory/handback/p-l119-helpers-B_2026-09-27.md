## 1 · THE API (`require('./asof.js')`, or the CLI in brackets)

**`parseTime(t) → epoch ms`** (`node asof.js time <t>` → `{"ms":…,"utc":"…Z"}`).

**THE TIMEZONE RULE:**
- **An ISO 8601 string MUST carry its zone:** `Z` (the transcripts' form) or a numeric offset such as `-06:00` (git's and the notes' form). **A zoneless time is REFUSED**, with the reason. "01:36" could be Regina or UTC, six hours apart, so it is never guessed.
- A number, or a 13-digit string, is epoch milliseconds (the board's `ts`, the ledger's `at`).
- Fractional seconds are kept exactly.
- **The run:** `node asof.js time 2026-01-01T10:00:00-06:00` → `{"ms":1767283200000,"utc":"2026-01-01T16:00:00.000Z"}`, and `… 2026-01-01T10:00:00` → refused, exit 1.

**`fileAsOf(repo, path, T) → { status, commit, commitTime, content, renamedFrom?, renamedTo?, lastSeenIn?, nextChange, t, gitSecond }`** (`node asof.js file <repo> <path> <T>` prints the metadata as JSON, then the content).
- **"The file as of T"** = the file in the repository's state at T: the newest commit on HEAD's **first-parent** line whose **committer date ≤ T**, then `git show <commit>:<path>`.
- **git dates are whole seconds,** so T is floored to its second (`gitSecond`). The boundary second is **inclusive**, which a test pins.
- **Statuses:**
  - `FOUND` (with `renamedFrom` if the path had an older name at T, followed back with `git --follow`);
  - `NOT-YET-EXISTING` (the path appears only after T);
  - `DELETED` (it existed at or before T and is gone by T; `renamedTo` says where, if it was renamed away, and **its new content is never returned as FOUND**);
  - `NOT-TRACKED` (git never held it);
  - `NO-COMMIT` (no commit at or before T).
- **`nextChange` = the first commit AFTER T that touched the path,** with its time. A verifier can then see "the file changed 40 s after the claim" and choose UNVERIFIABLE over WRONG.

**`boardAsOf(T, {dataDir}) / ledgerAsOf(T, {dataDir}) → { file, t, timeField, rows, counts }`** (`node asof.js board|ledger <T> [--data <dir>]`: a counts line, then one row per line). There is also a generic `jsonlAsOf(file, timeField, T)`.
- **The rows are those whose own time field is ≤ T** (`ts` for the board, `at` for the ledger), **sorted by time, never cut by line position.** The real board has 8,779 rows earlier than a row above them (a two-machine union, §3), so position means nothing.
- **Fused lines are split with the tools' own `parseBoardLine`,** required from `consonance/tools/chain-status.js`, not copied.
- **Counted, never guessed:** `lines`, `fusedLinesRecovered`, `unreadableLines`, `rowsWithoutTime`, `rowsAfterT` and `rowsAtOrBeforeT`.
- **`resolveDataDir(explicit?)`:** `--data`, else `CONSONANCE_DATA`, else `~/.consonance.json` `data_dir` (BOM-stripped), the order `actors.js` and `chain-status.js` use. Otherwise it throws with the reason. A missing ledger file is an error, not an empty result.

**What the 19 tests cover:**
- **Time (3):** `Z`, the offset form and epoch ms name the same instant; zoneless is refused; fractional seconds are exact.
- **File as of T (11):**
  - NOT-YET-EXISTING before first commit; NO-COMMIT before any commit;
  - **a commit exactly at T is included**;
  - 1 ms before a change shows the old content and names `nextChange`;
  - an offset-form T equals its UTC form;
  - **a path named after T follows back** (b.txt at 17:30Z → a.txt's `v2`, `renamedFrom: a.txt`);
  - **a path renamed away by T is DELETED** (a.txt at 18:10Z → `renamedTo: b.txt`, content null);
  - a deleted file is DELETED after and FOUND before; a never-held path is NOT-TRACKED;
  - **LIMIT, uncommitted:** a working-tree file never committed reads NOT-TRACKED;
  - **LIMIT, skew:** c5 dated before its parent c4 makes c4's deletion visible at 18:45Z.
- **Board and ledger (5):**
  - board rows are filtered by `ts`, not position, and returned in time order;
  - a fused line is recovered, a torn line is counted unreadable, a row without `ts` is counted;
  - the ledger is filtered by `at`;
  - `CONSONANCE_DATA` is honoured;
  - a missing file throws.

## 4 · LIMITS — where "as of T" cannot be made exact, named rather than approximated

1. **UNCOMMITTED STATE IS INVISIBLE TO GIT.** A file edited but not committed at T, or written at T and committed later, is not what git shows for T. **The helper cannot recover a working tree's past.** It reports `nextChange` so the verifier can see the gap; the verdict for such a claim should be UNVERIFIABLE, not WRONG. That is E's rule to register, not mine.
2. **COMMITTER DATE, ONE MACHINE'S LINE.**
   - "As of T" follows committer dates on this checkout's first-parent history.
   - A commit made on D carries D's clock.
   - A rewritten history keeps or resets dates.
   - **A commit dated earlier than its parent makes the parent's later-dated state visible** (pinned by a test).
   - D's unpushed commits after `5ced140` are not on L at all, so for claims about D's files at D's times, L's git can be wrong or silent.
3. **RENAMES are git's heuristic.** `--follow` tracks one path by similarity. A split, a merge or a heavy rewrite during a move is not followed. The renamed-away lookup scans the whole history for renames, which is slower on a large repo but only on that fallback path.
4. **BOARD / LEDGER time is the WRITER's clock.**
   - Rows from the other machine carry its clock.
   - **I did not examine what `ts_source` distinguishes**; that was keys only.
   - A torn line that doesn't split into whole objects is counted as unreadable, and its rows are unknown.
