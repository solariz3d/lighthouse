| outcome | the window says |
|---|---|
| **PUBLISHED** `{branch, from, to}` | **CLOSED — this machine's state is published** · `<branch>` moved `<from>` → `<to>` on the remote |
| **UNCHANGED** `{at}` | **CLOSED — nothing new to publish** · the remote already holds `<at>` |

| **REFUSED, a divergence** (`REFUSED_DIVERGED`, or B's `DIVERGED — N travelling` line) | also, in plain words: *"This machine lacks rows that the saved state already holds, most likely written on the other machine. Then *"Union those rows into this machine first (`ledger-union.js --write --file <file>`), then close again to publish."* |
| **TIMED_OUT** | **NOT CLOSED — the publish did not finish in time and was stopped** · "Nothing is confirmed published." + text |
| **FAILED** | **NOT CLOSED — the publish could not run** + text |
| any other outcome | **Publish outcome not recognised: `<X>`** · "This window cannot say whether anything was published." Never a success line |
| `null` or absent | **nothing new**: the window renders exactly what it rendered before D134 |
| `phase:"publishing"` | the stick result stays; *"Publishing this machine's state to the remote. The stick step is finished (above); Close Consonance appears when the publish is done — up to 15 minutes."* (A's bound, `LEAVE_PUBLISH_TIMEOUT` = 900 s); no button |

## 2 · FOR A — the file and row count do NOT reach the window today (close.js, not main.rs)

**The packet asks to name the file and the row count "from the outcome". The outcome does not carry them.** Traced by
reading. close.js was not run, since a real close is forbidden:
- **B's gate:** `state-sync.js:587` writes the receipt as `done(refuse(divergenceRefusal(…)), 'REFUSED_DIVERGED', { files })`.
  The per-file list goes under **`files`**, **no `why`** is set, and the readable list goes only to state-sync's own
  stderr (`:489–495`).
- **close.js** captures that stderr (`spawnSync`, `:192`) and relays it only when there is NO receipt (`:196–200`). With a
  receipt it prints `no('the state set was not prepared: REFUSED_DIVERGED', [rec.why || 'state-sync exited 1',
  ...rec.paths, 'Nothing was published.'])` (`:220–224`). **`rec.why` and `rec.paths` are both absent** on this receipt.
- **So A's REFUSED text reads:** `NOT CLOSED — the state set was not prepared: REFUSED_DIVERGED` / `state-sync exited 1`
  / `Nothing was published.` It carries **no file and no count.**

**What the window does about it:**
- It recognises the divergence from `REFUSED_DIVERGED` and says the plain-words meaning.
- It names **each file and count when they are in the text**, parsed from B's own line shape
  `<path>  N row(s) only in the state copy`.
- When they are absent, it says truthfully where they are: *"listed under `files` in `state-sync.push.json` in the data
  folder"* (B §1: the receipt carries `files: [{ path, state_only_lines, … }]`).
- **It never invents a count.** A test pins that.

**The one-line fix, A's to make in close.js `:221–223`:** add
`...(rec.files || []).map((f) => \`${f.path}  ${f.state_only_lines} row(s) only in the state copy (the first at its line ${f.first_state_only_line})\`)`
to the detail list. That is B's own wording, so the window's parser picks up each file and count with no change here.
**Until then the keeper sees the meaning and the pointer, not the file.**
