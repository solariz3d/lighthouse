## 2 · How the two coexist: the PROPOSAL, built

**A mode switch, one page, never both live.**
- The header's select reads **Equation track** (the default) or **Pieces (paused)**.
- Switching **reloads** the page into the other builder, so no shell, panel or event listener is shared.
- `?mode=pieces` / `?mode=core` in the address picks a mode (the window proofs use it), and the last choice is kept in
  localStorage.
- The piece builder's code path is untouched: `startCore()` returns before it runs.

**What each mode mounts:**
- **Equation mode:** the core panel in the left column, plus the piece builder's preview, camera and validation panels,
  unchanged. They read only the shared path; validation's speed slider calls `setDesignSpeed`, which the core shell has.
- **Pieces only:** handles, textures, share, install and the guide, which read the word document.

## 6 · What the window found that the headless tests could not (all fixed; each has a test or a capture)

1. **The core never loaded in the app.**
   - `src/core/document.js` requires `tools/piecewise.cjs`, whose command-line half requires `fs` and `path`, and the
     webview's loader refuses node built-ins.
   - Node's own `require` hid it: every headless test passed.
   - **Fixed** in `index.html`: the core is loaded with the exporter's in-memory node shim.
   - **Test:** the core loads through `app/lib/cjs.js` with the shim and builds the same track as node's; without the shim
     it is refused, naming "fs".
   - **For A/E:** the core needs nothing from `fs` at run time. A split of `piecewise.cjs`'s solver from its CLI would remove
     the need for the shim.
2. **The ghost never showed** (probe: 0 batches). The pointer was already on the Extend button, so no `mouseenter` fired.
   The ghost now follows the extend fields too; capture 2 shows 90 ghost batches.
