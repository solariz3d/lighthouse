## 1 · THE SWITCH-OVER

**The flag: `CONSONANCE_JEV_MODULE`, exact value `on`.** It follows the `CONSONANCE_UNION_AT_LAUNCH` precedent (`state-sync.js`);
`'ON'`, `'1'`, `'true'` and `' on'` are all off.

**It is read in ONE place:** `consonance/tools/jev-shadow-runner.js` `run()`, from `cfg.env`, the app's own environment. It
can't travel to `judgePass` any other way: the runner hands it a **key-only env** (`jev-shadow-runner.js:187`, *"in memory
only"*), and that should stay so.

**ON, `run()` calls `jev-judge.js` `loadJevModule()` once** and hands the result to both passes as `jevModule`. Two things
change and nothing else:
- **the prompt**: `jev/lib/prompt.js` `narrowedView` + `buildPrompt`, with the rubric through `readDiscipline(config.rubricPath)`;
- **the question**: `jev/lib/ask.js` `ask()`, at `config.gateway`.

**What stays the room's:** the seats (`seatSessions`: main.rs plus the live roster), the store and its ledger
(`%LOCALAPPDATA%\consonance\jev-shadow`, as today), the row shape, the daily cap, and the skip-a-503 / end-on-a-401 /
one-refused-row-for-a-secret rules.
- Every capture and row made this way carries **`via: 'jev-module'`**, so the two paths can always be told apart.
- Rows made this way also carry `reason`, from B's `ask()`, and have `cost: null` and `generationId: null`, since `ask()`
  returns neither.

**`loadJevModule` refuses, loudly, and the runner turns judge mode OFF** (`judge mode off: CONSONANCE_JEV_MODULE=on, but …
— the shadow keeps running`). It refuses when:
- the room can't be found, or the room has no `jev/lib/{prompt,ask,config}.js`;
- the room config is **absent** (`jev/lib/config.js` reads an absent file as "all defaults", which is right for a stranger,
  but the room must say what it wants);
- the config is invalid (C's own message is carried);
- the audience isn't `consonance`;
- the room is opted out (`.jev-off`).

**Judging on the old path when the new one was asked for would be a silent substitution, so it doesn't.** Mutant S5 pins
this.

**The module, the seat ids and the config come from ONE tree:** the room `roomOf` finds, as in L099. The builder's
`sources_sha256` is taken **from the same read that is `require`d**. That is the L114 lesson: the old runner hashed a fresh
read of files it had cached.

**Flag OFF is byte-for-byte today's behaviour:**
- `jev-judge.test.js` 37/0, `jev-shadow-runner.test.js` 42 existing tests, `jev-shadow.test.js` 32/0, and none of those
  tests edited.

  and the export line gaining three names), plus one in the runner (the `judgePass` call gaining `jevModule`).
- **The module branch in each pass sits BEFORE today's code and `continue`s**, so no line of today's path was edited.

**One correction I made to myself:** I first widened `transientStatus(err)` to take the module's error class.
