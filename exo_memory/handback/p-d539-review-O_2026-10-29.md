**2a. Bank the bend, E's core (`src/core/bankswing.js`):** nothing.

**2b. Bank the bend, A's tool (`app/core/coreshell.js`):** one fix, not blocking.
- **Fix:** `app/core/coreshell.js:1237-1238` read `d.pieces[i].length` for the last piece and for the selection's last piece. A flight has no `length` field (`src/core/document.js:354`), so either can be NaN:
  - **A run whose last piece is a jump:** `peakS` is NaN.
  - **An open track whose head is a flight:** `s1 = Math.min(NaN, …)` is NaN. This happens even for a bend nowhere near the end.
- swingBank then refuses with BAD_RANGE, and the message shows "NaN m". Nothing changes on the track, but the user gets a message that makes no sense.
- The fix: use `pieceOffsets`' own lengths, `off[i + 1] − off[i]`, plus the segment sum for the last piece, as `bankswing.js:98` already does.
