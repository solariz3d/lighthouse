## A deviation from the brief, and why

**node 24's TAP carries no file path.** Its top level is each file's top-level tests, flattened, with names and durations only
(checked on a two-file scratch run before the real one). Per-file wall time cannot be read from it. So a third reporter,
`file-events-reporter.mjs`, ran beside spec and TAP. It records each test event's `data.file` and the time it arrived. Each file's
own test (nesting 0, named by its globbed path) carries that file's subprocess wall time in `duration_ms`, and its `test:dequeue`
gives its start. No test or app code was changed.

## What the numbers say for part 2

1. **The critical path is one file.** `core-mutation.test.js` started at +24 s and ended at +2,015 s; the suite ended at 2,422 s.
   So no concurrency setting can bring the wall under about 2,015 s (33.6 min) while that file takes 1,991 s. Raising
   concurrency to 6 or 8 can at most shorten the other 400 s, and with 11.4 cores already busy it risks oversubscribing.
2. **The 20-minute target lives in the three big mutation harnesses** (core-mutation 1,991 s, mutation 1,837 s, core-close-mutation
   1,183 s). Each copies whole directories per mutant (`cpSync` of app/ subfolders, `src/`, `tools/`) and runs its mutants one
   after another with `spawnSync`. The packet's second move (copy less, or share one copy with a per-mutant overlay) fits. So does
   running a harness's mutants in parallel inside the file, or splitting one harness into several files the runner can schedule.
   Which of those is smallest is the ruling's; I have not timed a mutant's copy against its inner run, and that split would decide it.
3. **The slowest non-mutation files** are `sound-bands.test.js` (434.8 s, a browser render) and `preview-async.test.js` (179.2 s).
   I have not read them for waste.
4. **No browser test passes `--mute-audio`.** checked: `grep -rlE "msedge|chrome|--headless|mute-audio" test app/test` → 7 files
   (six tests and the `soundrender.js` helper); `--mute-audio` occurs in none. Chrome starts with `--headless=new` at
   `app/test/soundrender.js:65` and `app/test/texture-page.test.js:40`. Part 1 forbade code changes, so this is noted, not fixed.
