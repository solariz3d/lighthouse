## The expansion: `${NAME}` in path values, from the `env` PASSED IN

**`load` stays pure.** `expandVars` reads only the `env` argument, and a test sets a variable in `process.env` alone to
prove `load` refuses it as unset.

**The rules, decided and tested:**

| written | result | why |
|---|---|---|
| `${NAME}` | the variable's value | NAME is `[A-Za-z_][A-Za-z0-9_]*`. **On win32 it matches case-insensitively,** as Windows env names do (a plain-object copy of the env loses that, so it is done here). **On posix it is case-sensitive.** |
| **undefined** `${NAME}` | **REFUSED** | the message names the variable, the key and the config file |
| `${NAME}` set to `""` | **REFUSED** | `"${X}/jev"` would silently become `"/jev"`, a folder at the filesystem root |
| **bare `$NAME`** (no braces) | **REFUSED** | a literal `$HOME` folder is the silent failure to avoid; the message names the fix: `${NAME}`, or `$$` |
| `$$` | a literal `$` | so `$${NAME}` is the literal text `${NAME}`, never expanded |
| `${` unclosed, `${}`, `${1X}`, `${A-B}` | **REFUSED**, each for its own reason | "unclosed" / "not a variable name" |

**What expands:** only **path values**, meaning `ledgerDir`, `rubric` and each `optOut` entry. `gateway.model` and
`sessions` are taken as written (tested).

**Order:** expansion first. A leading `~` still means the home passed in, and a non-`~` result must still be absolute.

**A refusal never echoes a variable's value** (tested with a value that expands to a relative path).

**A stranger's defaults are unchanged:** no config means no expansion, and the same per-OS `ledgerDir` (tested). A's
parallel E2E runs on defaults.
