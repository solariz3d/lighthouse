two different things; the plan put them next to each other and the numbers do not connect.

## 5 · THE BASELINE UPDATE — a test change, so the proof comes first

The keeper's rule, verbatim: *"never weaken, remove, or modify existing tests to make them pass unless the test
itself is verifiably wrong."* This lap modifies one test. The proof it is warranted, each point measured above:

1. **The assertion was about the corpus, not the code.** `/FORGOTTEN\s+0 files/` against the live repo — true on
   08-25 when written, false from 09-08 onward. The tool it ran is **correct**: §1's bracket shows it steps
   exactly at the two deleting commits and nowhere else.
2. **Both departures are deliberate**, by named commits that state why (§3). The tool reported them correctly;
   the test reported them as a failure because nobody had acknowledged them.
3. **The test's own failure message prescribed exactly this step**: *"a departure appeared in the real corpus —
   update loop/forgetting_pilot_2026-08-25.md"*. It was designed to be re-baselined when a departure is
   acknowledged. The acknowledgement was deferred at D083 and never made.
4. **The old form had no signal left.** Scored against HEAD's test file, the mutation harness **refuses to run at
   all**: `pre-flight (unmutated copy): red 11/1`. For thirteen days a genuine third departure would have been
   invisible — the test was already red, so it could not turn red.

**What changed**, in `consonance/tools/forget-rate.test.js`:

- `FORGOTTEN 0 files` → an **`ACKNOWLEDGED_DEPARTURES`** list of two entries, each **`[path, deleting commit,
  bytes, reason from the commit message]`**. The packet's rule — *"a baseline update, with the commit named in
  it"* — is met per entry, not once for the lot.
- The test now asserts the DELETED set **equals** that list exactly, **and** the FORGOTTEN count and byte total
  equal the list's, **and** the untouched `RENAMED_SIMILAR 1` assertion, byte for byte as it was.
- **Renamed**, because its old name — *"has never lost a file"* — is now a false sentence: *"has lost from the
  reading path ONLY the acknowledged departures (all-time)."* A test whose title is untrue is its own carrier
  problem.
- **The byte check compares digits, not a formatted string.** `forget-rate.js` prints bytes with
  `toLocaleString()`, so on a locale that writes `172.048` a string match would go red for the locale, not the
  corpus. Found while writing it; the old test never read bytes, so it never had the problem.

**Not weaker — stricter, and measured.** The old pin fired on *any* departure but was permanently red; this fires
on a new departure, on an acknowledged one coming back, and on the byte total moving — from a green baseline.

**Not done, deliberately:** `loop/forgetting_pilot_2026-08-25.md` is not edited. The test no longer points at it
— the acknowledgement now lives beside the assertion, with its evidence — and the pilot is a dated record that
was true on its date. Whether it gets an addendum is a record decision, not a test repair.
