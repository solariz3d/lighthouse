## 2 · The keeper's reading (`trip-check.js` `cleanWeek`, was `:184`)

`clean: bad.length === 0 && days.size >= 7`, "a clean trip on each of seven days", is replaced.

**`clean` is now three-valued:**
- **`false`:** at least one bad trip in the last seven days.
- **`true`:** at least one trip, and none of them bad.
- **`null`, THE EDGE: zero trips in the window is UNMEASURED.** It is neither clean nor failed. The argument:
  - "No bad trip" is true of an empty set, so it would be said whether or not anything worked, and it carries no
    information.
  - Zero rows is also exactly what a broken recorder produces, which is the failure this lap exists to end.
  - An idle week is not evidence of a solid one. It isn't a failure either: nothing went wrong in it.
  - `reason` says which case applies, and the CLI prints `UNMEASURED`.

**Also reported, deliberately not folded into the verdict: `launches_on_record_since`,** the earliest launch this
machine still holds.
- Launches before this lap were overwritten, so for the next seven days a clean week covers fewer launches than it
  names.
- The keeper's rule is about bad trips, so I computed that rule and put the coverage beside it. I did not make the
  verdict stricter than the keeper chose.
- The CLI prints it every run.

**The existing test's first half, "seven clean days is a clean week", still holds under the new reading, and I left it
unchanged.**
