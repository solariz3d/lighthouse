## What changed (`app/core/keys.js`)
- **Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z act on the TRACK with the focus anywhere except a text-entry field.** A number field, a checkbox or a
  select included. The field's own text-undo is stopped (`preventDefault`), so the browser does not also undo the typing.
- **A text-entry field keeps them for its own text**:
  - which ones: `textarea`, an `input` with no type or of type text, search, email, url, tel or password, and `contentEditable`;
  - on this page that means the track name (`#name`) and the share code box.
  - **A decision of mine, to flag:** taken literally, "from anywhere" would undo the TRACK while you type a name, which no editor does.
    Photoshop's own text boxes keep Ctrl+Z for their text. If the keeper wants it literal, it is the one `TEXT_ENTRY` selector.
- **Ctrl+S and Ctrl+Backspace are unchanged:** in ANY field (`input, select, textarea`) they stay the field's.
  - **How Ctrl+Backspace still deletes a word:** `bindKeys` neither acts on it nor calls `preventDefault` inside a field, so the browser's
    own word-delete runs. Checked in the real window, below.
- `keyAction({ …, inField, inText })` gains an optional `inText`. **A caller that passes none keeps the OLD rule** (any field keeps every
  key), so `app/shell.js`'s re-export and `shell-keys.test.js` are unchanged.

## Undo refills the fields: does it need a guard? My answer: a small one, recommended, but NOT built here
- **What happens (real window):** typed `123` into a number field without Extending, then Ctrl+Z. The track stepped back one piece (2 → 1),
  and the field was refilled with the restored head's value (`100`), so the half-typed `123` is gone. That is D242 item 7 doing its job.
- **Why a guard is worth having:** inside a number field, Ctrl+Z ALSO plausibly means "undo what I just typed", and Photoshop's numeric
  boxes do exactly that. Today the first Ctrl+Z after typing both throws the typing away AND steps the track.
- **The guard I would add** (not built, because it needs the panel's own state and A owns `panel.js` right now): if the focused field holds
  text the panel did not put there (un-applied), the first Ctrl+Z only puts the field back to what the panel showed and does NOT step the
  track. The next Ctrl+Z steps the track.
- **Cost without it:** one un-applied typed number. Nothing in the document is lost; one Ctrl+Y gets the step back.
