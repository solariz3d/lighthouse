## 2 · WHAT IT DOES, and where each number comes from

**The load per lateral line** (ARCHITECTURE.md:68-69). A profile point sits at o(u) = X·L + Y·U, using C's
`src/geom/profile.js` `offsetAt` / `normalAt` rather than re-deriving them. In a rotation-minimising frame that line's
tangent is T·(1 − κ⃗·o), so
`f = v²·κ⃗/(1 − κ⃗·o) + a_T·T + g·ŷ`, projected on n(u) (into the surface), across, and along T.
- **Checked by the tests:**
  - 1.00 g at rest on the flat, FINDINGS.md:31-32's calibration;
  - v²/(R·g) across in a flat turn, with the inside and outside edges at their own radii;
  - v²/R − g at the top of a loop;
  - a/g along T when accelerating.
- **1 − κ⃗·o ≤ 0 is the fold** (ARCHITECTURE.md:57): red, with no load taken there.
- `inferred:` the roll-rate term is left out.

**The limits** (`limits.js`; the test "MACH6 defaults" pins every value):

| limit | value | source | use |
|---|---|---|---|
| suspension stop | 20 g | FINDINGS.md:103-104 | **info only** |
| proven | 90 g | FINDINGS.md:105, :112-113 | fN above it is **AMBER** (never red) |
| the withdrawn 60 g red | — | FINDINGS.md:116-118 | **absent**, and a test holds that 70 g is neither red nor amber |
| jump falls | 3.2 g and 6.3 g | FINDINGS.md:336-337 | both landings (ARCHITECTURE.md:73-78) |
| reach bound | dist·tan10° + ½·6.5 g·(dist/375 km/h)² | FINDINGS.md:312-313, as tools/read_track.cjs:149-151 | `reachable` |
| seam | 5.9° | FINDINGS.md:24 (p90 upper) | **AMBER** past it |
| stacked | 2 m | ARCHITECTURE.md:85 | red |
| steep | 50° | ARCHITECTURE.md:87 (community-reported) | red only with `csp: false` |
| lap speed cap | 745 km/h | FINDINGS.md:37 | lap sim cap only; `inferred:` that it is near the top speed |
| car acceleration | none | **not in FINDINGS** | no default is invented; with no design speeds and no `car.accel`, the lap says `no-speed-model` |

**The red list** (ARCHITECTURE.md:81-87). Each item carries `{ s0, s1, u, reason, source }`, and a test requires every
source to name a `.md:<line>`.

| reason | fires on |
|---|---|
| `gap-in-road` | a gap that is not a jump word, or a hole between road stations. The open head is exempt (INTERFACES §4) |
| `missing-soft-collision` | `opts.softCollision === false` |
| `fold` | computed from the path, plus C's `folds[]` if passed |
| `self-intersection` | only from C's `folds[]` with `other`. Otherwise it is listed in `notChecked` |
| `stacked-within-2m` | two passes of the road within 2 m (a spatial hash; the same pass within 25 m of s is excluded, `inferred`) |
| `wall-ride-from-wall-object` | a wall-ride whose surface material is WALL |
| `steep-without-raycast` | a surface above 50° on an export with `csp: false` |

**Amber and info:**
- **amber:** `load-above-proven`, `seam-past-envelope`;
- **info:** `on-the-stops`.

**Jumps** (ARCHITECTURE.md:72-80). The projectile model FINDINGS settled on (§8 :246-247, widened by §7d) gives
`minSpeed` per landing, with the harder landing binding the reported `minSpeed`. Each landing reports `clear` (reaches
the landing lip) and `caught` (touches down on the landing road given), plus `reachable`. A jump whose landing is not
yet built (the open head) is `pending`.
- **Why not `tools/jump_flight.cjs`:** it solves the inverse problem (it fits g_eff from a replay, and it reads the
  replay at require time). The builder needs the forward one. Its outputs, 3.2–6.3 g, are the inputs here.

**The lap** (ARCHITECTURE.md:88-89):
- open: `{ ok: null, reason: 'open' }`;
- closed, with design speeds or `car.accel`: a point-mass lap (full throttle, gravity along T, the cap), 3 laps so the
  carried speed is real;
- `where[]` names `leaves-surface` (fN < 0 at u = 0), `stall`, `jump-not-caught-<g>g` and `landing-unreachable`, with
  `timeS` and `minV`.

**Smoke on C's real `buildPath`** (not a test, one `node -e`): a half-pipe straight, turn (R 60) and straight at 150 m/s
gives 391 samples, 1,955 lines, no red and no amber, and a max fN of 28.28 g on the outer wall (u = −13).

### What open and incremental mean here

**`validate` on an OPEN path:**
- `lap: { ok: null, reason: 'open' }`;
- no `gap-in-road` red for the head segment;
- a jump whose landing is not built yet is `pending`.

**`revalidate` carries everything before `fromS` − look-back and recomputes the rest. The look-back per check** (stated
in the code, as INTERFACES §4 asks):

| check | look-back |
|---|---|
| loads / amber / info | 1 station (the along-track term reads the neighbours' speeds) |
| seams and holes | 1 station |
| folds | 0 |
| segment reds | the look-back station's segment, i.e. the word before the change (the old head loses its gap exemption) |
| stacked | every new point queried against **every** point, marking **both** stations |
| jumps | recomputed whole (they are few; each costs at most its landing search) |
| a closed path | full validate (C spreads the closing twist, so every frame moves) |
| a change of speed model | full validate |

- **The result is the same object shape as INTERFACES §3.** The raw findings ride along non-enumerable (`_raw`), so a
  result still compares and serialises as the interface shape.

### A real bug the tests found, fixed

**An EDIT of the head piece left a stale stack.** An old station stacked only on the removed piece kept its red,
because a carried stack did not record what it overlapped.
- The edit test was **red at the first version**.
- **The fix:** each station's stack entry records its deepest partner. It is carried only if that partner also lies
  before the cut. Otherwise the station is re-queried against every point, so a shallower OLD stack survives (the
  "re-derived, not dropped" test).
- **Two more changes, each forced by a surviving mutant, and neither changes a tested output:**
  - stacked keeps each station's **deepest** overlap (order-independent), not the first hit;
  - `ranges()` sorts by a total order (reason, s, u).

**An equivalent mutant, resolved by simplifying the code:** re-checking "the segment before `from`'s" was redundant,
because the one-station look-back already lands in the previous word. The `− 1` is removed and the comment states why.
