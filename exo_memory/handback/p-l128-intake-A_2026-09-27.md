## 2. The proposed fix — the smallest, at the call site (NOT applied)

**The change** (`main.rs:5483`): when the newest entry cannot fit even under the cap, the map is going to be IndexOnly
whatever is reserved. So reserve only the floor, which the IndexOnly section fits: it is **2,497 chars** in C's shell
today, against a floor of 8,000.

```rust
// was: let reserve = map_reserve(own_map.as_deref());
let reserve = match own_map.as_deref() {
    // An entry that cannot fit under the cap renders IndexOnly regardless (map_section); reserving the cap for it
    // funds nothing and starves the optional briefs (L128: C woke with no committee brief).
    Some(m) if m.len() - last_heading(m) + MAP_SECTION_OVERHEAD > SHELL_MAP_RESERVE_MAX => SHELL_MAP_FLOOR,
    other => map_reserve(other),
};
```

- **Why at the call site and not in `map_reserve`:** the existing test
  `a_master_whose_newest_entry_is_past_the_cap_is_refused_out_loud` (`main.rs:5356`) asserts
  `map_reserve(huge) == SHELL_MAP_RESERVE_MAX`. Changing `map_reserve` would change what that test pins, and that is
  a ruling, not mine to make.
  - That test's own comment says the cap exists so "the deck [is not] gutted for one enormous entry". Today the capped
    reserve guts it anyway, for an entry that then renders as an index.
  - **This fix keeps that test and its IndexOnly refusal as they are.**
- **What it does for C (inferred):**
  - Before, C's optional seat was at least its 14-item index (~5.6k) and below the committee (15,823) plus the index
    of the rest, so under ~20.8k.
  - Freeing 28,000 (36,000 → 8,000) puts it at ~33.6k or more, which carries the committee brief and some cards.
  - The map section is unchanged: IndexOnly, saying its numbers.
  - **Not verified by a rebuild.**
- **The blast radius:**
  - **Panes:** only those whose newest entry is over 34,800. **Today that is C alone.** A, B, E and the librarian's M
    are far under it (table above), so their reserve, shell and map tier are byte-identical.
  - **The fixed seats:**
    - The **librarian** goes through the same path. Its M map's newest entry is 5,203, so it is unaffected.
    - The **chair**'s shell is `BUILDING.md` and carries item 7. The chair was not measured through this path here.
  - **The Third Place:** its intake states "COMMITTEE.md (no committee here)" (`main.rs:6802`, `:6907`). No committee
    and no pane map, so it is untouched.
  - **Fresh instances:** `own_map` is `None` (`:5480`), so `map_reserve(None) = 0`, unchanged.
- **The test that would pin it** (red before the fix):
  `a_pane_whose_newest_entry_cannot_fit_still_carries_the_committee_brief`. Build `map_of_shape(120_000, 60_000)` (the
