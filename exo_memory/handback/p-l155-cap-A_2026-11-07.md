## 1. The cap (what was built)
`consonance/tools/heavy-run.js`, two new exports and one line in `hold()`:
- `cpuMask(raw, cpus)`: the N lowest logical CPUs as a BigInt mask. `null` (no cap) for unset, empty, any non-digit string (`'12x'`, `'1e1'`, `'0xC'`), 0, negative, fractional, N >= the machine's CPU count, or a machine of more than 64 CPUs (one processor group only).
- `applyCap({env, pid, platform, cpus, run, log})`: unset or whitespace = returns at once, asks the OS nothing, prints nothing. Set: on Windows runs `Get-Process -Id <pid>`, sets `.ProcessorAffinity = [IntPtr][Int64]<mask>`, then **reads it back** and compares. A read-back that differs, a failed query, an unusable value or a non-Windows platform is **said once on stderr and the run goes on uncapped** (never throws, never exits). Only an integer pid and an integer mask reach PowerShell.
- `hold()` calls `applyCap` **after** it has the lock and not for a re-entrant (nested) run, so a waiter is never throttled while it waits and a nested run is not capped twice.
- **How children inherit it:** the holder pins ITSELF. A Windows process is created with its parent's affinity, so every process the runner starts afterwards (test workers, headless Chrome, cargo, and theirs) carries the mask. `inferred:` that this is the OS rule for CreateProcess; `checked:` below on a child and a grandchild.
- The mask is the LOWEST N logical CPUs, i.e. N/2 physical cores on a 2-way SMT part (Windows numbers a core's two threads adjacent). `inferred:` this concentrates heat on a few cores' share of the die; a spread mask (every k-th CPU) is a possible later change and is not built.
- Not built (not asked): the per-machine `~/.consonance.json` profile (`heavy: { cpus, ... }`) the plan's 12:16Z amendment describes. Only the env var exists. Reading the profile into `CONSONANCE_HEAVY_CPUS` is a small next piece.
