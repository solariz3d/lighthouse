## 1 · THE GATE — it refuses the app's own launch, and position cannot fix that

### 1.1 · Measured, with the positive control

    tasklist /FI "IMAGENAME eq consonance.exe" /NH
      -> consonance.exe   23900 Console  2  48,180 K          <- the app this pane runs inside
    node -e "require('./dev/place-conversations.js').consonanceRunning()"
      -> true                                                 <- the gate function itself, called read-only
    tasklist /FI "IMAGENAME eq not-a-running-image.exe" /NH
      -> INFO: No tasks are running which match ...           <- positive control: the filter can say no

The gate is `place-conversations.js::consonanceRunning` (`:166`), called by `tail-carry.js::run` only
when `mode === 'import' && apply`. It asks one question: **does an image named `consonance.exe` exist?**

### 1.2 · Why "before the lock and before any pty" does not satisfy it

§3 says the gate is satisfied by construction if Arrive runs before the single-instance lock and before
any pty spawns. **Those orderings are about a mutex and ptys; the gate is about an image name, and the
image exists from process creation — before `main()`, before `claim_single_instance()` (`main.rs:10384`),
before `.setup()`.** No position inside `consonance.exe` can be earlier than `consonance.exe`.
So an in-app `node dev/tail-carry.js --import --apply` refuses with *"Consonance is running"* on every
launch, forever. That refusal is correct and stays. The gate's stated fear is an open writer appending
under a live seat, and the image name is a sound proxy for that on every path except this one.

**What the gate does NOT block, which is most of the module.** The rehearsal (import without `--apply`)
and the export are ungated. Shown against the real stick, from inside the running app:

    snap before  ->  node dev/tail-carry.js --stick D:\consonance-L-20260911 --import  ->  snap after
      7 seats, every one NOTHING_PENDING · 0 bytes · 0 refused · exit 0
      stick (32 files: path, size, mtime) + ~/.claude/consonance-carried.json: IDENTICAL before/after

Every write in `tail-carry.js` sits inside `writeLedger`, `applyExport`, `writeCarried` or `applyImport`,
and those are called only after `if (!apply) return` (`run`). Checked by grep before running anything
against the stick.

**Right now the stick holds nothing for this machine:** every `ledger.json` seat has `pending: null`.

## 3 · THE DESIGN QUESTION THIS HANDS THE KEEPER — three shapes, one recommendation

**A · The arrival is its own process that opens first.** A small step runs the rehearsal, the rule in §4
and the import, then starts `consonance.exe`. This satisfies the gate truthfully, because the app does not exist
yet — it is what `ARRIVING.ps1` already does, and it is the keeper's literal wording: *"a module to
consonance that **opens first**"*. The open choices are where it lives (`launch.ps1`, a `src/bin` launcher, the
stick script) and whether the desktop shortcut points at it.

**B · In the app, detect and withhold.** `sync_at_launch` finds the stick and runs the rehearsal, which is
allowed. If any seat is still pending for this machine, it withholds seats through the existing
`SEATS_WITHHELD` refusal-not-lockout, naming the step to take. It never imports. On its own it loses "lands every
time without a step"; as a net under A it guards falsifier 1: no seat wakes on the older
conversation because the arrival step was skipped.

**C · Teach the gate what it fears instead of an image name.** For example, "is any process holding
these seats' transcripts open", which would admit the app's pre-spawn moment. That is A's file, and it is
the shape most at risk of becoming the bypass §7 forbids. A gate that tests a subtler thing is a gate
with more ways to be wrong in the permissive direction.

**Recommendation: A, with B beneath it. Not C.** A keeps every refusal exactly as strict as it is tonight.
B makes skipping A loud instead of silent. Both reuse `tail-carry.js` whole.

**Leave is buildable in the app — the export is ungated — and I did not build it, for two reasons the
design has to settle first:**
1. **Two exporters, one ledger.** `ARRIVING.ps1` starts `ON-EXIT.ps1`, which waits for the app to close
   and then exports. An in-app Leave on exit would be a second writer of the same `ledger.json` at the
   same moment. The design must say which one survives. Under A, the in-app Leave replaces ON-EXIT.
2. **The contract is not landed.** `tail-carry.js` has no `--json` yet, and A has +69 uncommitted lines
   in it right now (`git diff --stat -- dev/tail-carry.js`). Building a parser against a contract still
   being written is the "wrong contract" §2 warns about.

## 4 · RULING 1 — WHEN A RETIREMENT MAY BE AUTOMATIC

**ARRIVING's rule stands in structure and is TIGHTENED twice for fixed seats. Nothing is loosened.**

    pane, REFUSED "DIFFERENT conversation"   -> retire automatically — but NOT silently (4.3)
    fixed, REFUSED "DIFFERENT conversation"  -> retire automatically ONLY IF all three hold:
         (a) the birth is read from THE FILE THE CARRY REFUSED OVER, never a search      [tightened]
         (b) born after the stick's export (pending.at)                                   [kept]
         (c) born in a launch minute on THIS machine's own clock                          [tightened]
    fixed, birth unreadable or no pending.at -> STOP                                      [kept]
    any seat, any OTHER refusal              -> STOP  (diverged, won't settle, can't key)  [kept]
    STOP names the seat, the reason, the file; --retire-far for a fixed seat is the keeper's to type

### 4.1 · (a) The birth must come from `row.dest`, and ARRIVING's search can retire a lineage — measured

`ARRIVING.ps1:63-72` (`FarFirstTimestamp`) runs `Get-ChildItem -Recurse -Filter "$sid.jsonl"` across **every**
slug and takes the most recently written file. The carry refuses over one exact file:
`dest = place.paneJsonl(projectsRoot, seat.cwd, seat.sid)` (`tail-carry.js:497`). **These are not the same
file when a seat's id exists under two slugs, and on this machine it does:**

    0c0c0c0a…a01 (main)  C--Consonance-instances-main/…jsonl                262,159,624 B  2026-09-14 01:31
                         C--Users-zackn-claude-instances-main/…jsonl          1,005,720 B  2026-07-27 00:56

Today the most recent write happens to be the right file. **The unsafe path is one this room has already
lived through:** a seat spawned in the wrong cwd writes a new conversation under the same id in a
different slug. That is the homeless-transcripts case (P1, B and E on 2026-09-10 01:54; D055: all four seat
cwds `C:\Users\nname`). That stray file is newer and born later. ARRIVING would read *its* birth
("after the export") while the carry refused over the **lineage** file, and **retire the lineage automatically.**
That is the fixed-seat loosening the chair forbade, reachable through ARRIVING's own search. So the birth
is read from `row.dest` and nowhere else.

### 4.2 · (c) Two clocks, and the unsafe direction

`pending.at` is the **exporter's** clock (`tail-carry.js:471`, `new Date(now)` on the far machine). The
birth is **this** machine's clock. Nobody has measured the skew between L and D. If the exporter's clock
is **behind**, a lineage conversation born shortly before the export reads as born after it, and gets
retired automatically. The window is narrow — only a conversation born within |skew| before the export — but it is
the unsafe direction, and a constant margin would be a number nobody measured.

**So the second condition is one clock:** the seat's first timestamp must fall in a minute this machine
recorded as a launch in its own `persist.log` (every launch writes `<unix> SYNC AT LAUNCH …`). This is the room's
own test, *"a first timestamp at a launch minute"*, applied on a single clock. Both (b) and (c) must hold.
Either one alone still admits a case the other catches.

### 4.3 · Panes — they proceed, never silently, and why they do not stop

**Chosen:** a pane refused only for "DIFFERENT conversation" is retired automatically, as ARRIVING does.
Before the import runs, it is **named with its address**: path, bytes, last written, printed on screen and
written to `persist.log`. ARRIVING gives that line to fixed seats only; a pane gets just its session id,
which is less than a retirement owes.

**Why not stop:** a retirement here is a recoverable move, not a deletion. A pane's roster row and its
capture travel with the stick. And a different conversation under a pane's id on the arriving machine is
overwhelmingly a fresh wake under the old id — 236 of 236 pane resumes were `-> fresh` before D059. Stopping
on those would make arrival fail on the commonest harmless case. **The real risk I cannot rule out:** a
pane used on this machine in breach of "one machine open between carries" holds real work, and this rule retires it.
The address line is what makes that recoverable instead of lost. **How many such collisions exist is
unmeasured.** A pane refused for any other reason stops, as ARRIVING does.

**The address has to come from the tool, not be guessed.** §2 moves the carry's retirements into
`consonance-attic/<slug>/`. ARRIVING's message still says *"the stamped file beside it"*, which will be wrong the moment
A lands. Whatever runs arrival must print the address A's result reports.

## 6 · OWED TO A — the contract cannot carry Ruling 1 as written

Applying §4 from outside the tool needs three things per row that §2's contract does not list:

    kind         "fixed" | "pane"     — seats() builds it (tail-carry.js:302, :311); the row drops it
    dest         the exact file compared — (4.1) the rule is unsafe without it
    pending.at   the export time      — (4.2) condition (b); already in the ledger, not in the row

Without them, the app has to re-derive the roster and the slug rule. That is a second copy of
`encode_cwd`, which `tail-carry.js:95` exists to avoid. **Proposed: add all three to every import row
in `--json`.** Also the `why` text: ARRIVING matches `'DIFFERENT conversation'` in prose, and §2 says the app never
parses prose. That refusal needs its own machine-readable reason, for example `"reason": "different_conversation"`,
or two tools will drift on a reworded sentence (the L052 lesson: matching git's prose on stderr).
