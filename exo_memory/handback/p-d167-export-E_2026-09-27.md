## 2 · What the export does, and every refusal

Every refusal is an `ExportError` with `err.code`, raised **before anything is written**:

| code | when |
|---|---|
| `EMPTY_DOC` | no words, or no road |
| `OPEN_TRACK` | the loop is not closed. An AC lap needs one, and A's AI encoder refuses an open line (`NOT_CLOSED`). `closeLoop` closes a document. **Decision, open to the chair:** an open point-to-point export is not offered. |
| `NOT_CLOSED` | `buildPath` refuses the closure |
| `RED` | any validation red, **plus a failed lap proof**. `lap.ok === false` becomes a red `lap-proof`, with every failing point named (e.g. `lap-proof [jump-not-caught-6.3g at s 198.0 m]`). ARCHITECTURE.md:88-89 says "Full-lap proof **before export**". `err.red` carries the ranges and their sources. |
| `NO_START_STRAIGHT` | no straight is long enough, or wide enough, for the grid, the pits and the hotlap start. The message gives both lengths. |
| `BAD_SCENE` | T1's `validateScene` refuses the scene |
| `MARKERS` | a §5c check is red, or a marker name repeats |
| `NOT_OURS` | the target folder exists without `.t180b-builder.json`. It is left untouched. |

**Written with warnings:**
- every amber range, with its FINDINGS source;
- a lap that could not run (`no-speed-model`);
- validation's `notChecked` list;
- `selfCheck: false` (said, never silent);
- repeated mesh-node names (§4.1);
- the noblock red.

**The noblock variant.** A missing soft-collision block is red in §4. The folder without it is the §10.1 soft-road
control, so:
- it is written only on request (`variant: 'noblock'` or `'both'`; the default is `'block'`);
- the red is carried as a named warning;
- validation runs with the block present, so every other red refuses both folders.

**This is my reading of how the chair's "both variants" meets §4's red; the chair can overrule it.**

**The markers, generated.** They go on the longest run of `straight` segments with no yaw, pitch or roll. From the far
end back:
- the start line: `AC_TIME_0_L/R`, a gate across the floor at ±(floor half-width − 0.5 m);
- the grid: 4 slots, `AC_START_0` is pole, two columns at ±min(3 m, floor half − 1.5 m), 8 m apart;
- the pits: 2 boxes, single file, 8 m apart;
- `AC_HOTLAP_START_0`, 12 m behind the last pit;
- all of them 1.5 m along the surface normal.

v1 builds no pit lane, so the boxes sit on the start straight. **Every distance is a default I chose (inferred, not
measured)**, and each can be overridden (`grid`, `pits`, `height`, …).

**The AI line** is A's generator in `'floor'` mode. `'wall'` mode reads the platform test's own constants (WF 5, LW 8),
which an arbitrary profile does not have. Its speed is the slowest design speed when every word has one; otherwise it is
A's 300 km/h.

### 4.1 · For C: `selfCheck` on a real document's mesh refuses every multi-part track

- **What happens.** `buildMesh(…, { selfCheck: true })` on the sample (1036 m, words resolved into in/body/out parts)
  gives 26 intersection groups. Some break bvh.js's own rules:

## 7 · D166 addendum 2: sculpt handle bounds (done, carried here by the chair's word)

- **`handleBounds(doc, id, opts) -> { id, word, scope, redNow, handles: { h: { value, unit, min, max, below, above, amberMin, amberMax } } }`.**
  - Each bound is found by running the same `validate` on the document with that one handle changed, through A's
    `editWord` → `resolve` → C's `buildPath`.
  - The bound is exact to the handle's quantum: 1 mm, 0.001°, 0.0001.
  - `below` / `above` name what stops it: `red` (with its reasons and FINDINGS/ARCHITECTURE sources), `range`,
    `refused` (A refuses the value), or `red-now`.
- **The signature differs from INTERFACES §4b's `(path, segments, index)`.** Segments carry no handles, so a handle
  cannot be rebuilt from them. `(doc, id)` matches A's own hook, `library.js handleInfo(doc, id, boundsFn)`, which a
  test drives.
- **Scope:** `'track'` (any new red counts) when the track is otherwise clean, else `'word'` (only its own stretch).
- **Tested**, one quantum each side of the bound: clean inside, red outside, the red naming its source. The handles and
  the reds that stop them:

  | handle | stopped by |
  |---|---|
  | length | fold |
  | turn | stacked |
  | easeIn | fold or seam |
  | climb | fold |
  | roll1 at the head, `csp:false` | steep, exactly 50° |
  | width, wall | stacked |
  | ψL, `csp:false` | steep |

  Also tested: range and refused stops, `red-now`, amber inside the red bound (with the amber reason checked), and
  scope.
- **A's `ROLL_STEP` refuses roll0 and roll1 on a middle word,** so only the head's roll1 is sculptable today.
- **The steep rule in `src/validate/index.js` changed to measure the real surface normal,** per station and per u,
  so bank now counts, not only ψ. 56 of 56 validate mutants are caught after the change.
