## The five conditions

- **(i) The control runs whole as now, and narrowed once per distinct caughtBy.** A pattern goes into the harness's `NARROW` map only if
  its narrowed control has 0 failing rows, ran at least one row, and reported the named test. A pattern that fails any of these keeps
  its mutants whole, and the control says so with a `D412 whole:` diagnostic. In all three harnesses, in every run, **no pattern was
  kept whole**.
- **(ii) Narrowed first; a catch stands; a miss is re-run whole, and that verdict stands.** `IR.narrowedFirst`. Proved by the rows
  "a narrowed miss is re-run whole, and the whole run's verdict stands, caught or not" and "a narrowed run that throws (NOT TESTED) is
  no verdict; the whole run decides, and its throw still throws". **In both full runs all 207 mutants of the three harnesses ran
  narrowed and were caught: the fallback never fired.**

      checked: grep -c "^# D412 path: narrowed" full1.tap / full2.tap → 207 / 207 ; "whole" → 0 / 0

- **(iii) caughtBy is regex-escaped; wide patterns are flagged.** `IR.narrowArgs` escapes every regex character (proved on real child
  runs: `(1)`, `[2]`, `a.b`). No pattern names a describe block (`suites` 0 everywhere). These patterns match more than one row; each
  still narrows, because a catch reads the same `includes(caughtBy)` either way:

  (checked: the `# D412 wide:` diagnostics in `core-mutation-solo.tap`, `mutation-solo.tap`, `core-close-solo.tap`)
