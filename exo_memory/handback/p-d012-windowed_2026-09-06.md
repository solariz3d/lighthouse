## 4. What the windowed form cannot see — asked for by name, and measured

**(i) TIME. The window is ten LAPS and never a duration, and nothing in this ledger measures elapsed
time.** Measured on the live ledger: gaps between consecutive laps run from **0.4 h to 139.8 h — a
350× spread**. Ten-lap windows over the actual record have spanned **198–225 h (8.3–9.4 days)**, but
three consecutive laps have spanned as little as **1.2 h** (D008→D010, the ring-lap burst of
2026-09-04). So the same instrument has covered hours and covered weeks, and its sensitivity silently
tracks the lap rate. A room that suddenly runs laps quickly gets a much shorter memory without
anyone deciding that.

**(ii) A PARTIAL LAPSE.** One opened row anywhere in the window reads exactly like ten. It measures
whether the practice **died**, never whether it is being **kept**. A reader who does not know that
will over-read a green — so it is printed, and asserted.

**(iii) EXCLUDED and VOID laps occupy a window slot**, unlike every other total in the report, which
says of them *"these are not counted anywhere below"*. That inconsistency predates this lap (the
all-time form used the same set) and is **left alone rather than changed blind**: no lap on this
ledger is currently excluded, so no live number could tell the two choices apart, and a change with
no observable consequence is exactly the kind this room keeps finding under rocks later. Named here
and in the output; someone else's call, with data, when there is data.

**(iv)** It is silent until the ledger holds ten laps — unchanged, and already printed as
*Window not full*.

## 5. A smaller finding: the prose already said "window"; the code read all-time

The registered sentence has read *"if 10 laps pass and no row has an opened field"* since the tool
shipped. The code read the whole ledger. **The sentence is ambiguous** — "10 laps pass" can be read
as *the first ten* — so this is not quite a bug report and is not filed as one. But the windowed
reading is at least as faithful to the words, and it is the only one that can fire twice. Worth
having on record that the divergence was between a sentence and its own implementation, not only
between two defensible policies.

## 6. The refusal, weighed rather than skipped

The packet offered *"the ruling is wrong and the all-time form was right"* as a real answer. It is
not right, but the fairest version of it is worth stating, because it changes what the all-time form
*was*:

**The all-time form is the correct implementation of a different falsifier — a one-time ship gate.**
*"Was the third stage ever used at all?"* is a real question, it was answered (no, for ten laps, out
loud, under the table, unread), and once answered it is **finished**, not broken. The defect was
never that the arithmetic was wrong; it was that a **finished** check was left standing where a
**standing** check was needed, and nothing in the output said which kind it was.

That is why the all-time count stays on the line as context rather than being deleted, and it is the
one thing I would push back on in the ruling's wording: *"the registered form could never have fired
again"* is true, and *"the all-time form was the defect"* would not be. The window is the fix
because the **question** changed when the gate shipped.

## 9. What this does NOT establish

- **It does not make the practice kept.** It makes a lapse *visible ten laps later*. Nothing here
  causes anyone to write an opened row; the opened-row gate does that, and only on mapped laps.
- **It does not measure the ring laps**, which are the gap the gate cannot reach and are most of this
  week's laps. If ring laps keep skipping `--map`, this falsifier will keep going red for a reason
  no gate in this file can fix — and that red will be correct.
- **It says nothing about whether the opened rows are true.** Still self-report, still limit (c).
- **Ten is not a defended number.** `WINDOW` was already 10 for BUILDING.md's falsifier and this
  reuses it. Nobody has shown that ten is the right memory for *this* question; it is the right
  number for *consistency with the constant already there*, which is a weaker claim and is the honest
  one.
