## 3 · CONTRACT FINDINGS — each measured, none renegotiated

1. **THE GATEWAY GIVES NO `reason`. The contract's `reason` is `null` in practice.**
   - Measured on the room's own store, keys only, no text: `%LOCALAPPDATA%\consonance\jev-shadow\jev_judge.jsonl` has **527 rows, and all 403 verdict answers have exactly `choice, confidence, probabilities, type`.**
   - ask.js passes a `reason` through when one arrives and never invents one (mutant M22).
   - **This bites E and the design:** the flags line *"your last turn: <one-line reason>"* has no reason to print. The prompt asks the model for `{"verdict", "reason"}`, but the `/v1/evaluate` route returns only the declared question's answer.
   - **Owed:** either a second question that carries a reason (if the gateway can return free text), or a flags line without one. That is the librarian's and the keeper's call.
   - The gateway also returns `confidence`, which the contract drops.
2. **A's `narrowedView` returns `{ user_context, assistant_move }` or null, not the contract's string.**
   - A declares this in `prompt.js`'s header, and it is right: buildPrompt places the two fields separately.
   - jev-judge passes the view straight to `buildPrompt` and accepts either shape when checking for a move to judge.
   - **The contract text should be amended to the object.**
3. **C's default `rubricPath` is `jev/lib/METHOD.md`** (`config.js:43`, `path.join(__dirname, 'METHOD.md')` from `jev/lib`). **That file does not exist.** The rubric ships at `jev/METHOD.md`, which is A's `DEFAULT_RUBRIC` (`prompt.js:21`, `'..'`).
   - With the default config, every turn today would log `refused … cannot read the rubric` and never judge.
   - My tests pass only because their config sets `rubric` explicitly. **I did not touch either file.**
   - The fix is one line in C's `config.js`, or A's constant reused.
4. **The transcript can lag the Stop hook.** The current hooks page ([code.claude.com/docs/en/hooks](https://code.claude.com/docs/en/hooks), read 2026-09-23 through a summariser, not verbatim) says of the Stop payload's `last_assistant_message`: *"Use this instead of reading the transcript file, which is written asynchronously and may lag."*
   - The same page lists `prompt_id` in the payload and says Stop hooks *"cannot use `async: true`"* and are blocking. That confirms the detached child is the only way not to hold the session.
   - **My handling:** the child polls the transcript for the end_turn row, 10 × 500 ms. A turn whose end never appears is logged `no-turn-end`, never guessed (mutant M33).
   - **What it leaves open:** A's `narrowedView` reads the transcript too, so on a lagging write it could build the prompt from the *previous* turn while the uuid is this one. I have not reproduced that.
   - **The cleaner design, for the librarian to route:** key the turn by the payload's `prompt_id`, and take the move from `last_assistant_message`. That changes A's contract, so I did not do it.

It never carries a gateway body, the prompt or the key. ## 4 · WHAT THIS DOES NOT DO — stated limits

- **No cross-process pacing.** Each turn is its own process, and ask.js's pacer spaces calls within one process only. Two sessions ending at once are not spaced, and a 429 fails that one turn (logged `gateway-failed HTTP 429`, and **not retried**: the next turn is a new process with no memory of it). This is a new property compared with the room's runner, which paced a whole pass.
- **The secret patterns are enumerated, not closed** (stated in ask.js's header, as in the room's).
- **No log rotation.** `jev.log` grows by one line per failed turn; with no key set, that is every turn.
- **A mutant counted "caught" means the suite exited non-zero**, not that the intended test was the one that failed. I did not inspect each mutant's failing test.
