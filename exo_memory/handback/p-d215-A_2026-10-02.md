## A FINDING THAT CHANGED THE BUILD: the installer would not have applied the new matcher
Changing the manifest's matcher alone does nothing on D. `install.ps1` decided a hook was "already correct" if it found it in ANY group, regardless of matcher, so the gate (already in the second reader's group on the two-verb matcher since D212) would have stayed there and never seen `chair_inject`; the run would have printed "already correct" and left an empty new group to prune. I verified that in the sandbox before the install. **Fix, in `install.ps1`:** a matcher-scoped hook found under ANOTHER matcher (or no matcher) is MOVED: dropped from the old group, added to the group of its own matcher, printed as `REMATCH … was matcher / now matcher`; a group it empties is pruned by the D205 prune. It applies only to entries that HAVE a `Matcher` (an unmatched entry is never moved), and `Test-SameHook` is unchanged, so no hook the script does not manage is touched. **This is a change to the installer's merge, not only a matcher edit; B should read it.**

The gate runs BEFORE the tool, so **the tool did not run** and nothing reached any pane or the board. What came back to me, in the same turn, as the tool call's error, verbatim: `PreToolUse:mcp__consonance__chair_inject hook error: SOURCES gate: the dispatch has no SOURCES: line. List what you opened or ran this turn that the message relies on. This dispatch was NOT delivered. Its pointer is logged (C:\Consonance\data\sources-gate.jsonl, ring 2168f10f4328), so nothing is lost: fix the line and re-send the same dispatch in this turn. Format: SOURCES: <path> · <path> · \`<command>\` (one line, above the NEXT: line; or SOURCES: none (no state claims) …)`. **So for the chair:** a denied dispatch is a failed tool call whose error text is the reason; the turn does not end; the chair adds a `SOURCES:` line (or `none`) above its NEXT trailer, makes sure the sources were opened or run in an EARLIER message of this turn (not the same message as the dispatch), and calls `chair_inject` again. The same applies to an unmatched item: the reason names it. **Fails open:** any error of the gate's own (no transcript, unparseable, exception, an 8 s watchdog) allows the dispatch, and the gate only denies after its ledger row is on disk (no data dir or an unwritable ledger → allowed), so a gate bug cannot trap a dispatch. **Two things that will cost the chair a re-send:** a source read before a KEEPER message or a pane ring in the same stretch is stale (a background-task notification is NOT a boundary since D214), and a `Write` does not count as opening (read the file back first).
**Live evidence:** `tail -1 C:\Consonance\data\sources-gate.jsonl` → `tool: mcp__consonance__chair_inject, decision: deny, kind: missing, target: B, nCalls 40`, the pointer line, no unmatched items; `grep -c probe-not-a-real-token C:\Consonance\data\sources-gate.jsonl` → **0** (the WHOLE live ledger); `grep -c 2168f10f4328 C:\Consonance\data\second-reader.jsonl` → **0**, so the second reader did not fire on the dispatch.
