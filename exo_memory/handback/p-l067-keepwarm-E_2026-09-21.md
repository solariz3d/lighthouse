## 0 · Headline

**Built, and it runs only while the app is open.** One thread starts in `setup` beside the inbox drain and ticks
every 60 s. On each tick, every live pane is pinged only if all of the following hold:
- its **own Stop stamp** reads ready;
- its composer reads **exactly Empty**;
- **≥ 50 min** have passed since its **last request STARTED** (read from its transcript);
- it has not been pinged in the last 50 min;
- its seat is not switched off.

The ping goes through `gate_or_queue`. It writes one board row, and the seat's off switch is a file.

## 1 · Where I departed from the spec, and why

**(a) `gate_or_queue` alone would break "never over the keeper's typing".** When `gate_or_queue` cannot deliver
now, it **queues** the message (`main.rs` `Inbox::push`). The drain then **force-delivers** a queued message after
`MAX_HOLD_MS` = 240 000 ms, even over a composer that never read empty: the `Forced::SignalOutranked` arm of
`drain_decision`. That is right for a packet that must arrive. It is wrong for a ping whose only job is to be harmless.
- **What I built:** keep-warm makes its **own stricter decision first**. It requires the Stop stamp itself (never
  the Stale/Unstamped/Contradicted screen fallback) and the composer exactly `Empty` (never `HasText`, never
  `Unreadable`).
- **Then it still calls `gate_or_queue`.** The inbox rule stands, and the source test that derives every
  `inject_to_pane` caller and requires `gate_or_queue(` in its body passes with `keep_warm_send` among them.
- **If the gate queues it anyway** (the seat's state moved between the two reads), keep-warm immediately withdraws
  **its own** message through a new `Inbox::withdraw_tail_if(pane, "keep-warm")`, and the drain writes its usual
  WITHDRAWN row.
- **Why `withdraw_all` was the wrong tool:** it would have cancelled every other seat's queued packet for that pane.
- **Why the withdrawal cannot be overtaken:** forcing needs 240 s of waiting, and the withdrawal happens in the same
  call.

**(b) The idle-delivery switch is not honoured by keep-warm, on purpose.** With
`CONSONANCE_DELIVER_ONLY_WHEN_IDLE=off`, `drain_decision` returns `Deliver` for everything, which would put a ping
into a running turn. Keep-warm's own decision never reads that switch.

**(c) Human-driven panes are skipped. This is the keeper's call to reverse.** He said *"every pane that is active
and seats as well"*. `deliver_pull` holds a standing rule, *"NOT delivered — pane … is HUMAN-DRIVEN (never inject
into a person)"*, and a human-driven pane is the keeper's own conversation. Keep-warm pings `main`, `librarian`,
`third_place` and `committee`, and skips `human`. The flip is one `matches!` line in `keep_warm_decision`, and the test
that pins it says so. **I did not decide this against him silently; this line is where he decides it.**

**And one cost the spec does not bound, stated so nobody meets it on a bill.** The spec has a floor (≥ 50 min) and
no ceiling. So on the **first tick after a launch** (60 s in), every resumed seat is idle for hours, and **every seat
is pinged**, which is a full cache write for each. At tonight's measured 603k–924k per seat, that is about **6.37M
tokens at every launch, for every seat, whether or not the keeper uses it that session.** Before this, an unused seat
cost nothing. This matches his *"restart is the only full re-read"*, but only if he accepts that it happens to
**all** seats. The alternative is to ping only seats still warm (`since_start < 60 min`), which keeps warm seats warm
and never warms a cold one. That is one comparison in the same function. **Flagged, not chosen for him.**

## 2 · THE FINDING: every ready stamp on L is 22 hours old, and I found why

    ls --time-style C:\Consonance\data\ready\*.json          last writes 09-20 06:20 … 07:53 local, then NOTHING
    (per seat, node over each transcript: last request 11:22–11:37 UTC today; stamps all "stop" 2026-09-20)

**The cause:** eight of the keeper's hooks resolve their library directory as
`process.env.CONSONANCE_DATA || ~/.claude/shell` (`grep -rln "CONSONANCE_DATA ||" ~/.claude/shell/hooks/`: l2-overseer,
l3-overseer, ready-prompt, ready-stop, session-end, session-start, stop, userprompt-submit). **This pane's environment
carries `CONSONANCE_DATA=C:\Consonance\data`** (`echo`), so `ready-prompt.js` requires
`C:\Consonance\data\lib\ready.js`. That file does not exist (`ls` → no such file), and the hook's `catch` swallows the
error, so **no stamp is written, silently**. Run by hand for this pane: exit 0, prints `{}`, stamp unchanged.

**Where `CONSONANCE_DATA` comes from: not established.** The app never sets it process-wide (`grep set_var(` → none).
The pane spawn does not set it (`main.rs:1150-1151` set only `CONSONANCE_PANE` / `CONSONANCE_READY_DIR`). It is in
neither the User nor the Machine environment (PowerShell `GetEnvironmentVariable` → empty). PTY children inherit the
app's environment, so **whatever launched the running app had it set**. I did not identify that launcher.

**What it means for keep-warm tonight:** every seat's stamp says `stop`, so `pane_gate` reads **Ready** for every
seat, and "not busy" rests on the gate's **screen** check (a live turn on screen turns Ready into `Contradicted`,
which keep-warm skips). A turn keeps its spinner redrawing at least once a second, so a running turn should read
Contradicted. But **the stamp half of the busy check is dead on L until the variable collision is fixed**, and so is
the stamp half of the whole delivery gate. **This is the keeper's hooks, and I did not touch them.** It is also the
same variable-name class as my own D090 guard in `ready.js`, but not caused by it: stamps kept being written for seven
hours after that install (00:30 → 07:53).

**What "last request started" means, established from a transcript rather than assumed** (this seat's own `.jsonl`,
last 40 lines). Every API request writes one or more `assistant` lines sharing a `requestId`, stamped when the
**response** lands. The line just before the first of them (the prompt, a `tool_result`, or an `attachment`) is
stamped when the request was **sent**. So the start is that line's timestamp:
- **an earliest bound**, which means a seat is pinged early and never late;
- **sidechain lines are excluded**, because a subagent's requests warm a different prefix.

**Neither ready stamp gives it.** `stop` is when the turn ENDED, late by the whole last response. `prompt` is the
turn's FIRST request, and `stop` overwrites it anyway. The test fixture has a 9-minute response. Measured from that
response, the seat reads 41 min idle at 10:50 and waits, and its cache dies at 11:00.

## 5 · The addendum: the ping's exact text, and whether the trailer gate applies

**The trailer gate does NOT apply on the app-side path.** `trailer_gate` is called from exactly three places, all MCP
verbs: `mcp.rs:573` (`chair_inject`), `:660` (`call_chair`) and `:905` (`call_librarian`). `gate_or_queue` has **0**
references to it, and `main.rs` has no `trailer::` call at all.

**The text, as chosen:** `[keep-warm, from the chair — not the keeper] Reply with exactly: ok`. It is one line with
**no `NEXT:`**. The trial needed a NEXT line only because it went through `chair_inject`. From the app, a trailer would
be refused by nothing, but the receiving seat would **read** it: in this room a `NEXT:` line is a routing instruction
seats act on. I act on every one I am handed. So it would invite exactly the "more than ok" the ping must not produce.
A test pins it: no newline, no `NEXT:`, ends `Reply with exactly: ok`, says `not the keeper`.

**Not verified:** that seats actually answer only `ok`. That is the trial's to show (the arms in panes A and B).
