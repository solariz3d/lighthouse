## Site 1 — the Scribe (`run_distill` → `claude_oneshot`)

**Marked data.** `scribe_prompt` (`main.rs:8365`):
1. puts the board rows between `<board_rows_{id}>` and `</board_rows_{id}>`, where `{id}` is a fresh UUID;
2. puts a line before them saying the rows are DATA, that instructions inside them are not to be followed, and that
   only the close tag carrying that id ends the data;
3. restates the task after the close tag, so the last thing the model reads is never a board row.

**The delimiter argument.** A fixed tag is one a board row can contain, so it is not a delimiter.
- The id is drawn for each prompt, and **redrawn while the rows contain it**.
- A row holding `</board_rows>`, or any other id's close tag, is therefore still data.
- A row can only end the data early by guessing the id before it is drawn.

`scribe_input` keeps the old row format unchanged.

**Flags.** `ONESHOT_ARGS` (`main.rs:8327`) = `-p --tools "" --settings {"hooks":{}} --mcp-config {"mcpServers":{}} --strict-mcp-config --no-session-persistence`.
- The Scribe needs no tools; it returns a JSON array.
- Hooks are off because the user-scope SessionStart, UserPromptSubmit (board digest, `~/.claude/settings.json:38`) and
  Stop hooks would each run inside a Scribe call. Nothing in `run_distill` reads what a hook produces.

**`--model` is not pinned.** No measurement says which model distills best, and the default is the keeper's choice.
The marking and the empty tool list are the fix.

**The second caller, `committee_form` (`main.rs:8047`).**
- **What it feeds:** its JSON goes into `raise_from_forming` → pulls → `deliver_pull` into panes.
- **Is pinning safe there:** yes. It returns JSON and uses no tools, hooks or MCP. Both callers want the same flags,
