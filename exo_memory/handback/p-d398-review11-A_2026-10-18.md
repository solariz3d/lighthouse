## Part B: the review of the diff

### Findings (scored)

| # | finding | verdict | evidence | caught by a seat? |
|---|---|---|---|---|
| 1 | **The dither's compact Bayer matrix loses levels once the canvas is taller than about 2,364 px.** `pass_bayer2` is `fract(dot(a, vec2(0.5, a.y * 0.75)))`, which is `fract(0.5 x + 0.75 y²)`. For a pixel row y near 2,400 that term is about 4.3 million, where a 32-bit float spaces numbers 0.25-0.5 apart, so the fraction is no longer exact and some of the 16 levels collapse. The same file's own sin-hash rule was written for exactly this class (a big argument, GPUs reduce it differently). The pass runs at the canvas backing size (`preview.js:327`, CSS size times device pixel ratio), so a maximised window on a 5K-class or larger screen would show a coarser pattern. Effect is bounded: the offset stays within one step, it just breaks fewer steps (the banding partly returns). The test draws 1400x860 only | **real (small, edge)** | emulation, `Math.fround` at each operation (a float32 emulation, not a GPU): distinct levels in a 4x4 tile of the real function: 16 (float64); rows near y = 860, 1440, 2160, 2364: 16 in float32; near 2400 and 2880: **8**; near 4320: **4** (probe in the shell this turn; output lines `rows near y=2400 distinct levels fp32: 8 float64: 16`). Also `precision mediump float` is declared in that shader; on a GPU that really uses 16-bit there the pattern would be gone at a few dozen rows, but a desktop WebView2 through ANGLE normally gives full 32-bit (inferred, not checked) | **no.** E's rows run in headless Chrome's GL at 1400x860 (§1, §4 of E's hand-back says the limit is that GL) |

### Notes, not findings

The comment and the CHANGELOG say "half a step either way" / "less than one level"; the second is true. Negligible; a Bayer matrix with the usual (k + 0.5)/16 centring would be exactly centred.
