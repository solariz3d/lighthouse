### The key, and why (your choice, item 1)
`indexFor(path)` now keeps the tree per **path object AND `path.head`** (a version), guarded by the sample count too. `path.head` is what `finish()` in `src/geom/path.js` builds as a FRESH object at the end of `buildPath`, `extendPath` and `rebuildPathFrom`, which are the only things that change a path's samples. I did **not** use "the last sample's identity", which B suggested and which I first expected to work, because I read `path.js` before choosing: after a sculpt, `rebuildPathFrom` keeps the unchanged tail's `SampleView` objects and only re-places them (`blk.pl = Q`, line 314), so the END of the track can move while its last sample is the same object. **Measured through the real shell** (`sp2/ident_dbg.js`): a kh brush on the first piece of a 4-piece open track: `how` sculpt, same path object, **last sample the same object, sample count unchanged, the end of the track moved 83.2 m**, head replaced; a kh brush at s0 400: last sample the same object, end moved 65.2 m, head replaced. So B's suggested key, with or without the count, would still have been stale after a sculpt (mutant S2 below fails 2 tests). A path with no head (a hand-made one) falls back to its last sample. A version counter in the track model was the other option; it would have had to be threaded through `preview.js` and `guidePlan`'s callers, and the head already exists, is replaced by the geometry itself, and works for any caller of `guidePlan`. The dependency is now pinned by a test (row 23): every in-place extend and sculpt replaces the head.
