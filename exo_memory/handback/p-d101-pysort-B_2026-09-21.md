## 1 · THE DEFECT AND THE FIX

`install.ps1:691-692` (HEAD) chose `…\Programs\Python\Python3*\python.exe` by `Sort-Object FullName -Descending`. That is
a **string** sort, and `"Python39" > "Python314"`.

**The fix mirrors pane A's rule in `userprompt_pulse.test.js:68-70` (`1c8760d`):** the dir name must match
`^Python3(\d*)$` (case-insensitive), and candidates sort **descending on the numeric minor**, with no digits counting as
**0**, like A's `|| 0`. A found the defect and did not copy it, and the installer and the test side now agree.

**One behaviour change that comes with "the same way", stated rather than slipped in.** A's pattern excludes suffixed
dirs, so a 32-bit **`Python312-32` is no longer a candidate**, where the old glob accepted it. On a machine whose **only**
Python is a `-32` build, the fallback now finds nothing and prints the "none found" placeholder instead of a working
32-bit interpreter. No machine I can see has one: D has `Python313` and `Python314`, from a read-only probe of the same
glob. **Whether a 32-bit build should count is A's rule and the keeper's call.** If it should, the pattern loosens to
`^Python3(\d*)(?:-\d+)?$` in both places together, never in one.
