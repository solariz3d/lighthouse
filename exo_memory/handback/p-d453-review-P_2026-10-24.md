## 1. Question 1: M2 and M3 against the code

**What the count does.** `fullSteps` (trackmodel.js :131–141): a closed update with no slot for its detail (an open track clears the slots) and `was.closed` false takes the grow branch when `keptFrom(was, nk, lk) > 0`, else `buildMesh`. The branch passes `reuseMesh` its own per-segment flags, `j < was.keys.length && nk[j] === was.keys[j] && lk[j] === was.liftKeys[j]`, computed independently of the count. So a mutant of the count can only move an update between the two branches.

**What reuseMesh does with a flag** (mesh.js :403–426): a piece is kept only when `same[j]` holds, its font source is kept too when it has none of its own (`dependsOnPrev` → `same[before]`), and its start pitch and bank equal the previous piece's to 1e-12 (`prior.p0`, `prior.b0` against the new path's first sample); every other piece is `meshPiece`d again, every seam beside a remade piece is `meshSeam`ed, and the loop's own joint always is. Its documented contract (:392–397) is equality with `buildMesh` to round-off, held by preview-speed on three tracks, and the row's vertex check holds it on this lap.

- **M2** (the lift key dropped from the count): the count can exceed the number of flagged segments only where a key is equal and the lift key is not; such a segment's flag is false (the flag still compares `lk`), so it is remade. Either branch yields `buildMesh`'s mesh. The reverse, count 0 with a flag true, cannot happen (a true flag needs both equal). Equivalent in output.
