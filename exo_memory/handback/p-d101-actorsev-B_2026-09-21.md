## 1 · WHY IT RAN ON D — the diagnosis

**The runner does not decide the skip. The file does.** The `js-suite.js:63-92` contract says a MACHINE-BOUND file must
*"where its universe is absent, print `JS-SUITE: NOT-RUN`"*, and that the gate must be *"a CONTENT question — is this
the universe these assertions are about"*. `home=` and `root=` are for the runner's probes, not the decision.

**What D's environment gives it:**

    pane env CONSONANCE_DATA=''           ->  dataDir() falls to ~/.consonance.json data_dir = C:\Consonance\data
    ~/.consonance.json machine_tag = D

The data root comes from the same config key on both machines. **C's seam work (`7b101b1`) and A's stick-apply scrub
(`3d89dfb`) changed how `CONSONANCE_DATA` reaches some processes, but this pane carries none, so neither is what put the
file in play.** It ran in D082 on 09-19, before both.

**The gate's content question stopped discriminating machines.** It asked two things:
- does the board carry every id in `actors.js`'s `PRE_LETTER` table?
- does `persist.log` have at least one letter assignment?

On D both answers are yes:

    JS-SUITE: UNIVERSE C:\Consonance\data — 7/7 pre-letter ids on the board · 13 letter assignments in persist.log

**D's board carries all seven pre-letter ids** (first rows 2026-07-06 to 07-14, read from `board.jsonl`), because boards
travel between machines. **D's `persist.log` is D's own history:**

    grep -m1 -E "^[0-9]{9,12} letter [A-Z] -> pane=" C:/Consonance/data/persist.log
      1784993504 letter A -> pane=1582ff09-1500-4c10-8af7-f75c524d9613      (2026-07-25T15:31:44Z)
    actors.js:248   const LETTER_BIRTH = 1785057198;   // L's: letter A -> pane=6fe15f0a…, 2026-07-26T09:13:18Z

So the file ran over a shared board and a local letter history, and exactly one assertion failed: *"LETTER_BIRTH
re-derives from persist.log"*, actual `1784993504`, expected `1785057198`. **The other six pass on D.** They are about
the board, and the board really is shared.

This is the same finding as D082 §2.2(b): *"The constant is a fact about one machine, asserted on every machine."* D082
classed it MACHINE-BOUND. It did not then see that the file's gate is what should have declined.

## 2 · THE FIX — in the file's gate, by the runner's own rules

`survey()` gets a third universe condition: **`persist.log`'s earliest letter assignment must be `actors.js`'s
`LETTER_BIRTH`.** It is computed exactly as the `LETTER_BIRTH` assertion computes it, and when it fails the gate states
an **observation, not an interpretation**. That is pane E's rule, already written in this gate: a foreign letter history
and a damaged one read the same, and only `home=` tells them apart.

**Why this key, and why it does not weaken the assertion:**
- **It is the only exported fact about which letter history this is.** I looked for a better one. `actors.js`'s
  `LETTERS` is a path to the local `letters.json`, not a canonical map (`actors.js:89`), and L's letter-A pane appears
  only in a comment. The key comes from `actors.js`, outside this file, which is the same pattern the gate already
  follows for `PRE_LETTER`.
- **At home it still goes red.** On L, a mismatch makes the file decline, and **js-suite reads a NOT-RUN on the machine
  whose `machine_tag` equals `home=` as a CLASS ERROR** (rule f, `js-suite.js:105`). So a wrong constant or a damaged
  `persist.log` still fails the suite where the constant lives. **What changes:** the red is reported as a class error
  rather than as one assertion's failure, and in that case the other six do not run on L. That trade is stated here,
  not hidden.
- **Elsewhere it reads NOT-RUN, never green.** The runner re-runs every NOT-RUN forced and prints the forced outcome
  beside it (§0).
