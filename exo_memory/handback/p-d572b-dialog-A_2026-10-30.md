## 1. What changed (`166c67a`)

- **`src/core/document.js`:**
  - `edgeApronM` is an optional top-level field; `setEdgeApron(doc, w)` sets it, and `null` removes it.
  - `checkEdgeApron` refuses with `BAD_APRON` anything that is not a number from 0 to 10 (`APRON_MAX_M`, the exporter's own limit, `apron.js:128`).
  - The value is quantised to the millimetre like every other length. `serialize` writes it and `parse` reads and checks it.
  - **A track that never set one carries no field**, in memory and in the file, so every saved track's text is byte for byte what it was (the spawns and pit lane rule).
- **`app/core/coreshell.js`:**
  - `edgeApron()` gives the track's width, or the exporter's `APRON_WIDTH_M`.
  - `setEdgeApron(w)` is one undo step; a refusal goes to the message line, and nothing changes.
  - `exportArgs` puts `edgeApronM` into the options only when the track set one, before markers. So `{ ...opts, markers }`, which a core-mutation mutant anchors on, is untouched.
- **`app/export/export.js` runSegments and `app/export/exportjob.js` runJob:** both pass `edgeApronM` through. Both took only named options before, so without this the export's own process would have dropped the setting.
- **`app/menubar/items.js`:** `apronField(doc, shell)` and `APRON_HELP`. `fileItems` takes `apronRow`, and `app/index.html` passes it in. There is one CSS line for the help line: 11 px in `--text`, the whole row.
- **CHANGELOG** (Unreleased ▸ Added): "**Choose how wide the edge apron is, track by track: File ▸ Edge apron.** It is 2.0 m unless you change it, from 0 to 10 m, and it is saved with the track; tracks saved before open at 2.0 m. At 0 there is no apron: the gap under the edge is closed to the eye only, and a wheel can still drop under."
- **MAP.md:** the `apron.js` line now names `edgeApronM`, `setEdgeApron` and File ▸ Edge apron.
