## 0 · Headline — THE BRIEF'S BINARY DID NOT FIT, AND THE FILE ALREADY HAD THE THIRD CLASS

**The three unresolved ids are neither pre-letter panes nor live panes. They are not panes at all.** Each is a
fixed string that the Rust control plane writes into the board's `pane` field. `actors.js` has had a class for
exactly this since 07-31: **`NON_PANE`**, which already holds `chair`, `gate` and `blind`. `blind` got there the
same way these three did, when this assertion caught it within hours of its writer being built. So the fix is
neither of the two the dispatch offered:

- **Not PRE_LETTER.** All three first posted AFTER the letter system existed (`LETTER_BIRTH` 1785057198 →
  2026-07-26; the first row is 2026-09-09). Putting them there would fail that table's own guard at
  `actors.evidence.test.js:249` ("was still posting after the letter system existed — it is NOT pre-letter").
- **Not letters.json.** No seat is behind them. Giving one a letter would bind a script's output to a person,
  which is the thing the `NON_PANE` doc at `actors.js:291-294` exists to prevent.

This is the same finding as **B's on D, 2026-09-19** (`handback/p-six-reds-B_2026-09-19.md` §2.2(a), "STALE
CLASSIFICATION in `actors.js` `NON_PANE`, with the tripwire working"). I found it before reading B's file, and
