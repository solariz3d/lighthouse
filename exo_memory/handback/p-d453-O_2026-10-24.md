## 2. The cause, and the fix

**Why not even the straights.** `app/preview/trackmodel.js`'s branch for "an open track closed by adding road" (2026-10-15) kept the placed mesh only through `grownFrom`. That was a **prefix rule**: every placed segment's key unchanged, or 0. D447 changes the key of every placed curve it banks, so `grownFrom` returned 0 and the model fell through to `buildMesh`, which remakes everything.

**The fix (56c99aa).** `keptFrom` counts the placed segments whose key and lift key are unchanged at their index. The track model gates on that count being non-zero (0 when the new track is shorter).
- `reuseMesh(..., { grow: true })` already received a per-segment `same` flag. It keeps a piece only when that flag holds and the piece starts at the same pitch and bank, and it meshes every other piece and every seam beside one again.
- So a partial keep is as exact as a full one, and `reuseMesh`'s contract is that it equals `buildMesh` to round-off. The vertex check below is unchanged and passes.

**What "the straights" were on the row's lap.** Only 200 of its 950 placed segments are unchanged.
- Its pieces after the first are laid with `targets: { kh: 0 }` and Extend's default blend, which eases the turn rate to 0 over the whole piece. So p3 ("600 m straight") and p5 are long run-out curves, and Close banks them.
- Segment 600, on p3: roll0 0 → −0.425 rad.
- The 200 kept are p1, the only true straight. All 750 changed segments are changed by design.
