## 0 · THE SHAPE — the plan's, kept, with the two unnamed cases ruled

The refusal at `launch.ps1` (the `if ($dirty)` branch after `$behind` is known) is replaced by a park. **In order:**

1. **Untracked collision first (case b).** `ls-files --others --exclude-standard` ∩ the paths the pulled range **adds**
   (`diff --name-only --diff-filter=A HEAD origin/main`). Any hit means `--ff-only` would fail *after* a stash, so this
   refuses **before anything is stashed**, with **the original text** plus the colliding path. Nothing is touched.
2. **Park:** `git stash push -m "park <machine> <UTC stamp> behind=<n>"`, tracked changes only (the same set `$dirty`
   was computed over, `--untracked-files=no`). The stash's sha is read before and after, so a push that "succeeds" but
   creates nothing is caught. **Any failure → the original refusal text, nothing pulled** (tested with a held
   `index.lock`, a real way for a stash to fail).
3. **The existing `--ff-only`, unchanged.** If it fails, HEAD did not move, so the park is put straight back
   (`stash apply --index`, then drop). The Notify is the existing "git refused to fast-forward" one.
4. **Re-apply only on disjoint paths:** the stash's paths (`diff --name-only <stash>^1 <stash>`) ∩ what arrived (`diff
   --name-only <oldHEAD> HEAD`). Empty → `stash apply --index`, drop it, one green console line. Non-empty → **it stays
   PARKED**, and the Notify names the stash sha, its message, the overlapping paths, every parked path, and the one
   command to bring it back.
5. **NEVER conflict markers.** Re-apply is attempted only on disjoint paths, and if it still fails, `reset --hard HEAD`
   returns the tree to exactly the pulled commit, with the work whole in the stash.
6. **ONE RECORD per park:** a JSON line in `<git dir>\consonance-parked.jsonl`, with `at, machine, behind, stash,
   message, paths, overlap, outcome` (`reapplied` | `parked` | `parked-apply-failed` | `restored-not-pulled` |
   `parked-not-pulled`). **Why there:** it is machine-local, never tracked, never pushed and not in the data dir, so it
   needs no manifest rule, and it sits in the checkout the chair and librarian already work in. It is written UTF-8
   **without** a BOM, because PowerShell 5.1's `Add-Content -Encoding UTF8` writes one, and a BOM on line 1 would make it
   unreadable to `JSON.parse`.

**Park at LAUNCH, as recommended, and I agree with the reason:** launch sees every dirty case (a crash, a power cut, a
close without Leave), and Leave by rule touches no git (`dev/stick-waiter.js:61`).

### Case (a) — a pane that was mid-lap wakes to its in-flight edits parked

**Git cannot say which pane wrote a file**; a stash only knows paths. So the record carries **every parked path**, and the
Notify lists them. The librarian or chair matches them against the open lap's packets, which name each pane's owned
files. That's the one join that exists. A pane waking on a parked file should read the record (or `git stash list`)
before re-editing: its work is in the stash, not lost. **Not built:** an automatic pane attribution, because nothing
records one to read.

### Case (b) — an untracked file at a path the pull adds

Refused before the stash, with the original sentence and the path (test: "an UNTRACKED file the pull would ADD…").
Scope: only paths the range **adds**. An untracked file at a path the range *modifies* cannot exist, because that path
is tracked.
