## 4. Item 2: the plan's premise does not hold, and I propose leaving it out

- **The rule:** inside an outer `node --test`, an inner run takes `--test-concurrency=1`; alone, it keeps its own value.
  `T180_INNER_CONCURRENCY` overrides both. It lives once, as `IR.concurrencyArgs` in `test/inner_run.js`, the helper both test
  trees already share. The plan asked for a new helper in `app/test/`; I put it where the harnesses already load their shared
  code.
- **The sites:** the plan says 16; `grep "'--test'"` finds 19 inner spawn sites. Seven run several files above 1 and use the
  helper: core-mutation, mutation, acready, geom, lookmatch, texmaker and core_ramp. The rest already pass 1 or run one file,
  where concurrency changes nothing.
- **None of the seven opens a browser.** checked: each file was grepped for the 11 test files that call launchChrome or
  renderClips → 0 in all seven. So the 4 × 4 multiplier the plan names multiplies node processes, not browsers. inferred: the 11
  roots at 18:57 came from the outer 4 files, menubar-page's second browser, and other seats' runs.
- **The cost, measured on one harness:** mutation.test.js nested took **482 s** at concurrency 1 and **278 s** at 4.
  - inferred: the full suite took 2,509 s against about 1,475 s for 0.4.22 and 0.4.23 (which did more work, at
    SWEEP_SEEDS=60), and item 2 is the likely cause, since the cap never bound. This is not proved; I ran no full suite without
    `a8c7de5`.
- **What it may still buy:** less memory from fewer node processes at once. That is unmeasured.
- **The proposal:** land `cba8796`, `1e8e0c6` and lighthouse `2be890cd`; leave `a8c7de5` out. `1e8e0c6` touches only
  browser-cap.test.js, so it cherry-picks clean without it.
  - inferred: from a checked file list (`git show --stat`); the pick itself was not tried.
  - If the room wants the rule anyway, `T180_INNER_CONCURRENCY=4` restores the old speed per run.
- **The falsifier:** a full suite at `cba8796` plus `1e8e0c6`, without `a8c7de5`, that takes as long as 2,509 s would say the
  slowdown is not item 2.

## 5. Item 1's design, and item 3

- **The slot:** `os.tmpdir()/t180-browsers/slot-<k>.json` holds `{ pid, started, token, chrome }`. It is taken with `'wx'` before
  the spawn and given back on the Chrome's `exit` (and `error`), so every caller's existing `ch.kill()` releases it unchanged.
  Any slot still held is given back on process exit.
- **Takeover:** a slot whose holder pid is gone is taken over. A release removes only a slot that still holds its own token.
  Two takers of one dead slot can, at worst, leave one browser over N for a moment; this is noted in the code.
- **Waiting:** one log line after 30 s; an error naming the holders after 10 min.
- **N:** `T180_BROWSERS`, default 4, minimum 2. menubar-page holds one browser while it opens a second, so with N = 1 it would
  wait on itself.
- **texture-page:** its own Chrome now goes through `launchChrome`, which also gives it D400's own-port check. chrome-mute row 1
  drops it from the known launch sites (AMENDED D504) and asserts it has none of its own.
- **leftovers.js:**
  - a row, `orphan browsers N headless roots whose parent is gone: <prefix> n, …`;
  - `--reap-browsers` ends only roots whose profile starts with t180 and whose parent is gone (taskkill /T), re-checked by the
    same pid, start time and command line just before; it exits 1 when a kill fails;
  - without the flag it stays read-only.
  - On this machine at 01:11Z the row read 0. `--reap-browsers` was **not** run live (it would have ended another seat's
    orphan); its path is covered only by the injected tests.
