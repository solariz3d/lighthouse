## What I built (the plan's "What it is" and "The build")
`sources-gate.js`, a PreToolUse hook on `mcp__consonance__call_librarian|mcp__consonance__call_chair`, registered AFTER the second reader in the same matcher group (the D205 merge: one group, `[second-reader.js, sources-gate.js]`).
- **DENY** (reason names the unmatched items, says "NOT delivered", says the pointer is logged with the ring's sha, gives the fix and the format) when the `SOURCES:` line is missing, empty, or an item matches no completed call of this turn. `SOURCES: none (no state claims)` is allowed and logged (`kind: none`).
- **FAILS OPEN** on any error (unreadable stdin, no or unparseable transcript, any exception, an 8 s watchdog under the registered 10 s): allow, plus an `error` row where it can log.
- **Never loses a hand-back:** the deny's ledger row (`C:\Consonance\data\sources-gate.jsonl`: seat, tool, ringSha, kind, scrubbed first line as `pointer`, up to five `exo_memory/...` paths as `pointerPaths`, unmatched items; never the message) is written BEFORE the deny is emitted, and **if it cannot be written (no data dir, unwritable ledger) the ring is ALLOWED**. Secrets in the pointer line or items are redacted with the second reader worker's own shapes (a drift test pins the two lists equal).
- Position of the line is NOT enforced (anywhere, last `SOURCES:` line wins; continuation lines until a blank line or `NEXT:`). The plan says "second-to-last block"; enforcing the position would deny more for no gain.

## The care points
1. **The second reader still fires when the gate denies.** Both hooks match and run in parallel (docs), and the second reader allows at once and starts its worker. Test `THE SECOND READER STILL FIRES` runs both on one denied ring: the gate prints the deny, the second reader prints nothing and its stub worker runs. **A consequence to price in:** a denied ring ALSO costs one Sonnet read, so a denied-then-fixed hand-off gives the second reader TWO rows (the attempt and the re-send). They share `ringSha` when the message is re-sent unchanged, and differ when the seat edits the SOURCES line (the usual fix), so B's D203 precision scoring should join `sources-gate.jsonl` deny rows to `second-reader.jsonl` by time and seat, not by ringSha alone. This is the confound P3 already names, one level finer.
2. **What happens to a denied ring.** The seat sees the reason in-turn, as the tool's refusal; the same turn continues; it opens or drops the item and re-sends. Mocked: `IN-TURN` (deny, then Read, then the re-send allowed, ledger `['deny','allow']` with equal ringSha). **Live: see the LIVE section below.**
3. **Gaming, and what I chose (cheap, not airtight).** A Bash/PowerShell command counts toward an item only per SEGMENT (split on `&&`, `||`, `;`, `|`, newline) whose leading word is not a printer (`echo`, `printf`, `Write-Host/Output/Verbose/Warning/Error/Information`, `true`, `:`) and is not a `#` comment; so `echo path` does not count, `echo x && cat path` does. Also: an item must have COMPLETED without error in this turn (an errored Read, a failed Bash, or a call with no recorded result, such as one issued in the SAME message as the ring, does not count); a Grep over a directory or a Glob counts only if its result names the item. **Not caught:** `node -e "console.log('path')"`, `python -c`, a printer inside a wrapper (`powershell -Command "echo path"`), a Grep with no path whose result merely contains the basename, and any opened file that does not back the claim (the second reader's half).
4. **Turn boundaries.** The turn starts after the seat's last prompt: a user message with text, no tool result, not `isMeta`, not a subagent (sidechain) entry. A tool-result message with a reminder text block riding on it is still a tool result. An item read in a previous turn is denied (`TURN BOUNDARY` test, and the re-read after it is allowed). The transcript is read from the end in a 4 MB window that doubles to 64 MB until a prompt boundary is in view (a 5 MB tool result in the turn is tested).

## Deviations from the packet, each one small and listed
- **WebFetch URLs also count** (the plan names Read/Grep/Glob and Bash/PowerShell). Without it a seat that relied on a documentation page could only write `none` or drop the claim; this very hand-back cites one. One test and one mutant cover it; removing it is one `else if`.
- **Write/Edit do NOT count**, as the plan says: a seat listing a file it only wrote this turn is denied until it reads or `cat`s it. Cheap to add if P2 shows friction.
- Items from tools this gate does not understand (the board, MCP reads) cannot be matched, so listing them is denied; the seat names the command or file that carried the same fact, or `none`.
