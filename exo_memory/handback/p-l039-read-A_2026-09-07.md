## THE TALLY SCRIPT

30. `tool_audit_tally.js:41` — `const instruments = all.filter((n) => !n.includes('test'));` uses a
    **substring** where line 40 uses the `.test.js` suffix. `coupling-test.js` is a real instrument
    on the shelf and is silently dropped, which is why the script reports **46** instruments where
    the draft's own command returns 47. This one line causes items 31 and 32.

31. `:52` — the same bug's second face: `coupling-test.test.js` is reported as an **orphan test**
    because its subject was excluded from `instruments` at `:41`. It is not an orphan;
    `coupling-test.js` sits beside it.

32. `:82-87` — the partition self-check fires on every run against the current tree
    (`partition: instruments(46) + tests(55) != files(102)`) and the script exits 1. The check is
    correct; what it is detecting is item 30. As shipped, the tally cannot exit 0 here — so the
    draft's `:10-12` promise that its figures "re-derive from one run of it" cites an instrument
    that fails on that run.

33. `:52` — orphan detection strips only `.test.js` and does not know the repo's
    `<name>.<aspect>.test.js` convention, so it reports **13** orphans of which at least 11 are
    false: `actors.evidence.test.js`, `gen-consumer.build.test.js`, `gen-consumer.fixture-scope.test.js`
    and others all have their subject instrument on disk under the base name. The one class the
    script says it exists to catch is the class it mostly mis-reports.

34. `:55` — `const coverage = Math.round((100 * tested) / all.length);` divides an instrument count
    by **total files**, so the rate is diluted by the test files. Prints 43% where the intended
    quantity is 96%.

35. `:74` — the printed line is
    `coverage  ${coverage}%  (${tested} of ${instruments.length} instruments)`: it prints a
    denominator (46) that is **not** the denominator the number was computed with (102). The
    header's own promise at `:15` is "a coverage rate, with its denominator printed beside it rather
    than implied" — the printed denominator is the wrong one.

36. `:89-92` — the "second route" for coverage uses a **different definition** (denominator
    `instruments.length`), not a second derivation of the same one, so it disagrees by construction
    whenever any tests exist. It is guaranteed red, which means it cannot function as a self-check:
    a check that always fails detects nothing.

37. `:54` — `const tested = instruments.length - untested.length;` books every EXEMPT instrument on
    the covered side. `curate.js` and `pane-status.js` have no test and are counted as tested, so
    the rate is overstated in the direction that flatters the shelf.

38. `:29` — `const FALLBACK_ROOT = 'C:\Users\zackn\Consonance\lighthouse';` — a machine-specific
    absolute path hardcoded into a repo file. Also **it is the wrong machine path**: this checkout
    is `C:\Consonance\lighthouse`, with no `Users\zackn` segment.

39. `:29` — the same literal is a single-quoted JS string with unescaped backslashes, so `\U \z \C
    \l` collapse and the constant evaluates to `"C:UserszacknConsonancelighthouse"` — not a path at
    all. Verified with `node -e`.

40. `:30` — `path.resolve(__dirname, '..', '..') || FALLBACK_ROOT`: `path.resolve` never returns a
    falsy value, so `FALLBACK_ROOT` is **unreachable dead code**. The comment at `:27-28` calls it
    "a last resort for the case where this file is run from outside a checkout"; in that case the
    resolve still returns a (wrong) directory and `readdirSync` throws before the fallback could
    apply.

41. `:30` — the `TOOL_AUDIT_ROOT` environment override is undocumented: the usage block at `:20-21`
    lists two invocations and never mentions it, so the script's universe can be redirected from
    outside with nothing in the report saying it was.

42. `:37` / `:33-35` — `listJs` has no guard on a missing directory; run from a tree without
    `consonance/tools` the script dies with a raw ENOENT stack rather than the named failure the
    self-check section promises ("it exits non-zero and says which one failed").

43. `:43-45` — the comment asserts the EXEMPT pair are "entry points rather than instruments and are
    exercised through the suite indirectly." Nothing in the script or the draft checks that; it is
    precisely the hand-kept judgement the draft's §2 argues must not be smuggled in. Unsure whether
    the underlying claim about those two files is true — I did not run the suite.

44. `:17-18` — "The tally recomputes its own totals a second way." Only two quantities have any
    second route, and one of them is item 36. The `untested` and `orphans` lists — the two outputs
    the draft actually leans on — have no second derivation at all, which is what let items 30-33
    ship.

45. `:66-67` — in `--json` mode the report object is written to stdout, the self-check then fails to
    stderr, and the process exits 1: a caller parsing the JSON gets well-formed output with no
    `failures` field and no signal inside the document that its numbers are known-bad. Unsure
    whether this is intended; listing it because the JSON is the machine-readable surface.
