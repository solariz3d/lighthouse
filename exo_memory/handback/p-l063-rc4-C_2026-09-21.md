## 4 · A DETECTOR FALSE POSITIVE, FOR E — rows 22–24 are not paths at all

`DRIVE = /(^|[^A-Za-z0-9_])[A-Za-z]:(\\\\|\\|\/)/`. In the regex `(\d\d:\d\d)`, the substring **`\d:\`** is a
backslash, the letter `d`, a colon and a backslash — which is exactly a drive letter to this pattern. Measured from a
script file: `stamp.test.js:83`, `:86` and `:93` each match on `"\\d:\\"`, and a synthetic `(\d\d:\d\d)` matches too.

**Baselining them is harmless** — they sit in a test file and `BENIGN-TEST` is a correct verdict for what they are.
But they are **not machine paths**, and any regex containing a digit class before a colon will fire this detector
forever. The fix belongs in `portable-paths.js` — for example, refusing a match whose letter is immediately preceded
by a backslash, which rules out `\d:\`, `\w:\` and `\s:\`. **Named, not made**: that file is E's this lap.

*How I nearly got this backwards:* my first check was a `node -e` one-liner through the Bash tool, and it printed
**`false`** — the tool had eaten the backslashes, so the test string was not the regex at all. Re-run from a file, it
reads **`true`** on all four. My recorded trap, and a false *negative* this time.
