## What it is (what the keeper sees)
- **Select on the track:** a click on a piece selects it, a Shift-click selects the run from the piece selected first; a click on nothing clears. The selection is drawn bright over the road with an end dot at each end (`app/core/selectionlayer.js`). A pointer that moved more than 5 px was a camera drag and selects nothing; with the brush armed the click is the brush's.
- **Save as piece:** a name box and a button; the file is `<app data>\pieces\<name>.t180piece`, the core's `t180b.piece/1` text. A name in use is REFUSED (the native side refuses it too: a piece is never overwritten; delete it first). A run the core cannot keep (a mixed cross-section) says why and the button is off.
- **Pieces library** (`app/core/piecesui.js`): per piece its name, "3 pieces · 400 m · turn +95.6° · climb 0.0° · plain" and a plan thumbnail; **Add at head** (one undo step), a **Mirror on insert** box, **Rename** (inline box; the new name must be free), **Delete** (asks "for good?" first). A file that cannot be read is LISTED with the reason (a named refusal), not hidden.
- **Delete selected:** at the open end the pieces simply go (one undo step). **In the middle it is PREVIEWED, as Close is** (the librarian's ruling): the track as it would be is the see-through ghost on the preview, the text says which piece's start changes and how far each piece after the gap moves, an overlap check of the result is shown, and **Apply delete** writes the track to its backups first (a copy that fails refuses the delete by name and nothing changes), then deletes as ONE undo step; **Cancel delete** drops it. A closed track says CLOSED and tells how to open the loop (Ctrl+Backspace). A join the core refuses is `DELETE_REJOIN`, with no preview and nothing changed.
- **Native** (`src-tauri/src/lib.rs`): `list_pieces`, `open_piece`, `save_piece` (refuses a name in use unless `replace`, which the page never sets), `delete_piece`; a name never carries a path.
