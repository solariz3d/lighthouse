**Kept as it was:**

- checked, `stats.js` over the 7 month files: re-rendering the parsed rows reproduces each file **byte-equal**, 2502 rows. So the port reads the store exactly as ripall wrote it.

**Changed, because the packet asks for it:**
- ripall rewrote every file each run. **lineage-rip appends.**
  - It parses the store exactly, using each row header's char count. A file that does not parse to its last byte is refused by name (`LINEAGE_UNPARSED`), because deduplicating against a store it cannot read would be a guess.
  - New rows go at the end of their month file. Their index lines go under one `## added <when> (n)` heading at the end of INDEX.md.
  - A run with nothing new writes nothing.
- Refusals before anything is read or written:
  - an output inside a git work tree, found by a `.git` folder or file in the path or any parent (`LINEAGE_IN_REPO`);
  - an output inside the transcripts it reads.
- Read-only on the transcripts (`createReadStream`, flag `r`).
- One run at a time: `<out>/.rip.lock`, taken over after an hour and removed on exit.
- It runs at BelowNormal priority (`os.setPriority`).
- An empty line, and a user line that does not parse, are counted and skipped. Neither is fatal.
- `--dry-run` counts and writes nothing.
- The default store is `<parent of instances_dir>\private\third_place\lineage`, which on this machine is `C:\Consonance\private\third_place\lineage`. So the tool carries no machine path.
- The default seats are every seat the store already names, plus main, librarian and third-place.
  - Sibling panes are not seats by default: what reaches them is the chair's packets.
  - Reading the seats from the store keeps one project's name out of the code.

**Changed, because of what I found (§2):**
- The port skips the room's own delivery heads in new rows: `[pane:X]`, `[librarian:LIB]`, `[chair:MAIN]`, `[committee]`, `[duration wakeup: …]`.
