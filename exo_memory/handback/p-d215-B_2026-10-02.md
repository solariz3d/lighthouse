## 2 · The installer rematch fix (`install.ps1` +18/−2): RULING — it cannot disturb a hook it does not already manage

**The change, read line by line (`git diff 89f83758 9649ff6 -- dev/shell/install.ps1`):**
- In the merge loop, while walking every group, a hook matching the entry (`Test-SameHook`) is now treated two ways:
  - **it is dropped from its group** if the entry HAS a `Matcher` AND the group is not that matcher's slot (`ReferenceEquals($g, $slot)`). This prints `REMATCH … was matcher / now matcher` and counts as a change. `$found` stays false, so the existing add path puts it into the slot.
  - **every other hook** in the group goes into `$keep` and is written back. The group is rewritten only if something was dropped.

**The four properties:**
- **Moved, not duplicated:** a hook found in the slot AND elsewhere keeps the slot copy (`$found = $true`) and loses the stray one.
- **Unmatched entries are never moved:** the guard is `$e.Matcher -and -not $inSlot`. On today's manifest only three entries carry a Matcher: second-reader, sources-gate and dispatch-gate. Every SessionStart, UserPromptSubmit, Stop, SessionEnd and PreCompact entry is matcher-less, so this path is inert for them.
- **Foreign hooks stay put:** only a hook passing `Test-SameHook` for that entry is dropped; `$keep` preserves the rest.
- **Idempotent:** on a re-run the hook is in its slot, `$inSlot` is true, nothing is dropped, and "already correct" follows. A's tests cover this; my re-run passed it (44/44).

**The one way it could touch something unintended,** stated so it is not discovered later. This is pre-existing scope, not new:
- `Test-SameHook` matches by **leaf name** (`[\\/]<leaf>` in the command).
- So a hook the keeper hand-registered with the same file name (e.g. their own `…\sources-gate.js`) under another matcher would now be MOVED. Before, it was only REPOINTED.
- And if someone deliberately registered a managed hook under TWO matchers, the extra copy would be collapsed into the manifest's one.
- Neither exists on D (checked: the live settings below).
- **The two `l2/l3-overseer` "duplicates"** in `$register` that grep shows are commented examples (lines 241/243). They are matcher-less anyway.
- **No change to `Excluded` handling:** excluded entries are skipped before the merge, as before.
