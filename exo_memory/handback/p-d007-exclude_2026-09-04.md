## 6 · THE SEVENTH-ENTRY TEST — the durable half

Three clauses, ordered so the cheap answer is refused before it is written down.

> **CLAUSE 1 — NAME THE SUBJECT, NOT THE SYMPTOM.** A reason that describes what goes wrong *if
> the file ships* — *it crashes · it fails the scan · it turns a test red · it makes the tree
> large* — is **REFUSED**. A reason must state a property the file carries **in every tree**:
> *it is this record's state · it is this machine's state · it is the generator itself · it is a
> test whose subject is excluded.* If the only true sentence available is about a symptom, the
> entry is a manifest gap wearing an exclusion's clothes, and the honest encoding is **absence
> with a comment** — the form A already used for `dev/shell/*`.
>
> **CLAUSE 2 — A TEST NEVER GETS ITS OWN REASON.** A test follows its subject and inherits that
> subject's reason verbatim. A test needing an *independent* argument is evidence the subject's
> exclusion is weak — go re-examine the subject. **Preferably: derive them in code** rather than
> listing them, because three of today's six are hand-maintained duplicates of a fact stated
> elsewhere in the same object, and a duplicate that can drift from its master is maintenance
> law 1 inside a data structure.
>
> **CLAUSE 3 — AN EXCLUSION PAYS ITS DANGLING DEBT, COUNTED, BEFORE IT LANDS.** Run
> `grep -rl <basename> --include=*.js --include=*.md --include=*.rs .` **in a generated tree** and
> put the number in the reason string. Today's six owe **9** and not one reason mentions it. An
> entry whose debt cannot be paid — because a shipped tool *prints* the pointer — is not an
> exclusion; it is a decision to ship a broken instruction, and that is the keeper's call, not a
> seat's.

**The abuse condition, because a growth rule is the easiest thing here to weaponise.** Clause 1 is
refusable by relabelling: any symptom can be restated as a property with enough prose
(*"it crashes"* → *"it is a file with an unsatisfiable dependency"*). The check that survives
relabelling is **counterfactual**: *would this reason still be true if the tree it ships into were
perfect?* The generator's identity surface is true in a perfect tree. `carrier-drift.js`'s crash is
not — it is true only because the registry is missing, and a perfect tree ships one. **If fixing
something else makes the reason false, it was a symptom.**
