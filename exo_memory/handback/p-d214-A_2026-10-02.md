## What it does, and how a mixed message is told apart
`isPrompt(e)` is now the one definition of a turn boundary (the turn reader and the backward-read window both use it). A user message is a prompt unless it is a tool result, meta, a subagent's, or **machine-only notification**. `isNotificationOnly(e, text)`:
1. **origin.kind `human` → boundary, whatever the text** (Claude Code records a typed or queued message that way).
2. Otherwise it needs a MARKER: `<task-notification` or `[SYSTEM NOTIFICATION` in the text, or `origin.kind === "task-notification"`. No marker → boundary (a bare `<system-reminder>` is still a prompt: narrow on purpose).
3. Then **take out only the harness's own wrappers**: `<system-reminder>…</system-reminder>`, hook-output blocks (`<…hook…>…</…hook…>`), `<task-notification>…</task-notification>` blocks, and a `[SYSTEM NOTIFICATION …]` banner. **If ANY text is left, it is the keeper's (or a ring's): a boundary** — one word beside a notification, or text before it, or an unterminated `<task-notification>` (its text stays behind). **Only if nothing is left is it machine-only and NOT a boundary.**
Classes are D199's `keeper.js` notification forms (`C:\Consonance\sealed\qc_2026-10-01\d199_phase1\keeper.js`, its MACHINE regex: `<task-notification` and `\[SYSTEM`), and no others: a chair or pane ring, a keep-warm and a typed keeper message are all still boundaries. I did NOT adopt keeper.js's other machine forms (slash-command echoes, compaction preambles, interrupt markers): the ruling is about notifications only.

**Checked against real data, not assumed:** this session's transcript tail (40 MB). Claude Code writes a notification as a user entry with `origin: {kind:"task-notification"}`, `promptSource: "system"` and a content STRING starting `<task-notification>`; a ring, a keep-warm and a typed message carry `origin: {kind:"human"}`. Run through `isPrompt`: **99 notification entries → not prompts; 45 rings and 41 keep-warms → prompts; 12 other keeper-type entries → prompts; the 4 other non-prompts were all `isMeta`** (an image note and local-command caveats, the old behaviour). Two entries show `turnOrigin: "task_notification"` with `origin: null` on a keep-warm or other message, so `origin` alone is NOT trusted to decide, only to veto (human) or corroborate (task-notification); the text decides.
