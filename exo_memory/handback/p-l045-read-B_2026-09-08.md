## What I read, and the one judgement call

**I read the two named files and nothing else.** I did not open `consonance/ui/`.

That is a deliberate call and it costs me coverage, so I state it plainly. The brief defines defect
classes that normally require the world — *a dangling path*, *a citation to a real line that says
something else* — and the instinct is to go read `consonance/ui/*.js` to check them. `consonance/ui/`
is not on the void list. **But the brief also says "Read the object and nothing else. Everything you
need is in the two files," and that is an ALLOW-list of two files, which is the stronger and more
specific instruction.** I have been bitten before by treating a prohibition as the complete boundary
and reading everything it failed to name, so I took the allow-list at its word.

**It turned out to cost less than I expected**, because the object quotes most of the lines it cites,
so a citation that says something else is visible inside the object (the class-vs-id citation at `:234` is exactly that). Where a
claim genuinely cannot be checked from the object alone, I have listed it as **UNVERIFIABLE FROM THE
OBJECT** rather than passing it — a claim that asks to be trusted while §1 promises "re-derived from
a command printed beside it" is itself worth reporting.

**Checked and clean:** no machine-specific path appears in either file; the script's root resolution
(`ui_guard_census.js:24`) is correctly relative and resolves to `<repo>/consonance/ui`. No sha appears
anywhere in either file, so there is no wrong sha to find.

## THE SCRIPT

- **`ui_guard_census.js:81`** — `if (String(r.lines) > String(largest.lines))` compares line counts
  as **strings**, so `"933" > "1188"` is true on the leading `9` and the largest-file scan returns
  the wrong row. **This is the root cause of the wrong `largest file` at `:43` and its restatement at `:66`** and is the one defect here that silently
  produced a wrong published number.
- **`:37`** — `split('\n').length` counts one more than `wc -l` on any file ending in a newline, so
  every line figure in the census is +1 per file and the subtotals are +4, +5 and +3 respectively.
  Drives the "agrees to the line" claim at `:51`.
- **`:93` with `:117`** — `ratio = testLines / jsLines` is printed under the label
  `tests-to-instrument ratio`. The quantity computed is not the quantity named. Drives the mislabelled ratio at `:49` and `:62`.
- **`:110`** — `pad('asset bytes', w) + String(assetLines)` prints a **line** count under a
  **bytes** label. Drives `asset bytes` at `:42`.
- **`:62` with `:87`–`:90`** — `casesIn` returns `read: false` when the summary line cannot be
  parsed, and **the call site never reads `read`**. An unparseable or crashed test contributes
  `0 passed, 0 failed` and is still counted in `ran`, so a test that produced no result is
  indistinguishable in the output from a test that genuinely has zero cases.
- **`:58`–`:60`** — the `catch` swallows a non-zero exit and parses stdout+stderr anyway, so a test
  file that **fails or crashes** still contributes whatever numbers appear in its output and the
  non-zero exit is never surfaced. This is why the census can print `cases failed  0` for a suite
  the prose says exits 1 (the contradiction at `:88`).
- **`:61` against the comment at `:52`** — the comment says it reads the **trailing**
  `N passed, M failed` line; `exec` returns the **first** match in the output. A file that prints a
  per-suite summary before its final one is read from the wrong line.
- **`:27` / `:86`** — `STUB_LINES = 110` drops any test file under 110 lines as "a stub … not worth
  running". Three real test files fall under it and are dropped from the case count with no
  inspection of whether they contain cases; the threshold is a bare constant with no stated basis.
- **`:114`** — the `skipped` array holds the **names** of the dropped files and only
  `skipped.length` is printed. Printing the members would have refuted `:85`–`:86` on sight.
- **`:29`–`:34` / `:46`** — `classOf` returns `null` for any other extension and `inventory` drops
  those rows with no counter, so the `files` figure at `:107` silently excludes anything that is not
  `.js`/`.html`/`.css`. Drives the "nothing is hiding" claim at `:53`.
- **`:42`–`:44`** — the inventory does not recurse, so `vendor/` is excluded only as a side effect of
  the `isFile()` test that excludes **every** directory. The header at `:17` presents vendor
  exclusion as a deliberate rule; nothing in the code names `vendor` or would treat a second
  subdirectory differently.
- **`:79`** — `let largest = rows[0]` throws on an empty inventory rather than reporting an empty
  directory. **Unsure** whether this is in scope as a defect; it is a latent crash, not a wrong
  number.
- **`:111`** — `String(largest.name).padStart(6)` pads a filename to a 6-column minimum, which is a
  no-op for every real filename; harmless, but the column never aligns with the numeric column above
  it. **Unsure** / cosmetic.
- **`:6`** — the header comment says the script "runs each test file", which the `STUB_LINES` skip at
  `:86` makes false; the file's own description of itself is the source of the "runs each test file" claim at `:81`.
