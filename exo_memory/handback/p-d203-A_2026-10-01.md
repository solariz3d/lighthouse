## The docs I read first (2026-10-01), and what the build rests on
- **Hooks** — `https://code.claude.com/docs/en/hooks`: matcher syntax: "**Exact match**: Letters, digits, `_`, `-`, spaces, `,`, `|` only: `"Edit|Write"` … matches either tool"; "**MCP tool naming**: Pattern is `mcp__<server>__<tool>`". So `mcp__consonance__call_librarian|mcp__consonance__call_chair` is an exact-name matcher (no regex). The stdin payload carries `session_id`, `transcript_path`, `tool_name`, `tool_input`, `tool_use_id`. **Allow:** "Exit 0 with no output or empty JSON" (a deny/ask/exit 2 is the only way to alter a call); **"Other [exit codes]: Non-blocking error. Tool call proceeds. Exit code 1 does NOT block"**; "On PreToolUse, a timed-out hook does NOT block". Default timeout 600 s (registered here at 10 s).
- **CLI reference** — `…/docs/en/cli-reference`: `--safe-mode`: "Start with all customizations disabled … CLAUDE.md, skills, plugins, **hooks**, **MCP servers**, custom commands and agents … do not load. **Authentication, model selection, built-in tools, and permissions work normally**, which differs from `--bare`." `--strict-mcp-config`: "Only use MCP servers from `--mcp-config`" (I pass no `--mcp-config`, so none). `--tools ""`: "Use `""` to disable all [built-in tools]". `--no-session-persistence`, `--disable-slash-commands`, `--output-format json`.
- **Headless** — `…/docs/en/headless`: "**`--bare` … doesn't use your subscription login**" (it needs an API key). So the worker does NOT use `--bare`; it uses `--safe-mode`, which keeps the subscription auth. `--output-format json` returns `result`, session metadata, and `total_cost_usd`.
- **I did not refuse the plan:** the matcher and a fail-open allow can be done as planned, and `--safe-mode` is a better reentrancy guard than the plan's example (`--strict-mcp-config` alone would still have loaded every room hook in the child).

## What was built (all under `consonance/`, copied to `~/.claude/shell/hooks/` by `dev/shell/install.ps1`)
- **`hooks/second-reader.js`** (the hook). Dream gate; reentrancy exit on `CONSONANCE_SECOND_READER_RUN=1`; acts only on the two tools (`tool_name` must be in the set, else silent exit 0); **returns ALLOW at once: exit 0, no output, ever** (it never prints a decision; no input makes it exit non-zero). One worker at a time: a lock file `<data>/second-reader.lock` taken with `O_EXCL`, `{pid, ts, token}`; a live lock gives a `skipped-busy` row and the ring is not queued; a lock whose pid is dead, or older than 180 s, or unreadable, is stale and replaced. It starts the worker **detached**, hands it the job **over a pipe** (the message text never touches the disk from this hook), and exits in well under two seconds (measured < 1.5 s in the test, with a worker still sleeping for 3.5 s).
- **`hooks/second-reader-worker.js`** (the detached half; `Lib = $true` in the manifest). Builds the **turn** from the transcript tail (last 4 MB; the tool calls and results after the seat's last prompt: a user message with text and NO tool result; the ring's own call left out; results clipped, whole bounded at 60,000 characters, oldest results reduced first), asks `claude -p --model claude-sonnet-5-5 --output-format json --safe-mode --strict-mcp-config --tools "" --no-session-persistence --disable-slash-commands` with **QS verbatim** (compared against the plan file by a test), prompt on stdin, `cwd` = the temp dir, env `CONSONANCE_SECOND_READER_RUN=1`. **120 s timeout** (kills the child tree with `taskkill /T /F`), plus a watchdog at 130 s, so it cannot outlive itself. **Fails open:** every failure (no transcript, spawn error, non-zero exit, timeout, bad JSON, `is_error`) is ONE `error` row and nothing else; the lock is released in every path.
- **The row** (`C:\Consonance\data\second-reader.jsonl`): `{ ts, seat, tool, ringSha (sha256 of the message), status, flags, model, ms, tokens: { in, out, cacheRead, cacheCreate }, costUsd?, chars, turnChars, calls, promptChars, droppedFlags? }`. **The message text is stored by sha only.** *A decision for the chair:* `flags` quote the flagged SENTENCES (that is what a flag is, and B reads them blind), so each stored quote is kept only if it really is a substring of the message (a quote that is not is dropped and counted, never stored: model hallucination guard), at most 300 characters, at most 20 flags, scrubbed. No other part of the message reaches the log (tested: a unique sentence and a path from an unflagged sentence are absent from the log).
- **The secret scan** is self-contained in the worker (an installed hook cannot require repo tools): `sk-or-`, `sk-ant-`, `vck_` named, plus the generic `sk-`, GitHub, AWS, Slack, Google, PEM, Bearer, JWT and `NAME=value` shapes. It scrubs what is **sent to the model** (the message and the turn), **what is stored** (flags, error text), and error text from the child. (`sk-or-` and `sk-ant-` are also caught by the generic `sk-…` shape, so removing their named entries alone is an equivalent mutant; the tests assert the tokens are gone, not which entry caught them.)
- **Registration** — `dev/shell/install.ps1`: two `$files` entries (hook; worker with `Lib = $true`) and one `$register` entry `Event = 'PreToolUse'` with `Matcher = 'mcp__consonance__call_librarian|mcp__consonance__call_chair'`. **Two files outside your list that the install needed (named):** `consonance/hooks/dream-gate.test.js` (one line in its hand-kept ENTRY table: its roster is discovered from `install.ps1`, so a new hook without that line turns it red) and `consonance/state-manifest.json` (two `STAYS` rows: `second-reader.jsonl`, `second-reader.lock`; without them `close.js --check` refuses a data-dir file nobody placed). They are per-machine on purpose (a shadow ledger of a hook running HERE; two machines appending between syncs is the conflict the manifest's limits name).
- **The mutants harness is `consonance/tools/second-reader.mutants.js`, not `hooks/`:** `install.ps1 -Check` audits every non-test file in a directory the manifest draws from and `consonance/hooks/second-reader.mutants.js` made `install-only.test.js` go red (UNDECLARED); moving it to `tools/` fixed that.

- **The lock's race.** Acquire is `O_EXCL`, so two rings starting together cannot both take a FREE lock (tested). Two rings that both find the same STALE lock can each remove it and one can then hold a lock the other already took: a narrow window, worst case two workers for one ring. Not closed.
