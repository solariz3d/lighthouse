## 1 · The flaky M15
**Before:**
- B's widened D178 read: the full suite 980 / 972 / **1 fail** / 7 todo under load. M15 NOT CAUGHT by its named test, "only by a file-level failure of `geom_sculpt.test.js`". Run alone, caught 2/2.
- My own D179 final-tree suite (04:02–04:16Z, lock held): 1,096 / 1,088 / **1 fail** / 7 todo, the same M15, the same shape. The message was "NOT CAUGHT; failing tests on the mutant: …\test\geom_sculpt.test.js (6718.3265ms)", the FILE and nothing else.
- Measured alone (scratchpad `time_mutants.js`, unlocked, one mutant each): the M15 mutant run takes 7.5 s and M13's 8.5 s, both caught by name. So it is NOT a timeout: the harness's 300 s child limit is nowhere near.

**The mechanism, stated before the fix:**
- The harness judged a mutant from a run of ALL seven geometry test files, and looked for a failing line with the named test in it.
- When the process of one file ends before it reports its tests (under load; the exact crash was NOT caught by §2's reproduction, see there), that file's failures appear only as ONE file-level line. The named test's own failing line is lost.
- M15 makes every sculpt in `geom_sculpt.test.js` regrow the whole path, including my D177 tests with 32 km tails, so that file is the heaviest there is on this mutant.
- **The catch depended on whether the heaviest file survived the machine's load, not on whether the named test failed.**

**The fix** (`test/geom_mutation.test.js`, sha256 ebab5cbef6ae8db5; the harness, not the sculpt test):
1. **A mutant runs ONLY its named test:** `--test-name-pattern=^<the escaped name>`. No other test in the file can take the verdict down with it, and the run is far lighter (M13 + M15 together: 2 tests, 2 pass).
2. **The verdict is the named test's own line:** ✖ = caught, ✔ = NOT CAUGHT, no line = NO VERDICT. A no-verdict run is repeated, at most twice, and every attempt is reported. It is never read as a catch or a miss. The message then carries the last run's output tail, which the old harness threw away.
3. **A CONTROL** (new for this harness): the unmutated copy passes EVERY geometry test, whole files, not one name. So a catch still means something, and the full files still run once per harness run.
4. **The judge is tested:** "harness: the verdict is the own line of the named test (✖ caught, ✔ not caught), and a file-level failure alone is NO verdict". The inputs:
   - B's exact failing line shape gives no verdict;
   - a longer name that shares the prefix gives no verdict (so neither a false catch nor a false miss).
- Nothing waits on time. The remaining limits are the child's 300 s cap and `maxBuffer` 64 MB (was the 1 MB default). They are bounds, not assertions.
- **M13** (the D173 case, the same load pattern): the same fix applies to it, as to every geometry mutant. Alone through the new harness, M13 and M15 both caught by name.
