**So it was not a trivial wake.** It was a full turn that did real work and paid the full re-read. But **nobody
started it**: the harness did, to report a background job that the previous session's close had killed. Under L070's
rule (activation = any request since launch) that made A "activated", and keep-warm would have kept it warm all
session on no one's use. The keeper's rule is "wait for each seat and pane to **activate**".

**The fix chosen: the notice does not count as activation.** Activation is now `activated_by_use`: a turn-starting
`user` entry since launch that is not a tool result, not a sidechain, not `isMeta`, and **not a task-notification**.
The notice is recognised two independent ways:
- **by `origin.kind`**;
- **by its text starting `<task-notification>`**, because older transcripts carry no origin.

Surveyed across **3,657 transcripts on D**: turn-starting prompts are 5,120 `human`, 1,517 `task-notification`, and
5,731 with no origin. **All 1,517 task-notification prompts start `<task-notification>`**, so the two markers agree
on this machine.

**The plan's other option (panes leave no background job at close) was not taken, with the reason.** It cannot be
enforced from `main.rs`: any seat can start a background job at any time, and closing the app ends it mid-run; the
notice is the harness reporting that on resume. That fix would need every seat's behaviour to change, or a close-time
sweep in files I do not own. Excluding the notice fixes the defect at the one place that misreads it.

**Activation is now STICKY for the session** (`KeepWarmActivated`). Once a seat is seen used, it stays activated.
Otherwise a long session whose activating prompt has scrolled out of the 4 MB tail would silently drop out of
keep-warm.

## 2 · ITEM 2 — the missed-window report (my own L070 §5)

`keep_warm_missed(activated, since_start, already_reported)` is true iff the seat is activated, its last request
started **≥ 60 min** ago (the TTL; at 60 it is already past), and this crossing has not yet been reported. The tick
writes **one `chair` board row per crossing**, keyed to the request start that crossed, never one per tick:

    keep-warm MISSED -> abcd1234 (committee): 61 min since its last request started, past the 60-min cache lifetime;
    its next ping re-reads it whole. Last reason it was not pinged: composer not read empty: never over the keeper's typing

**The row names WHY.** The tick now records each seat's last skip reason (`KeepWarmLastSkip`), because a miss
reported as a bare count gives the reader nothing to act on. The Third Place's row carries no numbers, as before. To
make this possible **the transcript is now read for every seat that is on**, not only an idle one: a seat whose
composer sat full for an hour is exactly the case this report exists to catch.
