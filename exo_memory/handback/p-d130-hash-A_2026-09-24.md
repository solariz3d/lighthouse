## 1 · REPRODUCED FIRST (red: 37 existing pass + 1 new passes, 4 new fail)

`node --test consonance/tools/jev-judge.test.js` on HEAD's code with the new tests: **38 pass / 4 fail.**

Each failing test loads, changes the file ON DISK, and loads again **in the same process**:
- **worker, the built prompt:** the second load still built the OLD prompt. `require()` returned the cached module.
- **worker, hash vs code:** the second load's `sourcesSha` equalled the hash of the NEW files while the builder was the OLD
  code. **That is the defect exactly: a hash describing code that did not run.**
- **worker, top level:** a side effect written at the worker's top level RAN at load. `require()` runs the whole file; this
  was never needed.
- **`loadJevModule`:** the same cache: the second load's `prompt.js` was the old code under the new hash. **This is my own D123
  code.** Its comment claimed the hash was "taken from the same read that is required". It wasn't: a `readFileSync` and then
  a `require` are two reads, and the second can come from the cache.

The fifth new test (`prompt.js` still finds its shipped rubric through its real `__dirname`) passed on red by design. It pins
behaviour the fix must keep.

## 2 · THE FIX — compile from the bytes you hashed (not cache-busting), argued

- **`loadJudgeInputs`:**
  - the worker is read once (`w2src`);
  - `buildOverseerPrompt` is cut from THOSE bytes with `extractFunction` and compiled with `new Function`, the way
    `readNarrowedView` already is at `:107`;
  - `sourcesSha = sha([s2, w2src].join('\0'))`, the same strings that were compiled.

  `buildOverseerPrompt` reads only `view` and `discipline`, so compiling it alone is safe, and the worker's top level never
  runs.
- **`loadJevModule`:** `prompt.js` is read once and compiled from THOSE bytes by a new `compileModule(file, src)`.
  - **Public Node API only:** `module.createRequire(file)` for its own requires, and a `Function` wrapper given the real
    `__filename` and `__dirname`, so `DEFAULT_RUBRIC` still resolves to `jev/METHOD.md`.
  - No cache: every call compiles the bytes it is handed.
- **Why not bust `require.cache` instead:**
  - it still leaves TWO reads, the hash's and require's own, so a write between them recreates the gap, smaller;
  - it changes process-global state that other holders of the module see;
  - and `require()` would still run the worker's top level.

  Compiling the hashed string closes the gap by construction.
