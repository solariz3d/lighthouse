## 2 · THE RUNNER

- **One node process, in-process calls:** `require('./jev-shadow.js')`. `capture` every 3 s (the shortest job lifetime
  measured was 8.3 s, D103) and `shadow` every 10 min.
- **The cadence, argued.** Nothing acts on Jev's answer, so latency is worth nothing and batching costs nothing. The
  busiest measured day was 233 L2 + 302 L3 = **535 verdicts, about 22 an hour**, and 25 per 10 min is 150 an hour, so it
  keeps up with room to spare and a backlog drains in bounded steps. At about 10k input tokens × $0.000000042, a run
  costs at most about **$0.011**. **The daily cap of 600** sits above the busiest measured day, so it limits a runaway,
  not a normal day: about **$0.25**. Neither cap is ever lifted by a flag larger than the tool's own hard cap (500 a
  run).
- **One runner per store:** an exclusive `wx` lock carrying pid, a random token and the app pid. A second runner exits
  **3** and logs *"another runner (pid N) is running"*. A lock whose pid is dead is **taken over, and that is logged**.
  A runner releases only a lock carrying its own token.
- **Stops cleanly:** the app pid is polled every 5 s. On death it clears its timers, waits for an in-flight `shadow`
  call (bounded by jev-ask's 30 s timeout), releases the lock, logs `stopped: app closed`, and exits 0. SIGINT, SIGTERM
  and SIGBREAK do the same.
- **A capture that REFUSES stops the runner.** That happens when the installed L3 builder can't be found or a discipline
  file is missing. It stops rather than feed Jev a prompt the judge did not see.
- **Store: `%LOCALAPPDATA%\consonance\jev-shadow`** (on D, `C:\Users\nname\AppData\Local\consonance\jev-shadow`). It is
  outside the data dir with no manifest row, per the librarian's ruling. It holds `captures/`, `shadow.jsonl`,
  `runner.log` and `runner.lock`.
- **The judges are never touched.** It reads `~/.claude/shell` and writes only the store. A test snapshots the fixture
  shell dir before and after a run and requires them byte-identical. No installed file was edited, no `install.ps1` was
  run, and both scoring windows run as before.
- **On L:** no key is set there, so each launch will log `REFUSED … no AI_GATEWAY_API_KEY` and exit 2. That is loud in
  the log and harmless to the app.

**The Rust side:** `start_jev_shadow()` mirrors `start_exit_waiter()`. It spawns `node <repo>/consonance/tools/jev-shadow-runner.js
--app-pid <pid>` with `NO_WINDOW | CREATE_NEW_PROCESS_GROUP` and null stdio, and **`env_remove("CONSONANCE_DATA")`**, so
the variable D098 measured can't ride into this child even if the app inherited it. A missing script or node is `plog`ged
and skipped, so a sidecar can never stop the app opening. **The app never holds or passes the key.**
