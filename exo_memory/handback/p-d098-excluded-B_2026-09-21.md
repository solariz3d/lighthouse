## 3 · A TEST THIS CHANGE TURNS RED — ON D ONLY — AND WHY THE FIX IS IN THE TEST

    node consonance/tools/install-only.test.js      in this pane: 8 passed, 3 failed

The three that fail: *"POSITIVE CONTROL: a fresh install of this repo, checked immediately, is GREEN"*, *"a hook declared
deliberately unmanaged prints its REASON and is not red"*, *"an EXCLUDED hook that is live anyway is RED"*.

**Isolated in a fresh detached worktree at HEAD** (no untracked files, none of C's in-flight hook edits):

| worktree | `install-only.test.js` |
|---|---|
| HEAD, no D098 edit | **11 passed, 0 failed** |
| HEAD + only my `install.ps1`, `CONSONANCE_MACHINE=D` | **8 passed, 3 failed** |
| HEAD + only my `install.ps1`, `CONSONANCE_MACHINE=L` | **11 passed, 0 failed** |
| HEAD + only my `install.ps1`, variable unset | **11 passed, 0 failed** |

**The cause is one environment variable.** The test isolates `USERPROFILE` in a throwaway home (its own `:20`) but
passes the rest of `process.env` through, **and every seat the app launches carries `CONSONANCE_MACHINE=D` on D**
(`env | grep ^CONSONANCE` in this pane). My tag lookup reads that variable first, by the room's rule, so inside the
throwaway home the manifest resolves as machine D. The test's assumption, that an Excluded entry is red wherever it is
live, **stopped being true on D the moment the keeper answered for D.** Its assertions are right for every other
machine.

I checked the obvious alternative and refuted it: PowerShell's `$HOME` **does** follow `USERPROFILE`
(`HOME=…\fakehome` with `USERPROFILE` set), so `~/.consonance.json` is not leaking. The variable is the only path in.

**The fix, NOT made: `install-only.test.js` is not mine this packet.** In its `run()`, pin
`CONSONANCE_MACHINE: 'TEST-NEUTRAL'` in the child's env so the existing assertions hold everywhere. Then add one case
with `CONSONANCE_MACHINE: 'D'` asserting the overseers read **LIVE HERE BY RULING** when live and **RULED LIVE HERE, NOT
REGISTERED** when absent. **Until that lands, this `install.ps1` should not be committed alone:** on D, js-suite would
go red in every app-launched seat.

**One design consequence, stated so it is chosen rather than discovered.** On a freshly installed D, the overseers are
absent and nothing registers them, so `-Check` reads **red** until they are wired by hand. I made that red on purpose:
if they vanished from D's `settings.json`, a green `-Check` would hide the loss of hooks the keeper ruled live, which is
exactly the silent loss this installer exists to catch. The cost is that "a fresh install is immediately green" no
longer holds **on D**. If the room prefers the invariant, it is one term out of `$regBad` (`:675`).
