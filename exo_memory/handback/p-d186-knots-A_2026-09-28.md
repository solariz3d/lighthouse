## 2. The API (in `src/core/README.md`, "Knot insertion")
- **`refineKnots(doc, pieceId, a, b, maxSpan)` → `{ doc, inserted }`.** Every span of that road piece overlapping [a, b]
  (the piece's own s) that is longer than maxSpan is cut into equal spans ≤ maxSpan. The other spans are untouched. It
  returns a checked document (the same object if nothing was needed); commit it like any edit, and undo removes the knots.
- **`insertKnot(piece, t)`, `insertKnots(piece, ts)`, and `boehm(U, P, t)`:** the rule itself, unquantised.
- **For a brush:** refine [s₀ − r − 3h, s₀ + r + 3h] to h ≤ 2r/6, then brush.
- **Told to E, not done by me (E's file):** `sculpt.js` widens by the largest span of the WHOLE nearby piece
  (`rUsed = max(r, 3·span)`), so it will not narrow after a local refinement. It must use the spans under the window before
  E's sculpt can call this end to end.

### 8.1 The design (E's prototype design, my own exact computation)
- **h** (m, along world up) and **l** (m, along the gravity frame's horizontal left) are ordinary channels: the same knots,
  quantised to 0.1 mm, C1 at every joint.
  - Left out of a new piece, they are 0 or continue the previous one.
  - They must fade to 0 (value and slope) before a jump (`FLIGHT_OFFSET`), and start at 0 after it.
- **`offsetPath`** runs after `buildPath`. For each sample inside an offset:
  - r̃ = r + hŷ + lR;
  - r̃′ and r̃″ from the channels' exact derivatives and the base segment's yaw rate θ′ and its slope θ″;
  - T̃ = r̃′/|r̃′|, and κ̃ = (r̃″ − (r̃″·T̃)T̃)/|r̃′|² (the vector form of WIKI-CURV, ref 02 §1);
  - the frame rebuilt the geometry's way with the SAME roll; bankG and grade from it (ref 09 §7).
- **Where h, l and their first two derivatives are all 0, the sample is the geometry's own object.** So outside a hill the path
  is bit for bit.
- `path.segEnd` (the mesh closes each segment on it) and `path.head` are lifted too.
- **Deviation from E's prototype:** κ̃ is EXACT, where E's `offset.js` took a central difference of T̃ (O(step²), which E stated).
