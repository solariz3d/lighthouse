## 2. The cause

With no ghost on show, the drag handles ask the preview for one again every `RETRY_FRAMES` = 30 frames (`app/core/panel.js:499` at a795359, in `ghostModel`). The preview builds that exact ghost a slice at a time: `GHOST_SLICE_MS` = 2.5 ms per frame (`app/preview/preview.js:345-351`). Every `showGhost(…, { sliced: true })` replaces the build under way and begins it from its first step (`preview.js:431-435`). So a ghost whose build needs more than 30 frames of slices is restarted before it is whole, and none shows.

- checked: `node scratchpad\d426\steps.js <tree> <ev>` measures TEST 10's next piece with `ghostSteps`, in node.

  | length | steps | ms |
  |---|---|---|
  | 1,500 m | 3,002 | 82 |
  | 2,000 m | 4,002 | 107 |

  Each ms figure is that length's whole ghost build. At 2.5 ms a frame, 30 frames are about 75 ms of building.
- checked: the same script emulates the preview with a real clock and the panel's retry (a frame with no ghost counts; at 30 it asks again). Two runs gave different results:
  - first run: **the ghost never arrived in 1,500 frames, after 51 asks**;
  - a later run (`steps2.js … old`): it arrived at frame 88, after 3 asks.

  inferred: the work sits right at the margin (82 ms against about 75), so whether the ghost shows depends on timing. On his machine the frame's other work comes on top. That fits "weird bug".
- **The save that "brought it back" is NOT explained.**
  - checked: `coreshell.js:1176-1188`, `save()` sets only `name`, `dirty` and `message`. The preview's refresh of that state is a `same` update, which keeps any ghost. The panel's `draw` re-asks for nothing.
  - inferred: the ghost arriving after the save is the same timing margin (one restart cycle happened to finish), not something the save does. I did not reproduce the save itself.
- The hint in the plan (D421c's `reuseMeshSteps` / `startExact` / `updateSteps`) is not the cause. The repro's open, undo, redo and save path on the copies builds the ghost every time when it is asked once (`scratchpad\d426\repro.js`: 750 batches each time).

## 3. The fix (63e3dd9)

- `app/preview/preview.js:440-441`: `ghostBuilding()`, true while a sliced exact ghost is not yet whole. It is read-only. It sits beside `clearGhost`, apart from E's overlay and tint code.
- `app/preview/index.js`: answers `'t180:ghost-building'` from it. It has a header line, a listener and its removal in `unmount`.
- `app/core/panel.js:499-501`: the timed retry asks again only when the preview does not say it is building. A preview that does not answer counts as not building, so the retry for a preview that mounts after the panel is unchanged. A new document still asks at once (`triedDoc !== d`), and so does every typed field and hover, as before.
- `CHANGELOG.md`: one Fixed line, in [Unreleased].
