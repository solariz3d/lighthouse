## 2 · THE FIX — a per-reader SEALED window, opened by the packet's own arrival

**Why not `blind.lock`.** That lock is GLOBAL, and `main.rs` `board_push` (`:2118`) mutes **every** board push while it
exists. That includes the hand-back rings, so a window that "ends when the hand-backs are in" could never see them
arrive. It also mutes the chair's and the librarian's digest. It is the wrong instrument for this, and I left it untouched.

**Why no dispatch tool.** The leak rides the reader's own `UserPromptSubmit`. That hook is the one moment guaranteed to
come after the dispatch and before the leak. The dispatch verb (`chair_inject`) is Rust in main.rs / mcp.rs: B's this
batch, and live only after a rebuild. A PreToolUse hook on the chair would be a second writer on another seat's settings.
**So the arrival opens the window, and nobody has to remember anything.**

**The rules** (`blind.js`, "THE SEALED WINDOW"; `sealedGate` `:256`, called at `board-digest.js:324–332` before anything
can be emitted). The state is a file, `<data>/sealed.json`, holding `{ windows: { <session id>: {letter, opened, until, why} } }`.

| case | behaviour |
|---|---|
| **OPEN** | The prompt is a CHAIR dispatch (`[chair:…]` at its head, pasted or bare) naming a sealed or blind read / reader / readers / reading / pair. That very turn is muted and declared. The window is written atomically, and a `sealed window OPEN — for <letter>` row goes to the board. |
| **during** | Every later turn of that seat is muted, with the declaration: `[blind] pane activity withheld — a sealed window is open for R since …`. |
| **END** | That seat's own ring: a board row whose text starts `[pane:<letter>]` (optionally inside `<pasted_content>`), after `opened`. The digest resumes that turn, prefixed with `[blind] sealed window for R ended — its hand-back rang at …`, and a `sealed window CLOSED` row goes to the board. **Per seat:** B ringing first does not end C's window. |
| **not an end** | Another seat's ring, even one that mentions `[pane:R]`. A `call_librarian REFUSED…` row. A ring from before the window opened. |
| **CRASH** | The window is a file, so a pane that dies mid-read comes back still muted and still declared. |
| **DAMAGE** | An unreadable `sealed.json` mutes **every seat except the chair and the librarian**: "failed CLOSED … Fix or remove". A window with no usable expiry also fails closed. |
| **EXPIRY** | A 12-hour backstop, so a reader that never rings does not mute forever. It is declared in the turn it is found: "EXPIRED … with no hand-back rung". |
| **EXEMPT** | MAIN_SID and LIBRARIAN_SID (main.rs `:6766`) never get a window and are never muted by this file. A seat not in the read keeps its digest. |
| **close fails** | If the file cannot be rewritten, the seat stays muted, with a line saying so. It never resumes on a window the file still calls open. |

**Detector precision, measured over every chair dispatch on this board** (`isSealedDispatch` over the board's `[chair:`
user rows; the command is in §3):
- **17 of 1,183 flagged.**
- The flagged set includes **all six** sealed or blind reads I could identify: L108 B and C, L113 B and C, D116 E, D117 B.
- **The other 11 over-mute.** They are packets that discuss sealed reads (L107, L114, this D130 itself, three July cycle
  packets, status checks). The cost is that pane loses its digest until it rings, which is declared, and it fails in the
  safe direction.
- **False negatives I cannot count.** A sealed read whose packet names none of those words would leak (§5).

## 5 · WHAT THIS DOES NOT ESTABLISH

- **That it works live.** Nothing runs until the install in §4c. No live window was set, by the packet's rule.
- **Detection is wording-based.** A sealed packet that says neither "sealed" nor "blind" next to read / reader / pair is
  not detected. The honest backstop is to write "sealed read" in every such packet. Proposed, not adopted.
- **The 12-hour backstop is a choice, not a measurement.** A read longer than 12 h would leak after a declared expiry.
- **Seats with no letter in `letters.json`** can only end by the backstop. The declaration says so.
- **It guards `[panes]` only.** The pulse carried no study content in either trace. Any other hook that injects board
  content was not audited here.
