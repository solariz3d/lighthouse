## 2. What changed (src/core/extend.js)

- **The normal equations, built from each sample's support only.** One `basisN` per sample on the one knot vector gives the 4 basis values and
  the first control point. Each sample adds its ≤ 4 × 4 products to a band of 3 either side, and its ≤ 4 products to the right-hand side,
  **in the same sample order** as the dense code. The dense code's B[a][q] was exactly N_k: a one-hot sum adds only zeros to one N, and every
  skipped term is a ±0 product. So the system is the same to the last bit. The residual uses the held points' value summed in channelValue's own order.
- **The samples' basis values are kept per piece** (a WeakMap keyed by the piece, checked against its knots array, knot count and length).
  A typed edge also types er, so bank + cup + edge fits **four** channels (phi, c, e, er) on one knot vector; they now read the basis once.
- **The elimination is the same partial pivoting, kept to the band.** Below row c + 3, column c is exactly 0, so the pivot search and the
  forward elimination of every row at and below the pivot are the dense Gauss–Jordan's operations, bit for bit. With pivoting the upper
  band widens to 6 (LAPACK dgbtrf's kl + ku), and swapped rows are re-slotted. The singular return ("the fit as it was", |pivot| ≤ 1e-12)
  is unchanged, at the same column.
- **A banded back substitution replaces the Gauss–Jordan sweep above the diagonal.** This is the one step whose rounding can differ (§3).
- **WHEN the fit runs is unchanged:** same call site, same arguments, every tick as before. The preview frame loop is untouched.
