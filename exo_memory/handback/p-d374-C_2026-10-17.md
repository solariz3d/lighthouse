## 0. The answer

**It was broken, not too quiet, and only in the mode the builder starts in.**
- The panel reads the turn and climb fields as **corners** by default: `app/core/panel.js:182`, `turnAs.value = 'corner'`.
- In that mode the handles it draws are `climbDeg` and `turnDeg`, not `climb` and `turn`: `panel.js:395` `CORNER_KIND`, `handles.js:50-51`.
- `notePlan` (`app/sound.js`, at 2e0a98d `:104-112`) tested `kind === 'climb'` only. So a `climbDeg` tick fell through to the melody branch and **walked MEL128 exactly as a length drag does**. A `turnDeg` tick did walk the melody, but skipped turn's pan.
- In **rate** mode (`climb`) the climb effect works as specified.
- **None of the suspects named in the packet was the cause**: `rateOf`, `tickEven`, the sample path and the D345 single-step flag all work. `stepPlan`'s single path also goes through `notePlan`, so the fix covers the wheel and arrows too.

**The fix** (`app/sound.js`): `SOUNDS_AS = { climbDeg: 'climb', turnDeg: 'turn' }`, applied as the first line of `notePlan`. Each corner kind now sounds as its rate kind does. The rate kinds are unchanged.
- I widened it to turnDeg because it's the same one-line cause: a corner turn drag had silently lost its pan. Say if that should come out.
