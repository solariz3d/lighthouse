## A · `exo_memory/audit/ui_guard_census.js`

- **`:81`** — `String(r.lines) > String(largest.lines)` compares line counts as strings, so "largest
  file" is the lexicographically largest: it prints `chain-indicator.js (933)` while
  `chain-indicator.test.js` is 1188 and `term.js` is 1184.
- **`:37`** — `split('\n').length` counts the empty string after a trailing newline as a line, so
  every per-file count and every subtotal is +1 against `wc -l` (12 files, 12 extra lines, 5523 vs
  5511).
- **`:93` and `:117`** — `ratio = testLines / jsLines` where `jsLines = instrumentLines + testLines`,
  printed under the label `tests-to-instrument ratio`; that is tests-to-all-JavaScript. The
  tests-to-instrument figure is 1807/2703 = 66.9 %, not 40.1 %.
- **`:110`** — the row labelled `asset bytes` prints `assetLines`, which is a line count; no byte
  count is computed anywhere in the script.
- **`:62` with `:87-90`** — `casesIn` returns `read: false` when no summary line is found and no
  caller ever reads that field; a test that crashes before printing a summary contributes 0 passed
  and 0 failed and is still counted in `ran`, so a crashed suite and a green suite with zero cases
  print identically.
- **`:86`** — the `STUB_LINES` skip drops `librarian-wiring.test.js` (106), `scripts-load.test.js`
  (101) and `third-place-wiring.test.js` (109), which carry 11, 4 and 10 real passing cases, so
  `cases passed 105` is not the layer's case count; running all five files gives 130.
- **`:74` with `:86`** — the skipped files' lines are still summed into `testLines` and therefore
  into the ratio, while their cases are excluded from `passed`; the two headline figures range over
  different sets of files.
- **`:79-81`** — `let largest = rows[0]` with no empty-set guard: an empty or unreadable
  `consonance/ui/` throws on `largest.lines` rather than refusing, and the script has no "a green run
  over zero files is the bug" check.
- **`:17` with `:42-44`** — the header states `vendor/ is excluded throughout`, but no rule excludes
  it; `readdirSync` is non-recursive and `isFile()` skips directories, so vendor/ is missed
  incidentally and any `.js` placed in a future subdirectory of `consonance/ui/` is silently outside
  the denominator with nothing printed. `[UNSURE]` whether the non-recursive walk is intended.

## B · `exo_memory/audit/p-ui-guard-census_2026-09-08.md`

### §1 · The census

- **`:51`** — "`wc -l consonance/ui/*` agrees to the line" is false: `wc -l` totals **5511**, the
  census says 5523. That glob also includes `consonance/ui/vendor`, on which `wc` errors with "Is a
  directory", so the command as printed does not even range over the same set.
- **`:52-53`** — "`ls consonance/ui/ | wc -l` returns 12" is false: it returns **13**, because
  `vendor` is listed. The conclusion drawn from it — "nothing is hiding in the directory that the
  census does not see" — rests on the wrong count.
- **`:55`** — "`vendor/` holds two files — `xterm.js` and `xterm.css`" is false: it holds **three**;
  `addon-fit.js` is also there and is unnamed.

### §2 · The headline

- **`:62`** — "The tests-to-instrument ratio is 40.1 %" repeats the script's mislabel; the
  tests-to-instrument ratio is 66.9 %.
- **`:62-63`** — "For every ten lines of behaviour shipped into the browser there are four lines of
  test" is the prose gloss of that mislabelled number; on the ratio it names, it is about 6.7 lines
  of test per ten of behaviour.
- **`:63`** — "The Rust side of this application runs closer to one-to-one" carries no command and
  cannot be re-derived from either object; it is asserted, and §9 does not list it as unestablished.
- **`:66`** — "The layer's largest file is `chain-indicator.js` at 933 lines" is false;
  `chain-indicator.test.js` (1188) and `term.js` (1184) are both larger. The draft inherits the
  script's `:81` string-comparison bug without catching it.
- **`:66`** — "larger than its own test" is backwards: 933 against 1188. The sentence's own next
  clause at `:68` ("the suite is the biggest test file we have") contradicts it, and §1's table at
  `:22` and `:26` prints both numbers three pages above.
- **`:70`** — "`app.css` … larger than any instrument except `term.js`" is false: `chain-indicator.js`
  at 933 is also larger than `app.css` at 605.

### §3 · What runs

- **`:78-79` with `:82`** — the command shown is `node consonance/ui/chain-indicator.test.js` and
  returns "93 passed, 0 failed", but `:82` attributes those 93 to `gate-card-routing.test.js`, which
  returns 12. The conclusion at `:82-83` that the gate-card path is "the best-guarded thing in the
  layer" is built on the mis-attribution and is false — the chain-indicator suite is.
- **`:85-86`** — "no file in the layer is that small — so the guard is inert today" directly
  contradicts the census output the draft quotes at `:46`, `skipped as stubs 3`; three files are
  under 110 lines and were skipped in the very run reproduced above the sentence.
- **`:88-89`** — "`node consonance/ui/chain-indicator.test.js` exits 1, because two of its cases are
  declared red against a fix that has not landed" is false on both halves: it exits **0** with 93
  passed and 0 failed, and the draft's own `:48` and `:81` say zero failures.
- **`:81`** — "105 cases pass and none fail" is presented as the layer's case count; the layer has
  **130**, and 105 is only what survived the stub skip.
- **`:91-97`** — the density table divides by `wc -l` line counts (105, 108, 1187, 302, 100) while
  §1's table uses the census's +1 counts (106, 109, 1188, 303, 101); two units for one quantity in
  one document.
- **`:99`** — "`scripts-load.test.js` has the lowest density in the layer at 0.040" is false:
  `gate-card-routing.test.js` is 0.0397 against scripts-load's 0.0400, and the table at `:96-97`
  rounds them into a tie that the sentence then breaks the wrong way.
- **`:93` and `:104-107`** — `librarian-wiring.test.js`'s 11 cases are used in the density table and
  as the cross-check, although the census skipped that file as a stub; those cases appear in no run
  the draft prints.
- **`:104-105`** — `grep -c 'test(' consonance/ui/librarian-wiring.test.js` returns **0**, not 11;
  the file declares its cases with `t(`. The count of 11 is right and the command that is printed as
  producing it does not. `:107`'s "The harness and the count agree" therefore rests on a command
  that returns zero.

### §4 · The module surface

- **`:113`** — "Every `.js` in the layer ends with a `module.exports` guard, so all four instruments
  are requireable under node" is false: only `chain-indicator.js` has one (`:924`). `app.js`,
  `intro.js` and `term.js` contain no `module.exports` at all.
- **`:119`** — "`chain-indicator.js` exports **24 keys**" is wrong: the `api` object at `:911-921` has
  **26** (the last pair, `ESCALATE_MIN` and `POLL_MS`, is easy to miss and is the pair §6 later
  depends on).
- **`:123`** — "`SEAT_TABS` is exported and consumed by `term.js`" is false: `SEAT_TABS` occurs only
  in `chain-indicator.js`, at `:695` and `:919`; `term.js` never mentions it, so the "one place the
  two instruments meet without going through the DOM" does not exist.
- **`:126`** — "`intro.js` is the only instrument with no direct test file" contradicts the draft's
  own `:261-262`, which says `term.js` "has no test file of its own". Both are true of `term.js`;
  "only" is false.
- **`:126-127`** — "the census counts it as covered" describes something the census does not do: the
  script computes no coverage of any kind and the string `cover` does not appear in it.

### §5 · The DOM-write rule — the section is wrong end to end

- **`:155`** — "One live `innerHTML` write survives in the indicator, at `:687`" is false.
  `chain-indicator.js:687` is a `//` comment reading *"textContent, never innerHTML: a pane letter
  reaches here from the board…"*; the write two lines below it, at `:689`, is
  `el.textContent = parts.join(' ')`. The file's single `innerHTML` occurrence is that comment.
- **`:156-158`** — "The suite is green because it strips comments before scanning and this write sits
  close enough to a comment block to be swallowed by the strip … a scanner green over a problem it
  still has, and it is the most serious single finding in this draft" is false and inverted. The
  strip is deliberate and is documented in the test at `:183-186`, which records that v1 matched the
  bare word and went red on the comment *explaining* why innerHTML is avoided. The suite is green
  because there is no write.
- **`:160-162`** — "`chain-indicator.test.js:198` re-asserts the same rule against a hand-built string
  and is a redundant duplicate of `:189`. It should be deleted" is false and the recommendation is
  harmful: `:193-199` is titled **POSITIVE CONTROL** and exists to prove the comment-strip does not
  blank the input and leave the check reading clean forever. Deleting it removes the only guard
  against the exact failure mode `:156-158` claims to have found.
- **`:140-145`** — `grep -c` given four file arguments prints four `path:count` lines, not the single
  totals `22` and `42` shown as its output. The totals are correct as sums (9+1+0+12 and 7+2+0+33);
  the transcript is not what the command prints.
- **`:147`** — "three-quarters of the layer's DOM writes go through `textContent`" is wrong: 42 of 64
  is 66 %, two-thirds.
- **`:256`** — "Delete the live `innerHTML` write at `chain-indicator.js:687`" prescribes deleting a
  comment, and the comment is the one recording why the rule exists.

### §6 · The event surface

- **`:168-169`** — `grep -c addEventListener consonance/ui/*.js` prints nine `path:count` lines, not
  `18`; the glob also sweeps the five `.test.js` files, so the number is not "listeners across the
  layer['s instruments]" as the next sentence reads it.
- **`:171-172`** — "`term.js` owns 11 of them and `app.js` owns 4, so the two of them are the entire
  event surface — the other instruments register nothing" is false: `intro.js` has 2 and
  `chain-indicator.js` has 1. It is also arithmetically impossible against the draft's own 18, since
  11 + 4 = 15.
- **`:172`** — "and never have" is a claim about history with no evidence in either object.
- **`:181`** — "fifteen seconds, six times a minute" is wrong: 15 000 ms is four times a minute.
- **`:187`** — "a hop crosses the fifteen-minute escalation after exactly 900 polls" is wrong: 900 is
  the number of *seconds* in fifteen minutes; at one poll per 15 s it is **60** polls.
- **`:190-191`** — "The suite does not pin the cadence. It asserts that a timer is registered and
  nothing about how often" is false: `chain-indicator.test.js:1170` asserts
  `assert.strictEqual(timers[0][1], C.POLL_MS)`. The *conclusion* — that 15 s → 15 min would pass
  green — happens to survive, because the assertion compares the timer against the same exported
  constant and both move together; but the stated reason is not the case, and the draft does not
  make the distinction it would need to.
- **`:258`** — "Pin the poll cadence in the suite — one case, and it closes the 15 s → 15 min hole" is
  offered as unbuilt work that is partly built, and as written would not close the hole either, for
  the reason above.

### §7 · The arrow

- **`:203`** — "The three resolvers are contiguous, `:334`–`:390`, with no other function between
  them" is false: `positionTab(hop)` is declared at `chain-indicator.js:356`, between `tabForWho`
  (`:347`) and `destTab` (`:383`). The three cited line numbers themselves are correct.

### §8 · The markup

- **`:216-219`** — "The nav id is declared twice in `index.html` … one of them is dead" is false. The
  two `grep -c` hits are `:32`, which is inside an HTML comment (`<!-- id="tabs" so
  chain-indicator.js can find the nav …`), and `:37`, the only real declaration
  (`<nav class="tabs" id="tabs">`). This is the same comment-counted-as-code error as §5, in the
  same document.
- **`:259`** — "Fix the duplicate `id="tabs"`" prescribes a fix for a defect that does not exist.
- **`:224`** — "`intro.css` is 190 lines" is false: 19 by `wc -l`, and the draft's own table at `:36`
  prints 20.
- **`:224-225`** — "the largest piece of the layer with no behavioural test at all" is false in the
  other direction too: `intro.css` is the **smallest** file in the layer by a wide margin.
- **`:231-235`** — "the code at `:39` looks up the same id, so the two agree" is false: `term.js:39`
  is `section.querySelector('.gatecards')`, a **class** selector run against a pane's own section as
  the non-fallback path. The id lookup is at `:34`
  (`document.getElementById('gatecards')`). The framing also misses why both resolve at all:
  `index.html:106` carries `id="gatecards" class="gatecards"` on one element.
