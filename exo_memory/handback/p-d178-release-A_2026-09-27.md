## 1. The fix OWED (D178 addendum): a failed edit changes nothing

**The defect** (B's read, `p-d176-read-B:111-115`, reproduced): place straight, straight; sculpt w1 `roll1` = 0.74 →
committed (`past.length` + 1), `message` null, `resolveError` 'ROLL_STEP…'. The cause is `app/shell.js` `commit()`: it
pushed the new document into history and THEN resolved it, so a document that is valid but does not resolve went in with
only `resolveError` set. `dragTo` had the same shape.

**The fix** (`app/shell.js`, two places): `commit` resolves FIRST. If that fails, nothing is committed, the track stays
as it was, and the message is `not applied: ROLL_STEP: …`. `dragTo` does the same per frame: the drag keeps its last
good frame and says why. I chose to refuse, not to make the next word follow the roll: the contract is "a failed action
changes nothing", and silently re-rolling a word the user did not touch would be a second, hidden edit. That choice was
the packet's to make as "A's call" in C's test, and it can be revisited.

**Tests** (red first, `node --test app/test/shell-failed-edit.test.js`: 2 of 3 red before the fix):
- the direct reproducer: no history entry, the document byte-identical, a ROLL_STEP message, `resolveError` null, and
  the track still resolves;
- the same edit as a drag changes nothing and adds no history;
- a good edit after a refused one commits and clears the message.

After the fix: **3/3.**

**C's todo is now a real passing test.** `test/perf_soak.test.js` "A: a sculpt that would tear the surface is refused,

**A leak found and closed.** The first build (a plain `cargo tauri build`) produced an exe carrying **98 copies of the
build machine's home path**. Rust keeps each dependency's absolute source path for panic messages
(`<home>.cargoegistrysrc…`), and those carry the Windows user name. Measured with
`grep -a -c '.cargo.registry' t180-track-builder.exe` → 95, and `grep -a -c nname` → 98. The installer scanned
0 only because its payload is compressed.
- `release.cjs` remaps them at build time (rustc `--remap-path-prefix`: cargo's home → `/cargo`, the repo →
  `/t180`). The prefixes are computed from the environment when it runs, so no personal path is written into the repo.
- It then scans the finished exe and the installer and exits 2 if the user name (as a path part) or the home folder is
  still there.
- After the fix: `.cargo.registry` → 0. `nname` → 4, and **all 4 are false positives, read one by one**: substrings
  of ordinary words in a compression dictionary and Rust's own strings ("onname", "givenname", "Palestiniannamed",
  "<unnamed>"). None is a path. The scanner's own verdict was "no private paths" for both files.

**The build** (checked): `node src-tauri/release.cjs`, run as `scratchpad/d178/build_release.js` under the heavy-run lock,
in its OWN target dir (`CARGO_TARGET_DIR=scratchpad/d178/target`), `CARGO_BUILD_JOBS=4`, with a 40-minute hard timeout
that kills only its own process tree. Three builds:
- the plain one: 112 s, leaked, not kept;
- the remapped one: 107 s, clean;
- the **final one, after the §1 fix: 44 s, clean.** The embedded `app/shell.js` holds the fix

**The installer:** `scratchpad/d178/target/release/bundle/nsis/T-180 Track Builder_0.2.0_x64-setup.exe`, **2,316,850
bytes, sha256 `02f5968bbcded3e9d4d6ae1f4662e23a2e5bc26bd7caeeca87cf8a56b1a097b1`** (`ls -l`, `sha256sum`). The exe it
