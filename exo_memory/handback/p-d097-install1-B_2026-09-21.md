### Why the guard's ruling blocks the install, and is not merely a keep

The repo copy **has never carried** the guard: `git log -S"isFreshCwd" -- dev/shell/hooks/userprompt-submit.js` → only
the 08-17 import, `58b94f9`, which brought it into `session-start.js` and not into this file. The **installed** copy has
it (`grep -c isFreshCwd` → 2), and so do `session-start.js` and `precompact.js` in the repo. `lib/fresh-guard.js` is
installed and byte-identical to the repo (`cmp`), and `../lib/fresh-guard.js` resolves from `hooks/` in both trees.

**Installed as it stands, the repo copy regresses more than the guard,** because the repo's `main()` now **writes state
on every prompt** and the state file is **shared by every seat** (`STATE_PATH`, one file). On a fresh pane, which is a
stock claude spawned without a brief, it would:
1. inject L3 notices and the beacon into a pane meant to hear nothing, which is the case the guard's own comment names;
2. **mark those notices as surfaced**, swallowing them from the rooms that were meant to see them;
3. **overwrite `last_prompt_iso`, and on first run `first_seen_iso`, from a throwaway pane**, which corrupts the rooms'
   NEW-DAY rollover and the thread's age.

The machine copy avoided (2) and (3) by returning **before** `readState`. The repo copy has no such return.

**The port, exactly.** Insert these five lines in the repo's `main()`, immediately after
`const meta = safeParseJSON(safeReadStdin());` and **before** `const state = readState();`, as the installed copy has
them:

```js
  // Fresh panes (Consonance's unbriefed spawn type) get no interval narration
  // and no L3 — a stock claude hears nothing between turns. Returning before
  // readState also leaves the surfaced-notice state untouched, so a fresh pane
  // can't swallow notices meant for the rooms. See lib/fresh-guard.js.
  if (require('../lib/fresh-guard.js').isFreshCwd(meta && meta.cwd)) return;
```

**NOT MADE, and why:** this packet is phase 1 and does not give me the hook file. The port also needs a test, red first:
a fresh-cwd payload producing no output **and** leaving the state file byte-unchanged. It is small, and I will do it if
routed. **Until it lands, my ruling for step 4 is: do not install `userprompt-submit.js`.** The other two files do not
