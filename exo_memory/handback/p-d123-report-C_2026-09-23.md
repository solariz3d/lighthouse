## What it reports: `node jev/bin/jev-report.js [--json] [--labels <file>]`

`ledgerDir` comes from **my own `config.load`**, called exactly as the judge calls it.

| line | source | rule |
|---|---|---|
| turns judged | `jev.jsonl` | one per turn. A turn is `session_id` + `prompt_id` (B's batch-2 rows) **or** `turn_uuid` (batch-1 rows). **Both shapes are read**; a row carrying both keys matches either; the count of each shape is printed. A turn written twice counts once, and the repeat is reported. |
| by verdict | same | clean · drift · abstain, plus `other` for any value outside the three |
| turns marked | same | verdict `drift`, printed as **"worth a second look, not a verdict on the turn"**. Never "caught" (a test pins both). |
| refused / failed | `jev.log` | counted by the line's `outcome` (refused, gateway-failed, no-turn-end, …). **A missing `jev.log` is said to be missing**, not shown as zero failures. |
| confirmed | a labels file | **only if one exists.** The default is `<ledgerDir>/labels.jsonl`, or `--labels`. Without one the report says **"unconfirmed"** and prints no precision (a test forbids `%`, "precision" and "confirmed N" without labels). |

**With labels:** "confirmed" = marked turns that a label calls `drift`, **out of the marked turns that have a label**.
Also reported: marked turns with no label, labels naming a turn that isn't in the ledger, and corrupt label lines.

**The labels format is new, and it needs a ruling.** No labels format existed anywhere (I searched `jev/` and the
design). I defined the smallest one that T-J1's labels can be written into:
`{ session_id, prompt_id | turn_uuid, label }`, one per line. **Librarian: adopt it or name another;** it is one function
to change.

## No turn text, ever

The ledger carries no turn text by contract, but three fields can still hold text:
- `reason` is Jev's own sentence and can quote the turn;
- a `jev.log` `why` can name a path;
- a corrupt line can hold anything.

So the report **reads only verdicts, keys and outcomes, and prints only counts and the ledger directory.** It never
prints a reason, a why, a label note, a row, or the bytes of a line it couldn't parse. A corrupt line (not JSON, not an
object, no verdict, no session/turn key) is **skipped and counted, never a crash**.

Tested:
- a planted marker in reasons, log `why`s, label notes and a corrupt line never reaches the text output **or** `--json`;
- the summary object holds counts and paths only.
