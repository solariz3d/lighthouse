### G1 · credentials before a push: `consonance/hooks/push-gate.js` (PreToolUse, matcher `Bash|PowerShell`)
**What it refuses:** a `git push` whose diff ADDS a line matching a key shape:
- `vck_`, `sk-ant-`, `sk-or-`;
- `ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` / `github_pat_`;
- `AKIA` / `ASIA` followed by 16 characters;
- a `-----BEGIN … PRIVATE KEY-----` header.

Each shape has a minimum length, so the word "vck_" in prose passes.

**What is diffed:** `@{upstream}..HEAD`. With no upstream, the merge base with origin's default branch (`refs/remotes/origin/HEAD`, else `origin/main`, else `origin/master`). The repo is the `git -C <dir>` one, else the hook's cwd.

**The reason names file:line and the kind, never the secret.** The ledger `<data>/push-gate.jsonl` likewise stores file, line and kind only.

**Live, in this session** (a temp origin and clone with a fake key, since removed):
```

  planted2.txt:1  (gateway key (vck_))
The secret itself is not shown. Take it out of the commit (amend, or rebase and edit the commit that added it), rotate the key if it was ever pushed, then push again. Scanned: the diff since upstream.
```

### G2 · junctions before a delete: `consonance/hooks/delete-gate.js` (PreToolUse, matcher `Bash|PowerShell`)
**The commands it watches:**
- `git worktree remove`;
- `rm` with `-r`, `-R` or `--recursive` (and PowerShell's `rm -Recurse`);
- `Remove-Item` or `ri` / `del` / `erase` / `rd` / `rmdir` with `-Recurse` (`-rec` and longer).

**What it refuses:** a target that is, or contains, a reparse point. Node's `lstat` reports a Windows junction as a symlink. The walk never follows links, and is capped at 200,000 entries and 6 s.

**The reason names each link and its target**, and says to remove the link first in its OWN command without recursing.

**Live, in this session:**
- the Bash form `rm -rf /tmp/…/tree` (a junction to `precious/`): **refused**, naming `…\tree\link -> …\precious`;
- the PowerShell form `Remove-Item -Recurse -Force "$env:TEMP\…\tree2"`: **refused**;
- the chain `rmdir link && rm -rf tree`: **refused**, correctly, since it is checked before any part runs. The reason now says so.
- Then `cmd /c rmdir <link>` alone, and the tree after: **allowed**. `precious/keep.txt` was intact at every step.

## Two bugs, found LIVE by the packet's "show them firing", and fixed
1. **G1 failed open on the Bash tool's paths.**
   - My first live push, `git -C /tmp/tmp…/work push`, went through, to a temp bare repo with a fake key, so no harm done.
   - The ledger: `allow-error, not a git repo`. Git Bash hands native programs converted paths, but a hook reading the command text gets `/tmp/…` and `/c/…` raw.
   - **Fixed:** in both G1 and G2, `/c/…` becomes `C:/…`, and other absolute MSYS paths go through Git's own `cygpath -w`.
   - A RED test for each form. The re-run after reinstall was refused, as shown above.
2. **G2 read `"$env:TEMP\x"` as a literal path**, which didn't exist, so it allowed unchecked. It was right that time only by luck.
   - **Fixed:** environment variables are expanded. A variable the command itself sets stays NOT CAUGHT, and the header says so.

**Also fixed before the first run** (found by reading):
- a shell word `"…"/*` split into two, which would have sent the walk to the drive root;
- a later target running out of walk budget turned an already-found junction into an allow. A junction found now always denies.
