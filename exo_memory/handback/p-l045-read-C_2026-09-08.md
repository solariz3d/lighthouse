## A · THE SCRIPT — `exo_memory/audit/ui_guard_census.js`

1. **`:81`** — `String(r.lines) > String(largest.lines)` compares line counts as **strings**, so
   `"933" > "1184"` is true; `largest` can never be the real maximum. Actual largest is
   `chain-indicator.test.js` at 1188.
2. **`:37`** — `split('\n').length` counts the trailing empty element, so **every file is reported
   one line high** (`app.js` 298 here vs `wc -l` 297) and every subtotal, total and ratio inherits
   +1 per file, +12 across the layer.
3. **`:110`** — prints `assetLines` under the label **`asset bytes`**. It is a line count; nothing in
   the script ever reads a byte size.
4. **`:93` with `:117`** — `ratio = testLines / jsLines` where `jsLines = instrumentLines +
   testLines`, then prints it as **`tests-to-instrument ratio`**. That is tests-as-a-share-of-all-JS
   (40.1 %); tests-to-instrument is 1807/2703 = **66.9 %**.
5. **`:52` vs `:61`** — the comment says it reads the **trailing** `N passed, M failed` line; `exec`
   returns the **first** match in the output.
6. **`:86` with `:27`** — `STUB_LINES = 110` skips `librarian-wiring` (106), `scripts-load` (101) and
   `third-place-wiring` (109), i.e. **three of the five test files**, so `cases passed 105` describes
   two files and not the layer.
7. **`:114`** — `skipped as stubs` prints the count but never the names, so the three files that
   silently contribute zero cases are invisible in the output the draft quotes. [unsure — design
   choice, but it is what let §3 below go unnoticed]
8. **`:17` and `:42`** — the header claims `vendor/` is "excluded throughout"; there is **no vendor
   exclusion in the code**. It is excluded incidentally by `isFile()`, so a top-level vendor *file*
   would be counted as ours.
9. **`:79`** — `let largest = rows[0]` with no empty-directory guard; `rows[0].lines` throws if
   nothing classifies. [unsure — unreachable today]
10. **`:84`–`:91`, `:116`** — `failed` is counted and printed but never affects the exit status, so a
    red suite leaves the census exiting 0.

## C · ONE PATTERN, SAID ONCE

Three of the largest findings — 22, 26 and 17 — are the same move: **`grep` was run, its count was
taken as the count of the thing named, and the line itself was never opened.** A comment saying
*"textContent, never innerHTML"* became a live `innerHTML` write; a comment explaining `id="tabs"`
became a duplicate id; a file that declares cases with `t(` returned 0 for `test(` and the answer was
written down as 11 anyway. In all three the document then built a recommendation on it — delete a
positive control, fix a duplicate that does not exist, trust a cross-check that does not run.

The census block itself is faithful: I ran the script and its output matches `:16`–`:49`
character-for-character. **The defects are the script's arithmetic and the prose around it, not the
transcription.**
