## 1. What it does (`consonance/tools/heavy-run.js`)

- **`status()`, read only,** judges each of the three files (`heavy-run.lock`, `heavy-run.2.lock`, `heavy-run.hold`, and any higher
  slot holding a lock). It uses the primitives `--run` uses (`pidAlive`, `pidGone`, `processIdentity`, `sameHolder`, `ageOf`):
  - a dead holder is free when its lock is 30 minutes old or more;
  - a young dead holder is free only when the second method also says gone;
  - a live pid now running another program is free (reused);
  - an unreadable file is free past the 10 s grace;
  - a hold past 90 minutes is IGNORED;
  - the caller's own hold (its token in the environment) is "yours".
- **`statusReport()`:** one line for the hold and one per slot, each naming seat, pid, command and since.
- **The CLI block `--status`:** prints the report and sets the exit code. It takes no slot, moves, writes or creates no file, and posts
  nothing.
- **Why a separate judge and not a call into `acquire()`:** acquire's `takeIfStale` moves stale files aside as it judges them, and the
  mutant harness anchors on its exact lines. So the existing code is untouched, and the six "STATUS agrees with --run" rows pin the two
  together. Each judges the same lock with the same witnesses, and status's "free" must equal acquire taking it over.
- `consonance/GATES.md`: a short section, "Who holds what: `--status` (D675)", with the line above.
