## What was wrong (B's finding, re-read at the code before changing it) and the fix
1. **The placeholder.** The merge seeded `[pscustomobject]@{ hooks = @() }` for EVERY event array that was new; only an UNMATCHED entry uses it, so the first-ever entry on an event that carried a `Matcher` left it behind: the stray `{ "hooks": [] }` in `~/.claude/settings.json` PreToolUse. **Fix:** seed it only `if ($groups.Count -eq 0 -and -not $e.Matcher)`.
2. **Unmatched → "the last group".** On PreToolUse the last group is now the second reader's `call_librarian|call_chair` group, so a future unmatched PreToolUse hook would have been silently scoped to those two tools instead of firing on every tool. **Fix:** an unmatched entry takes the LAST group that has NO matcher (so on any event whose groups are all matcher-less the behaviour is exactly what it was), and a new matcher-less group is made when there is none.
3. **(B's optional item, done, with limits.)** Empty-hooks groups are pruned **only on events this run registered for** (non-excluded entries), **never a group that holds any hook** (a hook the script did not install stays), and a prune **counts as a change** (the write condition gained `-and $pruned -eq 0`). Without that last part a run that changes nothing else would say "already correct" and never remove the stray group that is on D now. The run prints `PRUNE <event> N empty group(s) removed`, and the summary line gained "N empty group(s) pruned".
