## B3. The false "interrupted" row

**What the launch check read, checked.**
- **Where.** `close_small_interrupted_at_launch` reads `close_small::progress()` over `C:\Consonance\data\close-small.jsonl`.
- **The newest click.** It was 2026-11-21T13:47:04Z, with three seats listed and three `seat` rows reading `cut:`
  (13:48:20, 13:51:12 and 13:52:48Z).
- **The missing end row.** That run has no end row. The build that ran it was L212, and L212 writes none:
  - `git show ab69150a:consonance/src-tauri/src/main.rs | grep -c '"event": "done"'` prints 0;
  - L221's `da5c6043` prints 1;
  - the ledger holds 0 `done` rows ever (`grep -c '"event":"done"'`).
- **Why it fired.** `progress()` set `finished` only on an end row, so the run read as unfinished. The launch check then
  writes its `interrupted` row unconditionally once a run is unfinished. Its board line stayed silent, because
  `interrupted_line` found no seat left, but the row was written anyway. And `progress()` then marked the run
  `interrupted: true` on the strength of that row.

**Fixed** (close_small.rs, commit fcc4c2ee):
- **Finished without an end row.** A run whose every listed seat has a final state is finished, so the launch finds
  nothing to end and writes nothing.
- **The row already written.** An `interrupted` row marks a run interrupted only if a seat was still left. So the row the
  11-25 launch already wrote reads, as it should, "Done: 3 cut, 0 failed".
- **What stays.** The existing interrupted-run row (five listed, one cut, then the restart) still names the four
  never reached.
