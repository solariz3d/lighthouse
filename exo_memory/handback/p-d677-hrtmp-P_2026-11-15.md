## 3. The fix, at the cause: `hrtmp-p` `7b54701d` (base `1bfea2b3`), `consonance/tools/heavy-run.test.js` only

**The cause.** `tmp()` made one top-level `heavy-run-*` folder per row through `scratch.mkdtemp`. Both `scratch.js` and the test remove them
in `process.on('exit')`. A killed run (the mutant harness's ranges are killed) runs no exit handler, so one folder per row was left behind.

**The cure. I used "the next run sweeps", not the janitor's prefix list.** Each run makes ONE parent, `scratch.mkdtemp('heavy-run-')` (the same
literal, so the janitor's source-read prefix still matches it). The parent holds `heavy-run-owner.pid` with the run's pid, and each row's folder
is `r<N>` inside it. The names are built at run time, so the janitor's source scan reads no new prefix from them. At its first `tmp()`, a run
calls `sweepDead(<root>)`, which removes every `heavy-run-XXXXXX` whose owner file names a pid that is not alive (`process.kill(pid, 0)`;
EPERM counts as alive). It never touches a live owner's folder (the mutant ranges run concurrently), a folder with no owner file (the old
layout, and the old 2,574), or anything without the prefix.
