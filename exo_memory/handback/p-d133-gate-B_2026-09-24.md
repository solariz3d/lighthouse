## 1 · THE GATE (`state-sync.js` `stateOnlyLines` :456, `pushDivergence` :474, `divergenceRefusal` :488; wired at :585)

**The rule:** a push is **refused** when any travelling file the manifest marks `install: "fast-forward"` (the append-only, two-writer set — 11 files on the live manifest) has a **state copy holding rows this machine's copy lacks**.

- **The unit is writeUnion step 7's:** complete lines as a **multiset**. A line held twice there and once here is one row short. A partial last line here is a writer mid-line and covers nothing.
- **A state copy that doesn't exist yet** holds nothing, so it lacks nothing, and the push is allowed.

**Where it runs.** The first build wrote each travelling file into the state tree **inside the read loop**, so a check placed after it would have compared against bytes it had just overwritten.
- The loop now reads everything first (`bufs`), then the gate runs, then the writes.
- The gate also runs **before the `--dry-run` return**, so a dry run can't call fine a push the real one refuses.

**The refusal (exit 1).** It says `DIVERGED — N travelling append-only file(s) in the state tree hold rows this machine's copy lacks`, and then, per file, the count and the line number of the first such row. It **names the recovery**:

    node consonance/tools/ledger-union.js --data "<data>" --write --file <file>

then push again. The receipt (`state-sync.push.json`) gets `outcome: "REFUSED_DIVERGED"` and `files: [{ path, state_only_lines, first_state_only_line, state_lines }]`. **Nothing is written, committed or pushed.**

## 2 · THE "IN SYNC" FIX (`syncRelation` :1830, `printHeads` :1846, `cmdStatus` :1850, `writeStatus` :373)

**Confirmed at source:** `printHeads` (it was `:1748-1749` before this lap's edits) printed `in sync: <every machine's head>` whenever any machine had pushed, after every push and pull, whatever the heads were. On D today it would have said "in sync" 354 hours behind.

`syncRelation(st, diverged)` is pure and returns one of:
- **`IN_SYNC`**: this machine authored the head (its machine row's commit is the head; short and long hashes compared by prefix).
- **`BEHIND`**: another machine authored the head, or this one never pushed. E.g. `NOT in sync: D behind — the head 9486b30 is L's; D last pushed f70d50a`.
- **`DIVERGED`**: rows were compared and a state copy holds rows this machine lacks. It outranks the heads.
- **`NONE`**: no machine has pushed.

Where each is used:
- **`printHeads`** (every push and pull line) prints the relation. It compares heads only.
- **`--status`** also compares rows, with the gate's own function, and prints the relation line before its JSON.
- **The status file gains `relation: { state, line, rows_compared }`. It is ADDED, never renamed**, because chain-status reads that file.
