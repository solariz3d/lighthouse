## 2 · WHAT IS BUILT

`consonance/tools/lap-row.js` — `--stage` now refuses a row that MOVES THE BATON unless the incoming
holder was rung first.

    node consonance/tools/lap-row.js --stage <lap> <stage> --holder <station> --by <station> [...]

- **`--by` is the station WRITING the row**, required only when the row moves the baton. Rows that
  keep the holder (`working`, `handbacks-in` at the same station) are untouched and need nothing.
- **`--by X --holder X` is a RE-TAKE** and is always allowed, no ring required.
- **`--by A --holder B` is a HAND-OFF** and requires an audited delivery to B on `board.jsonl` since
  the baton last moved. Without one it is refused, and the refusal names the sender's verb, the
  required holder, `mcp.rs:397`, and a copy-pasteable re-take command.
- The row records `by` and `gate` (`rung` | `retake` | `rung-unknown` | `unarmed` | `parked`), so
  every pass the gate could not check is **countable rather than inferred**.

**The ordering problem the packet named, checked at source rather than assumed.** The ring is
audited to the board and the row is written by this tool — two systems. `chair_audit`
(`main.rs:6669`) calls `board_push` (`main.rs:1806`), which appends to the board file **inline**,
before returning; the verb handler audits before returning its result string. By the time a seat can
type the next command the line is on disk, so the correct sequence is visible to the gate. The one
path where it is not is the blind window, handled in §3.

**No `--force`, deliberately.** `mcp.rs` rests its no-wedge argument on this file — *"the holder is
not written by any verb here [...] so the baton can always be moved by hand and the loop can always
be un-stuck."* A gate that could refuse unconditionally would break that property. It cannot: the
re-take is always allowed, so any seat can pull the baton to itself, ring, and hand off — the
documented recovery, and the exact three rows the chair wrote at 03:35–03:36. A bypass flag would
therefore only ever be used to skip the ring, which is the thing being gated.

## 3 · WHAT THE GATE CANNOT SEE — every one resolves toward ALLOW

The packet's instruction was that a gate refusing a correct sequence is worse than no gate. Every
ambiguity below therefore resolves permissively, and each permissive pass is **printed**.

1. **A relay by hand.** The keeper telling a seat leaves no audit row and reads here as silence.
2. **A ring about something else.** Any audited delivery to the incoming holder inside the window
   passes, whether or not it mentioned the baton. A false pass by construction.
3. **An unresolved pane id** — allows, and says so. This is the **opposite** of `baton-wake.js`,
   which fires on `unknown`. Not an inconsistency: baton-wake REPORTS, so a wrong guess costs a
   line; this REFUSES, so a wrong guess costs a blocked write. The cost asymmetry points the other
   way, so the same ambiguity resolves the other way.
4. **Cross-machine.** `lap.jsonl` and `board.jsonl` are machine-local; the laptop is invisible.
5. **The blind window.** While `blind.lock` exists, `board_push` MUTES every entry
   (`main.rs:1839`), including a real ring's audit line. The gate **disarms** rather than refuses.
6. **Whether the writer is who it says.** `--by` is self-report. Acceptable in a GUARD and not in a
   measurement: this protects an honest seat from disarming its own foot; a seat that lies to it has
   bypassed a guard aimed at itself. **Nothing here should be read as an instrument.**

**The arming rule is adjacency:** the gate arms only when `board.jsonl` sits beside the ledger and no
`blind.lock` does. That is why `chain-status.test.js` — a suite this file does not own, and one this
file has broken once before by widening a rule under it — **keeps passing by construction rather
than by an exemption**: a fixture ledger lives in a temp directory and a fixture has no board. When
the gate does not arm, the write proceeds and prints `BATON-ORDER GATE DID NOT RUN … written
UNCHECKED`, because an absent guard and a passing guard must never read the same.

## 5 · THE MUTANT THAT SURVIVED, AND IT WAS A REAL DEFECT, NOT A MISSING TEST

First mutation run: **38 of 39 caught**. The survivor was *"a REFUSED ring counts as a delivery"* —
deleting `if (/REFUSED|FAILED|NotAttempted/.test(t)) return null;` changed nothing.

It changed nothing because every refusal and failure shape in `main.rs` already fails the anchored
patterns below it (`call_chair REFUSED …` and `call_chair -> Main FAILED:` both lack the `[`; the
failure line is `chair_inject (chair: …)`, underscore, against `chair injected (chair: …)`, past
tense). **A guard whose removal no test can detect is a comment that reads like one** — the shape my
own map records — and I had shipped it into the gate built on that finding.

It was **worse than dead**. Measured:

    (scratchpad/m2.js — the anchored shapes over the live board)
    real deliveries by anchored shape : 376
    the broad guard would DISCARD     :   2 (0.5%)
      -> chair injected (chair: claude-opus-5) -> 18916fe2 [delivered and received]: [chair] THE BUILD RAN AND FAILED…
      -> chair injected (chair: claude-opus-5) -> 1582ff09 [delivered and received]: [chair] THE BUILD RAN AND FAILED…

Both are real, delivered injections whose 110-character **preview** quoted a failure. **Discarding a
delivery makes this gate refuse a correctly-announced hand-off** — precisely the failure the packet
told me to design against, arriving inside the guard meant to prevent it.

Removed rather than tested around. What survives is the narrow case the broad test was hiding:
`[NotAttempted]` matched **inside the receipt bracket**, never anywhere in the preview. The mutant is
kept, pointing the other way: *"the keyword guard comes back, discarding real deliveries whose
preview quotes a failure"* — and the suite now goes red on its **return**.

**That mutant's own replacement then survived too**, because it broke only the `call_librarian` half
of the alternation while the test asserted only the `call_chair` half. Fixed by asserting both.
**Fifth time mutation has caught a test of mine passing for the wrong reason.**

## 7 · THE BUILDING.md LINE — DRAFTED, NOT LANDED

For `brief/BUILDING.md`, immediately under `## THE ORDER OF A DISPATCH` (:208). **I did not edit the
file**; it is a shared carrier and B and A are working this lap.

> **RING BEFORE THE ROW.** The dispatch fires *before* `lap-row.js --stage … --holder <them>`, never
> after: writing the row hands the baton away and **revokes your own standing to send it**
> (`mcp.rs:397` — each seat's one verb requires that seat to be the holder). That is the nine
> out-of-turn refusals on the board, two of them caused by exactly this inversion, including the
> chair's own at 03:35 on 2026-09-04 with the rule in its own context. The writer now enforces it:
> a row that moves the baton needs `--by <you>`, and a hand-off with no audited ring is refused and
> names the recovery. `--by X --holder X` is a re-take and is always allowed.

If the section's sequence line is also being amended, it becomes:

    finish the OUTPUT TO THE USER  ->  verify  ->  write/commit  ->  RING  ->  the lap row, SAME TURN

**Why this is a line and not just the code:** the code refuses on this machine only. A seat reading
BUILDING.md on the laptop, where `board.jsonl` does not carry the desktop's rings, gets an unarmed
gate and no refusal at all.

   is wrong for how seats actually run this tool and the adjacency condition should move.
