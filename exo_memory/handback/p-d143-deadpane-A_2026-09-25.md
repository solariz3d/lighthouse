## 0 · What already existed — and what was missing

**Detection was already there.** Each pane's waiter thread in `spawn_claude_pane` (`child.wait()`, then `emit("pty-exit")`)
saw Main die; term.js dimmed the pane, wrote `— process exited —` and added the ↻. So no watcher was added: the D143 work
**reuses that one thread** (a test pins exactly one `child.wait()` in the function). What was missing: no board row, no
record the rest of the app could read, a seat header still reading "awake", no automatic recovery, and keep-warm reasoning
from a stale stamp about a process that was gone.

## 1 · What was built

**Backend (`pane_exit.rs`, pure; wired in `main.rs`):**
- **`decide(still_ours, fixed_seat, pane, auto_reopened)`** → `Intentional` / `ReopenOnce` / `ExitedAgain` / `Prompt`.
  - **An exit counts only if the map still holds THIS child's pid, and no Leave has begun.** Every intentional end takes the
    session out of `Panes` first (`pty_kill` removes it, the Leave drains the map, `insert_pane` replaces it with a new pid),
    so this is exactly "nobody meant it" — and an intentional end does not spend the seat's once.
  - **Fixed seats (Main, the librarian, the Third Place): reopened ONCE per app run**, `--resume`, through the same
    `spawn_claude_pane(…, resume=true, …)` + `insert_pane` that ↻'s `pty_reopen` uses, in the seat's own folder
    (`main_cwd()` / `librarian_cwd()` / `third_place_cwd()`). A second exit — the reopened child dying too — is `ExitedAgain`:
    shown, posted, **not** reopened.
  - **Committee and human panes: `Prompt`**, never reopened by the app; the ↻ is the prompt.
- **`on_pane_exit`**, called by the waiter after `pty-exit`: records the exit (by pid) in `PANE_EXITS`, posts a board row,
  emits `pane-exit` {pane, code, action} to the UI, and for `ReopenOnce` spawns + inserts, then posts `pane REOPENED -> …` and
  emits `pane-reopened` — or posts `pane REOPEN FAILED -> … — ↻ on its pane retries it by hand`.
- **The rows** (`exited_row`): `pane EXITED -> <short> (<role>): its claude process ended by itself (exit code N); a fixed seat,
  so the app is reopening it once, resuming the same session` · `pane EXITED AGAIN -> … not reopened automatically a second time
  (a crash that recurs is not bounded by retrying) — ↻ on its pane reopens it` · `pane EXITED -> … ↻ on its pane reopens it (a
  committee pane is never reopened automatically)`. The Third Place's rows name it and carry no number (its rule). None says
  awake.
- **`liveness(exits, pane, current_pid)`**: Exited only if the recorded exit is the child the map holds NOW — so a reopened
  seat (a new pid) reads awake, and a dead one never does.
- **keep-warm (item 4, on C's D138, not undoing it):** the one `match keep_warm_decision(…)` keeps its exact text; a first
  arm `_ if exited` records the skip reason `KEEP_WARM_EXITED` ("its process EXITED: the claude child ended and the pane was
  not reopened — nothing to ping; ↻ on its pane reopens it") and pings nothing. The missed-window row goes through
  `keep_warm_row_for`: an exited pane gets the missed row **with that reason, never D138's "waiting on YOUR answer"** (an
  AskUserQuestion open in a dead process's transcript is waiting on nobody); a live pane gets D138's row word for word
  (tested equal).

**UI (`term.js`):**
- **The addition, the garbled reopen — the librarian's trace verified, both causes real:** nothing in term.js ever called
  `term.reset` (grep, HEAD), and `fitPane` sends `pty_resize` only when the fitted size differs from `p.sentRows/sentCols`
  (`:873`), so after a reopen the new PTY — born at 34x120 (`EMU_ROWS`/`EMU_COLS`) — never learned its size. **The proposed fix
  is right and is now `resetForReopen(p)`**: `p.term.reset(); p.sentRows = p.sentCols = undefined;` (plus un-dead, ↻ removed).
  It runs **before** the new process is started, so the new claude paints on a clean terminal (resetting after would wipe its
  first paint). **Both paths come through it:** `reopenPane` (↻) and `onPaneExit({action:'reopening'})` for the automatic
  reopen; `onPaneReopened` then fits, and the cleared last-sent size makes fitPane send it.
- **Seat headers never read "awake" over an exited child:** new wake states `reopening` ("Main's process exited — reopening it
  once") and `exited` ("Main's process EXITED — ↻ on its pane"), for all three seats, via one `setSeatWake(role, state)`.
  Only a landed reopen (↻ succeeded, or `pane-reopened`) sets `awake`. `pty-exit`'s ↻ creation moved into `markDead(id)`,
  also used when a reopen fails.

## 2 · Refusal considered, not taken

Auto-reopen is bounded, so I built it. **The loop:** once per fixed seat per app run, pinned by test and mutant. **A refused
`--resume`** (the crashed session unresumable) already returns Err from `spawn_claude_pane`'s P1b handshake (`:1191`,
exit inside 1 s) → one `REOPEN FAILED` row, no retry. **During a Leave** the spawn funnel refuses, and `on_pane_exit` also
requires `LEAVE_IDLE`. **`--resume` after a crash** is what the keeper's own ↻ did this morning and it resumed (garbled only by
the UI bug above). **The price of "once per run":** a second, unrelated crash hours later is not auto-reopened — it is posted
as EXITED AGAIN and the header says ↻. That is the bound the packet asked for; loosening it (e.g. reset the once after N
healthy minutes) would be a new policy and is not built.

## 4 · NOT verified

- **Nothing live.** No rebuild, no crashed child in a running app: the auto-reopen, the rows on the real board, the header
  text, and the reset + resize on a real xterm are proven only by the tests above (source shape + pure functions + a JS stub
  of the terminal). The first real crash after the rebuild is the live check.
- **Event order** in the UI (`pty-exit` → `pane-exit` → the new PTY's output → `pane-reopened`) is assumed from their emit
  order: the first two come from one thread in sequence, and `pane-exit` is emitted before the spawn starts the new process.
- **A child that exits before `insert_pane` has put it in the map** (inside the spawn itself) reads as not-ours and is silent
  beyond today's `pty-exit`. The resume handshake covers the refused-resume case; an instant crash of a fresh spawn is not.
- **A ring or delivery into an exited pane** (the dead session stays in `Panes` until ↻, as before) is not addressed:
  `librarian_call_exec` still sees Main "present". Named for a later lap — the exit record makes it a small check.
- **Main at 97% context** will likely auto-compact soon after a resume; expected, not tested.
