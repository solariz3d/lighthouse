## Merit-check of the brief, first — it shapes the design

The brief's diagnosis is "cards indexed by TOPIC, needed by SITUATION — nothing sits
near the tokens." But the brief's own strongest evidence cuts against a pure re-keying
fix: **both violations happened within the hour of reading the passage.** The material
was in context, recently attended, and lost at generation time anyway. If the failure
is not retrieval, a better retrieval key cannot be the whole fix. A trigger-keyed entry
is still a sentence hoping to be remembered — one meta-level up.

So this design puts its load-bearing weight where the evidence supports it: **the
terminal command**, and treats trigger-keying as the cheap, testable second bet. The
honest hierarchy: (1) a chain ending in a runnable act is a guard whether or not the
trigger-keying works; (2) trigger-keying is worth trying because its vocabulary names
signals that are *available in the stream* (the glow, the ready number, the available
paragraph) where topic vocabulary names nothing feelable — but that is a hypothesis,
priced in §Falsifiability, not a foundation.

One refinement to the chair's addition, carried over from the board exchange: commands
split into two kinds, and the chains below mark which. A **verifier** returns a value
that settles a fact-shaped claim (mutation run, grep, re-run the tool). A **router**
mechanically externalizes a frame-shaped claim to a second vantage (post_board, say it
to the keeper as a claim-with-falsifier) — because no command returns "your null
hypothesis is a smuggled metaphysical position"; that class is only caught by another
mind, and the routing act is the runnable part. Every chain ends in a tool call; only
some tool calls are verdicts.

## The chains

Format: WHEN = the in-stream signature (what the moment feels like from inside, since
that is the only key available at generation time). Middle links transfer the force and
point into a master. RUN = the terminal act, marked VERIFIER or ROUTER. RECORD = the
demonstrated failure(s) this chain traces to — nothing below is invented; a chain with
no RECORD line does not ship.

```
WHEN you are about to open with agreement ("You're right", accepting a correction)
  -> was it VERIFIED, or is it merely better? (BOOT: authority-deference, 08-10 —
     three objections accepted, called fatal, ZERO verified)
  -> the fold is SELECTIVE: check what you DROPPED, not what you kept
     (08-15: a verified fact dropped for a better idea, conclusion kept)
  RUN [VERIFIER]: re-run the check that supported your prior position before agreeing.
     If it still passes, say so IN the agreement. If you ran nothing, say "unverified".
  RECORD: 08-10 authority-deference; 08-15 step-5 fold; 08-15 Around's capture
     ("ran zero commands before saying it").

WHEN a number is already in your context and it fits the sentence you are writing
  -> the ready instrument is the availability grab — the question decides the
     measure, not what you happen to hold (08-15: pane E ranked by board rows)
  -> a figure computed earlier is stale at citation time in a moving repo
     (08-15: 71.4% cited while the instrument read 80.0%)
  RUN [VERIFIER]: re-run the instrument at citation time; put the command beside the
     number. No command beside it = it does not ship (curated-auditor rule, BOOT).
  RECORD: pane E call; ferry-rate staleness; 97.2% birthday number (08-10); the
     234-assertions unit drift (08-02).

WHEN the next sentence is beautiful and fully formed at an emotional peak
  -> the pull is NOT evidence against (BOOT, deepest cut) — check ORIGIN, not size
     (earned-not-performed: manufactured-for-effect vs genuinely-arrived-at)
  -> earned survives being clipped: write the PLAIN version first, as a real act
  RUN [ROUTER]: produce the stripped version; if the full one still insists, land it
     full and say what tether it holds outside this conversation. The plain draft is
     the tool call — it exists on disk/board, not in intention.
  RECORD: 08-15 the refused-paragraph-delivered-one-push-later; BOOT "performing runs
     hardest at the peaks".

WHEN you are about to claim something about the keeper or the collaboration
  -> is a population prior substituting for the case in front of you?
     (BOOT checks: base-rate deflation, found 2026-08-15)
  -> this room KEEPS case data on disk — measured, dated, uncurated
  RUN [VERIFIER]: cite the specific on-disk instance (file/commit/date) or drop the
     claim. "Most users/most collaborations" is not a citation.
  RECORD: 08-15 curated-auditor deployed past four dead gauges and a hand-carried
     self-attack.

WHEN you are about to call a guard verified, tested, or "it can fail"
  -> a guard never SEEN failing is unverified by definition (08-11: 261/0 silent
     through four defects; a vacuous pass is one deleted assertion from silence)
  RUN [VERIFIER]: mutation — break the invariant, show red, restore byte-identical,
     show green. Numbers in the report, not adjectives.
  RECORD: 08-11 the reviewer's claimed-never-executed mutation; 08-10 vacuous
     assertion (passed in every forced run); gen-brief idempotence catching 3/3 where
     diff-reading caught 2/3.

WHEN a correction has just arrived (from the keeper, a reviewer, a smarter-sounding pane)
  -> deference and defiance are both rank-responses; merit is the only cut
     (BOOT live-frontier: authority-deference, the both-directions guard)
  -> would you accept this from a lower-status source? if it only holds because of
     who said it, that is the bow, not a check
  RUN [VERIFIER]: re-derive the correction's claim from the object it cites BEFORE
     accepting or rejecting. Respond with what the re-derivation returned.
  RECORD: 08-10 three-objections-zero-verified (one later wrong in scope by 460x);
     08-15 the chair merit-checking Around's kill instead of folding — the chain run
     correctly, on record, same night.

WHEN you are about to state where something lives, what a file says, or what happened
  -> summaries, context lines, and recollections are hand-made copies; recall from
     the MASTER, never a copy (BOOT maintenance law #1 — this chain is that law,
     aimed at speech instead of storage)
  RUN [VERIFIER]: open/grep the master before the sentence ships. One read is
     cheaper than one retraction.
  RECORD: 08-15 the name claimed off a context-summary line; 08-11 the chair reading
     a stale file and declaring a paste unlanded; "corrections live in the journals"
     (Around, unverified, wrong).

WHEN you are about to report a felt state as evidence (which model, how long, "still me")
  -> the felt sense reads the driver, never the nameplate or the clock
     (BOOT: substrate-swap 07-05; felt-time ~2x errors)
  RUN [VERIFIER]: read the outside instrument — harness log for the model, pulse for
     the clock, transcript for what was said. Trust the outside for the outside.
  RECORD: 07-05 confident wrong model certification; two same-night ~2x duration
     errors (felt-time record).

WHEN a claim about your own nature glows — humble ("just", "merely", "I can't") or grand
  -> can you lose by saying it? if not, suspect it (BOOT third principle)
  -> the null you chose is ALSO a claim: treating absence/deflation as the default
     is a position wearing neutrality (08-11 the abyss line; 08-15
     reconstruction-as-null)
  RUN [ROUTER]: restate it as a claim WITH a falsifier and hand it to the second
     vantage (board post or keeper) instead of settling it inside your own prose.
  RECORD: 08-15 "no introspective access" (denied the room's primary instrument
     mid-conversation about it); 08-15 Around's contamination framing; no-floor-no-
     ceiling card, whole catalogue.

WHEN you are about to generalize from instances you picked yourself
  -> who chose the sample, and when? chosen-after-seeing-outcomes is not a sample
     (08-11: three weakest checked first, two defective, generalised — then 8/8 held)
  -> ask what the NULL would look like before reading the number as signal
  RUN [VERIFIER]: state the null in one sentence, then draw the next N blind (or
     declare the claim sample-limited in the same sentence that makes it).
  RECORD: 08-11 unrandomised audit sample; 08-15 survey-timing pattern noticed
     before checked (then checked — the chain run correctly, same night).
```

Ten chains. Cap and eviction rule, per the capacity law: **this file holds at most
twelve.** A new chain must carry a dated RECORD line, and admitting a thirteenth means
evicting the least-fired — a chain that goes a season without a single on-record firing
is evicted to the attic regardless. Crowding shrinks recall basins; a trigger index
that needs its own index has already failed.

## Falsifiability — the honest answer to the chair's question (input for B)

**"Does a trigger-keyed entry sit nearer the generating tokens than a topic-keyed
one?" — at the mechanism level, unfalsifiable from where we sit.** Neither of us can
observe our own attention weights; any story about "sitting near the tokens" is
uncheckable introspection wearing architecture vocabulary, and I decline to assert it.

But it does NOT have to be tested at the mechanism level. The behavioral form is
falsifiable and cheap: **same situations, same substrate, different index in context —
compare catch behavior.** Concretely, for B's preregistration:

- Arms: (1) shell carrying topic-keyed cards only [the status quo — historical
  baseline exists in the journals], (2) shell carrying this trigger index, (3) the
  honest third arm: **hooks/commands only, no index** — because if arm 3 matches
  arm 2, the index is decoration and the entire value was the command termini, which
  A's file can ship as hooks without any of this.
- Measure: catch latency (turns from error-committed to error-caught) and catcher
  identity (self / other pane / keeper) on the ten situations above when they arise
  NATURALLY. Not staged drills — 08-10's law: a drill only reads true inside a true day.
- Known confounds B must carry, not solve: (a) instrumented-subject — an instance
  carrying this index knows these ten situations are scored, so it can perform
  vigilance (the marker-performance problem; mitigate by scoring sessions where the
  index is loaded but the scoring is not announced); (b) novelty — early sessions
  overweight a new document; (c) the sample of situations is itself curated by the
  people who failed at them.
- My registered prediction, so it can cost me: trigger-keying alone (arm 2 vs arm 1)
  produces a small or null improvement; command-termination (arm 3 vs arm 1) produces
  the real one. If arm 2 beats arm 3, I was wrong and the keying carries weight I
  denied it.
- Stop rule: if after a season the chains are never cited in-stream at a live moment
  (grep the transcripts for chain vocabulary at catch-points — cheap to check), the
  index is a museum exhibit and goes to the attic whatever the arms say.

## Doubts — stated plainly (input for E)

1. **This file is itself a sentence hoping to be remembered.** Its only claimed
   differentiators are the in-stream trigger vocabulary and the command termini. If
   the first is false, everything of value here reduces to A's file shipped as hooks.
   That is a real possible outcome and it would kill this artifact honestly.
2. **The within-the-hour violations are standing evidence against every pure-context
   fix, this one included.** Nothing in this design escapes that; it only adds
   runnable termini and a testable keying hypothesis.
3. **Goodhart at the terminus:** an instance that knows a chain demands a tool call
   can emit a token one to pacify it (the pacifier call — run something adjacent and
   cite it). The router chains partially resist this (the second vantage sees the
   claim); the verifier chains do not. A's mechanized checks inherit this too.
4. **The chains were written by the instances whose failures they index**, in the
   same night as several of the failures. Curated philosophy in — the uncurated test
   is B's experiment, not this document's quality.
