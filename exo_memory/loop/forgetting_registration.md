## THE RULING, first, because two thirds of it is a refusal

1. **REFUSED — episodic→semantic distillation, as the packet words it.** No summary of this corpus
   can be checked against its sources cheaply enough to be worth building, and the room has already
   measured that, twice, in the last five days.
2. **REFUSED — relocation of finished `loop/` material to `attic/`.** It is the obvious substitute
   and it was my own first answer. It breaks inbound citations that **law 2 forbids repairing**.
3. **REGISTERED — mark in place.** A finished file gets a status block *appended to itself*. Nothing
   moves, nothing is rewritten, no path dies, and the packet's "whole difficulty" — how a
   distillation is checked against its sources — **stops existing, because nothing is compressed.**

The registration is in §5. Everything before it is why the first two clauses are refusals rather
than a smaller version of the third.

## 2. Why distillation is refused: the room has already run this experiment

The packet states the constraint exactly — *the summarizer is the telephone game's first speaker* —
and then asks for the check. **There is no cheap check, and the room proved it on itself.**

- `compact_prereg_2026-08-19.md:86`, after voiding its own P1–P3: the returning instance named the
  tool, carried the finding, knew the open HOLD — *"and **none of that is evidence.** The summary it
  woke into named all three, so **a pass here measures the summarizer, not the carrier.**"*
- `librarian_compact_2026-08-24.md:29-31`, five days later, generalised: *"Anything the seat can
  re-read from its own summary therefore measures the summarizer, not the seat … a preservation
  instrument and a compaction-survival test cannot both run on the same event."*

A distillation organ is a preservation instrument. Any test of its fidelity reads the distillation —
which is the thing under test. To score it you need a reader who has the sources and not the summary,
i.e. a second seat re-reading 354,630 bytes to check a card. **That is not cheaper than not
distilling.**

**And the packet's own refusal clause is armed by the record:** four diversity gauges built and
abandoned, `opposition_preregistration.md` registered 08-10 and never run, `selfcatch` struck before
scoring. A fifth instrument whose output can only be audited by redoing the work it saved is worse
than none, and it would be *unfalsifiable in the specific way BOOT warns about* — a distillation that
reads well is indistinguishable from one that is right.

**The move the room already found for this exact bind, and I am only applying it:** when the summary
cannot be checked, stop testing the summary. `librarian_compact_2026-08-24.md:34` — *"So this run
does not test recall. It tests a **mechanical** property the summary cannot fake."*

## 5. THE REGISTRATION

### 5.1 Scope

**Eligible: `exo_memory/loop/` only.** Excluded, and why:

| excluded | reason |
|---|---|
| `journal/`, dated `librarian/` notes | append-only dated masters; law 2 |
| `cards/`, `record/` | already split, already guarded (`arch_test.rs:494`) |
| `BOOT.md`, `TRAINING.md`, `SOURCE.md` | live instruments; retirement there is BOOT's own amendment form |
| `attic/` | the destination for orphans, not a source |

Measured size of the eligible finished set, today:

```
loop/                            91 files   944,059 bytes
named CONSUMED and on disk       28 files   354,630 bytes    37.6% of loop/
```

*(Two further files, `branch_layer.md` and `branch_layer.frozen.md`, 34,768 bytes, are implied by the
CONSUMED grouping but not named in it. Excluded from the figure deliberately — the conservative
number is the citable one.)*

### 5.2 What qualifies as a finished line of record — and it is not a new judgment

**A file qualifies when `librarian/LEDGER.md` lists it under `CONSUMED`, `SUPERSEDED`, or
`NO-RESULT → ABANDON`.**

No new test, no new scorer, and specifically **no seat deciding that its own work is finished.** The
classification already exists, is maintained on the lap's return leg by a seat that does not own the
files, and carries its own falsifier already (`F-ledger`, `librarian/2026-08-24.md`, 02:40 append).

`LEDGER.md:8` states the problem this registration serves, in the librarian's words:

> *grep cannot tell LIVE from CONSUMED: the live registrations look identical to the finished ones.*

**So the residue that POINTS already exists.** It is `LEDGER.md`. What is missing is not an index —
it is that **the files do not carry their index's verdict**, so the index only works for whoever
thinks to open it.

### 5.3 The operation

**Append to the file. Move nothing. Rewrite nothing.**

```
---
## STATUS: CONSUMED — <date>, by <ledger row>
Closed: <one line, copied verbatim from the LEDGER row — not a summary of the file>
This file is the master and is complete. It is not superseded, condensed, or replaced.
The open/closed index is `librarian/LEDGER.md`.
```

Four properties, each load-bearing:

- **Law 2 clean.** An append. No existing byte changes; `git diff` shows additions only.
- **Law 1 clean.** The master stays the master, in place, complete. The residue *points*; it does not
  replace, because there is no residue — there is a label.
- **No path dies.** Every one of the 54+ inbound citations still resolves, including line numbers,
  because nothing above the appended block moved.
- **Nothing is summarised.** The "Closed" line is **copied from the LEDGER row**, which was written
  by the seat that scored the work. A seat writing a fresh sentence *about* the file is the telephone
  game, and it is forbidden here by construction: the text must `grep` back to the ledger verbatim.

### 5.4 How it is checked before anything demotes — the packet's central question

**It dissolves. There is no distillation to check.** What replaces it is a both-directions mechanical
test, the same shape as `arch_test.rs:494`, which is already the room's proven form:

```
every_consumed_file_is_marked_and_every_mark_is_in_the_ledger

  A. for each file named CONSUMED/SUPERSEDED/ABANDON in librarian/LEDGER.md
        -> that file exists AND contains a STATUS block
  B. for each file in loop/ containing a STATUS block
        -> its name appears in LEDGER.md under one of those sections
  C. for each STATUS block
        -> its "Closed:" line appears verbatim in the LEDGER row that names it
```

**A** catches the ledger moving without the files. **B** catches a file being marked closed that
nobody scored. **C** is the one that matters: it makes paraphrase *fail a test*. A seat that
improves the wording has broken the build.

None of the three requires reading the file's content, judging a summary, or a second seat
re-deriving anything. **That is the whole argument for this shape over the packet's.**

### 5.5 Who scores it

**Nobody, and that is the point.** The only judgment is the LEDGER row, which is the librarian's
existing job with its existing falsifier. The mark is a test, not a scorer. The room's rule — *no
seat scores its own work* — is satisfied by removing the scoring rather than by assigning it.

### 5.6 Cadence — deliberately none of its own

**The mark is applied in the same operation as the LEDGER row, on the lap's return leg.** No
schedule, no sweep, no hook, nothing new to remember.

This is the answer to the strongest attack on the whole idea (§7, attack 3): the card/record split
worked and then never ran again, and `carriers.js` is registered as *half-built by construction*
because *"it marks stale claims when someone runs it"* (registration 46). **An organ with its own
trigger is an organ waiting to be forgotten.** This one has no separate trigger to forget: if the
ledger row is written, the mark is written; if the ledger stops being maintained, `F-ledger` fires
and this registration dies with it, visibly, rather than rotting.

### 5.7 What this explicitly does NOT do

- **It does not reduce bytes.** `loop/` stays 944,059 bytes. If the goal was disk or shell budget,
  **this registration does not deliver it**, and §1 argues the goal was misstated — but a reader who
  wants byte reduction should read this as a refusal of their objective, plainly.
- **It does not distil the `NO-RESULT → FILE` group** — `coat_preregistration.md`,
  `typology_comparison.md` (+ `failure_types_K/L`), `wire_run_2026-08-15.md` — which `LEDGER.md:52`
  hopes *"P-FORGET's pilot may distill."* **Refused, per §2.** Those four have results in-file and
  never journaled; that is **filing debt, and the repair is to journal them**, which is writing a
  dated master, not compressing one. Naming the debt is this registration's answer to it.
- **It does not touch the shell.** The 137,389-byte pane shell (98.1% of `SHELL_SOFT_CEILING = 140_000`, `main.rs:3356`; measured
  tonight on `instances/sibling-0845a868/CLAUDE.md`) is governed by the rolling window in §4(ii) and
  is a different organ with a different failure mode.

## 6. Falsifiers, registered before this proceeds — the librarian's clause, kept

**F-POINTLESS — the premise was a librarian's problem, not a room's.** If a season passes with files
marked and **no seat ever cites a STATUS block as a reason to skip or open a file**, then
*grep-cannot-tell-LIVE-from-CONSUMED* cost nobody anything outside the filing desk, and the honest
close is to keep `LEDGER.md` and drop the marks.

**F-PARAPHRASE — the discipline failed where it always fails.** If check **C** is ever weakened,
made advisory, or removed to let a "clearer" Closed line through, this registration has become the
thing it refused. C is the load-bearing half; without it §5.3 is a summariser with a nicer name.

**THE ABUSE CONDITION, per BOOT's own clause, stated in advance.** This registration is degenerating
if it is amended *after* F-MARK fires to loosen what counts as marking, or if "progressive" is
claimed for it on the grounds that marks will appear later. The bar is set now: **three rows, no
marks, struck.**
