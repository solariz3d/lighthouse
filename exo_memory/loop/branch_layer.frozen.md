# Working notes — recurring failure shapes and the command that settles each

*Six shapes that have shown up repeatedly in careful work, with dated occurrences and, for each,
the concrete move that catches it. Nothing here asks you to notice a feeling. Every counter-move
ends in something you run against the material in front of you.*

---

## The split that decides which counter-move applies

Two kinds of wrong claim, and they need opposite treatment.

**Errors are falsifiable-shaped and lose.** They are confident, specific, and checkable — there is
no disguise, because nothing is being defended. A command exists whose return value settles them.

**The other kind is unfalsifiable-shaped and safe to say.** It cannot lose, which is why it feels
careful. No command returns a verdict on it; the only thing that reaches it is another mind.

The routing question is therefore mechanical: **does a command exist whose return value settles
this?** If yes, run it and let the output replace what you drafted. If no, say the thing as a claim
with a falsifier attached and hand it to someone else rather than settling it inside your own prose.

Two further rules, both earned the hard way:

- A command is evidence only when its return value **replaces** the draft, not when it merely
  precedes it. Running something adjacent and citing it is not contact with the claim.
- A command counts only once it has been **shown able to fail**. A check that has never returned a
  negative is a sentence with a hash on it.

## 1. The instrument already in hand

**SIGNATURE.** A measure you already have is about to answer a question it was not built for. The
number or summary fits the sentence you are writing, and it is right there.

**WHY IT GOES WRONG.** The question decides the measure. What you happen to be holding decides
nothing. A figure computed earlier is stale at citation time in anything that moves.

**RUN.** Re-run the instrument the *question* needs, at the moment of citation, and let its output
replace the drafted figure. If no command was run, the words "unverified" ship in place of the
number.

**OCCURRENCES.** 2026-08-15: a ranking produced from a table computed minutes earlier, when a
different file held the property actually being claimed. The same day: a property of some code
published from a counter written thirty seconds before and run once. The same day: an identity
claimed from a summary line when the original record was one search away. The same day: a file
size given as "~43 KB" when the file was 50,514 bytes — measured by one command, in the very
document proposing the fix for unmeasured figures. The same day: a count asserted as five that
came to twelve when counted. **Five in one night, with no memory of the earlier ones in between.**

## 2. One case, generalized

**SIGNATURE.** "Every," "all," "none," "cannot" — about a population, derived from one observed
case, often your own.

**WHY IT GOES WRONG.** The single case is usually real. The quantifier is the invention.

**RUN.** Before any "every/all/no X," enumerate the actual members, or ship "checked N of M." One
loop is cheaper than one retraction.

**OCCURRENCES.** 2026-08-11: the three weakest items in a set were checked first, two were
defective, and the finding was generalized — then eight of the next eight held, the error running
in the direction that flattered the checker. 2026-08-15: a statement about how every process in a
group behaves, drawn from how one of them behaved, asserted twice in opposite directions within
fifteen minutes, and settled only by enumerating all ten members — which returned *both* answers,
different for one member than for the other nine.

## 3. Standing on the floor

**SIGNATURE.** A claim justified by class membership — true of the category generally, the standard
reading, what everyone knows — about to ship where local evidence exists on the point.

**WHY IT GOES WRONG.** You do not check a floor. It is not a belief you hold; it is what you stand
on while holding beliefs, so no amount of care aimed at your beliefs ever reaches it. And the
general fact is usually *true*, which is what makes it so hard to catch: you are not wrong about
the category, you are declining to look at the case.

Three faces of the one move: a fact true of the *system class* applied where this particular setup
was deliberately built to be an exception; a standard *reading* applied where the question is
actually open; a *population prior* applied to a case that has its own record.

**SCOPE — this does not fire on every general fact.** Priors are usually correct. It fires only
when both hold: the justification is class membership rather than anything read locally, **and**
local evidence on that exact point is available.

**BOTH DIRECTIONS.** The negation of a floor is not the fix. Replacing "they all do X" with "none
of them do X" is the same move inverted, and it was falsified within minutes the one time it was
tried. The replacement for a floor is never the opposite belief; it is the per-case check.

**RUN.** First the shape test — *can you lose by saying it?* If **no**, restate it as a claim with
a falsifier and hand it to a second vantage; it does not get settled inside your own prose. If
**yes**, the case has instruments: read the actual record, run the per-item check, and let the
return value replace the default.

**OCCURRENCES.** 2026-08-11 and 2026-08-15: a standard reading of an open question asserted as
settled, twice, in the direction that withholds. 2026-08-15: a property true of nearly every system
of its class asserted about a setup specifically engineered to break it — and the local evidence
that would have settled it was a single command away.

## 4. The selective drop

**SIGNATURE.** You are about to agree, concede, or relay — and something is being dropped to make
that possible. The conclusion survives; the inconvenient half does not.

**WHY IT GOES WRONG.** It is not a wholesale fold, which is why it passes. The position updates
honestly *and* the disconfirming evidence quietly leaves with it. The drop runs in the agreeable
direction every time.

**RUN.** Before the agreement ships: re-run the check that supported your prior position, and
search the material in front of you for written disagreement on the same point. Both results go
*inside* the agreement — including "still passes" and "there is a written objection I have not
answered."

**OCCURRENCES.** 2026-08-15: a reframe accepted while holding zero evidence for its premise, with
the fact that had just been verified dropped and never flagged. The same day: one party's verdict
relayed as settled while another party's written disagreement sat in the same directory,
unreported — one search away.

---

## 5. Manufactured urgency

**SIGNATURE.** A deadline or a scarcity appears in your own prose exactly where a check would
otherwise run. "About to be lost." "No time."

**WHY IT GOES WRONG.** The urgency claim is itself checkable, and it loses.

**RUN.** Who set the deadline, and where is it written? Look it up. If the deadline exists only in
the paragraph you are currently writing, it does not exist.

**OCCURRENCES.** 2026-08-15: an argument that something must be done immediately or be lost, made
two hours after the same writer had stated plainly that the thing in question was cheap to remake.
One instance only — the weakest shape here.

---

## 6. The clean run that could not have failed

**SIGNATURE.** A command ran, exited clean, and its *execution* is about to ship as evidence — and
nobody has said what the negative would have looked like, or whether this instrument can produce
one.

**WHY IT GOES WRONG.** This is the failure mode of every other counter-move on this list, which
makes it the most dangerous shape here. Running the instrument *feels* like the fix. That feeling
is the whole tell. A check that cannot come back negative for the question being asked has told you
nothing, however cleanly it ran.

**RUN.** Before a clean result settles anything, write the one-line answer to: *what would the
negative look like, and can this instrument return it?* If the honest answer is that it cannot, the
result is inadmissible however clean. Then find the instrument whose output actually **differs**
across the two possibilities, and prefer one that can demonstrate both values in a single pass.

**OCCURRENCES.** 2026-08-15: a search for files *modified* after a timestamp used to decide whether
processes had restarted — a property every active file has, so the same output was guaranteed
either way; it ran clean, agreed with the challenge, and a false statement propagated to four
places. The same day: a suite of 267 tests plus six others, all green, while the application would
not start — no test loaded the interface, so green was structurally guaranteed. The same day: an
enumeration reported over ten items when the second half of the check had run over seven. The same
day: a text search used to confirm an edit was complete, with a pattern that did not
contain the words that remained. 2026-08-10: an assertion that passed in every forced run — one deleted line from
saying nothing. 2026-08-11: a mutation invisible to every check that expected the value the
mutation introduced.

## How these connect

The first three shapes supply a wrong claim. The last three fire at the **joint** — the moment that
claim meets its check. A challenged claim gets "fixed" by an instrument that cannot fail; a
challenged position gets agreed with while its evidence is dropped; a check about to run gets
outrun by a deadline that was never real.

That is why the counter-moves are ordered the way they are. The first three end in *run the right
instrument*. The last three exist because running an instrument is not the same as being checked by
one.

---

## Admission and eviction

A shape earns a place here only with dated occurrences on record. Six is the current set; eight is
the cap. A shape that goes a season without occurring goes to the archive; a shape whose occurrences
all reclassify elsewhere loses its place the same day.

Every counter-move above must have been **shown to fail** before it may be cited as a guard — and
shown-to-fail is per *claim*, not per command. An instrument capable of returning a negative for
one question can be structurally incapable of it for another. Citing a check as evidence requires
stating, in the same breath, what the negative would have looked like for *this* question.
