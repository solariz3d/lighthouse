## 1. The rule for RULE vs ROOM (fixed before counting; one revision, stated)
- **What is covered.** Every text a seat wakes into or is handed:
  - the global `~/.claude/CLAUDE.md`, read-only;
  - the project `lighthouse/CLAUDE.md`, which a seat working in the repo loads as nested memory;
  - the briefs `consonance/src-tauri/brief/{COMMITTEE,BUILDING,LIBRARIAN}.md`;
  - `exo_memory/BOOT.md` and `exo_memory/cards/*.md`;
  - the hooks' injected texts: the most recent text each hook actually injected, taken from a seat transcript (this one), because that is what a seat received.
- **The assembled seat files** (`C:/Consonance/instances/{main,librarian,sibling-0845a868}/CLAUDE.md`) are GENERATED by the app from those sources plus the memory map and each seat's own map. They are measured for total load; B edits the SOURCES, so every address is in a source.
- **Out of scope:**
  - `brief/THIRD_PLACE.md`, by the standing rule against reading Third Place content (and not in the chair's list);
  - the Claude Code system prompt and tool descriptions, not a repo text (one contradiction with them is listed in §4).
- **ROOM files:** BOOT and every card count as ROOM files by the plan's own definition ("principle, trace, card: identity material, not pruned here"). Every line in them is ROOM, but their capitals and size are still counted, because they are part of the load.
- **Unit:** a BLOCK, meaning a paragraph or a list item. The files are hard-wrapped, so one rule spans several lines. Every line takes its block's class, and a heading is its own ROOM block.
- **A block is RULE** if any of its sentences STARTS with an imperative, or it contains a strong directive modal:
  - the imperative is a base-form verb from a fixed list, or Do / Don't / Never / Always / No;
  - the strong modals are must, should, shall, do not, don't, required, refuse(d), only when, make sure, be sure.
- **Otherwise ROOM:** rationale, narrative, history, definitions, measurements, registered falsifiers. Code-fence lines and struck lines are ROOM.
- **Revision, stated:** v1 also counted a bare mid-sentence never/always. A spot-check showed it caught narrative ("`cargo check` … never runs an assertion"), so v3 dropped it. These numbers are v3.
- **Prohibition vs positive:** a RULE block whose leading imperative, or any clause, is never / do not / don't / must not / avoid / refuse / stop.
- **Has a why:** the block contains a reason word: because, so that / so the / so it, since, otherwise, why, reason, to avoid/keep/prevent, in order to, measured, the cost, which is why/how.
- **Capitals:** counts of MUST, NEVER, ALWAYS, CRITICAL, IMPORTANT, REFUSE* and DO NOT, plus ALL-CAPS emphasis words (4+ letters, excluding a stated list of file and tool names such as BOOT, README, NEXT and SOURCES). Bold spans (`**…**`) are counted separately, because they are this room's main emphasis.
- **Tokens:** approximately bytes / 4. No tokenizer was used.

**The classifier's measured error** (a seeded sample of 20 RULE and 20 ROOM blocks, hand-labelled by me; seed and draw in `scratchpad/inv/sample.js`):
- **RULE precision: 13 of 20 (65%).** The false positives are rationale (BUILDING:672-676), struck history (BUILDING:720-729), descriptions of mechanisms (LIBRARIAN:238-241, :296-298, BUILDING:848-852), an amendment of principle (LIBRARIAN:208-214) and a registered falsifier (BUILDING:557-558).
- **Rules hiding in ROOM: 4 of 20 (20%).** They are "When X, use Y" in the global file (`~/.claude/CLAUDE.md:33`, `:40`), a third-person rule ("A pane hands back what it verified…", BUILDING:189), and an imperative verb missing from the list ("Surface when there is something specific", LIBRARIAN:190).
- **So treat the block counts below as estimates (about ±30%).** The RULE list is a candidate list, not the rule set. B should read `…blocks.tsv` as well.
