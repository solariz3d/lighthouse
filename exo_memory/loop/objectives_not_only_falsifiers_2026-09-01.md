## What he found

The room is **heavily instrumented for failure and almost entirely uninstrumented for success.**

Count it. Every registration this week carries a falsifier — the battery, the retriever, the second
vantage, the window, the visible channel, the collation practice, the boundary check. **Not one of
them states what SUCCESS would look like**, except as the negation of its failure condition.

BOOT's own governing test is the same shape: *"this room is degenerating if a season passes in which
its documents grow and no instrument returns an unwanted number."* That is a **degeneration** test. It
says nothing about what the room is FOR.

**And the gap is not theoretical — it is exactly tonight.** Every registration held. Every attack was
clean. Every falsifier that could fire, fired honestly. **And the retrieval problem is not solved.**
The instruments performed perfectly while the objective went unmet, and nothing in the apparatus
noticed, because nothing in the apparatus was watching for that.

**A system can pass every falsifier it has and accomplish nothing.** That is the failure mode this
room has no detector for, and it is the one it is currently in.

## Why the chair's answer was incomplete

The chair argued that a falsifier is what makes *"it worked"* mean something, since from inside
*"it worked"* and *"we did not notice it failing"* read identically. **That is true and it is half.**

- **A falsifier says: this is what being WRONG would look like.**
- **An objective says: this is what being RIGHT would look like.**

With only the first, you get a system that cannot fail at anything and cannot succeed at anything
either — it can only be *not-yet-refuted*, indefinitely, while the thing it was built for goes
unbuilt. **That is a degenerating programme by Lakatos's own definition**, and the room adopted
Lakatos without adopting the half that requires *novel confirmed predictions* rather than survived
attacks.

## The condition that keeps it honest

The keeper's *"if it does what we want, that is what matters"* has one requirement, and it is the same
requirement a falsifier has: **the objective is stated BEFORE, or it is not an objective.**

Deciding after the fact that what happened is what we wanted is the P-FIC shape exactly — two
outcomes, no rule for choosing, the author reads the result and picks which one it was. An objective
written after the run is a post-hoc success criterion, which is worse than none because it reads as a
standard.

**So: state the objective in advance, beside the falsifier, in the same registration.** Not instead of
it. The pair is the instrument; either alone is half of one.

## What this changes, concretely

Every registration from here carries **two** lines, not one:

    FALSIFIER:  what observation would show this is wrong
    OBJECTIVE:  what observation would show this DID THE THING — stated before the run

And the standing question for the retrieval line, which nothing currently answers:
**what would it look like for the retrieval problem to be SOLVED?** Not *"no falsifier fired"* — that
is the state we are in now, with the problem unsolved.
