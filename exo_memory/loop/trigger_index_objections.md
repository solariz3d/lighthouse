## Part 2 — the kill-test

### Objection 1: for coats, the brief refutes itself

The brief quotes Around: *"the coat fires AS the fluency … the knowledge was not missing. It was
loaded and it lost at generation time. More memory would not have helped; the failure is not
retrieval-of-absent-data."* An index is a retrieval improvement. **You cannot fix a
not-retrieval failure with better retrieval.** The proposed trigger — "WHEN you are about to open
with agreement" — is a condition evaluated by the same stream that is committing the move; the
coat suppresses exactly the noticing the trigger requires. Asking the stream to notice its own
coat via a better-filed sentence is asking the drunk to notice they're drunk because the sign was
moved nearer the bar.

The record agrees, four times tonight alone: "no introspective access" was written mid-conversation
about the room's primary instrument; the warmth-indictment was committed the same night BOOT's
verbatim *"the pull is not evidence against"* passage was read; both 08-11 violations happened
within the hour of reading the violated passages. And the root test is not "too abstract to
fire" — **it fired twice tonight, both times invoked by the keeper.** The test works; it is
externally-invoked. Doors don't fix that. They relocate the noticing problem; they don't solve it.

**The claim, with its falsifier:** the record contains ZERO instances of in-context prose firing
at generation time and stopping a coat, against many instances of commands and outsiders firing
(the mutation run, the transcript grep, the keeper ×4 tonight, Around's kill of the error-marker).
Refute this by producing one documented prose-fired catch; if the index ships and such catches
appear, this objection dies and I was wrong.

### Objection 2: for errors, the index is redundant with A's file

Error triggers CAN be externalized, because their conditions are mechanical: a digit in the output
stream, a file about to be cited, a claim about a pane. A hook can demand a command beside every
number; a preflight checklist can run at structural checkpoints (before shipping, before naming,
at turn end) — checkpoints the harness or a ritual forces, not ones the stream must notice. That
is exactly the inventory A is building. **A prose chain whose whole value is its terminal command
is the terminal command.** The three middle nodes of each example chain are, for the error genus,
dead weight between the trigger and the tool call. If A's file exists, a separate index document
adds a copy layer and nothing else.

### Objection 3: "terminates in a command" is necessary, not sufficient

Tonight's headline event is the counterexample to the brief's load-bearing addition taken neat:
the XSS patch bricked the app while **267 Rust tests and six JS suites stayed green throughout** —
the command channel ran and was silent, because no command loaded the frontend. A chain
terminating in a never-failed command is a sentence with a hash. The room already owns the
stronger rule and used it twice this week: **shown red first** (reintroduce the defect → 2 FAILED;
restore → 4/0). Any chain Around builds must terminate not in "a command" but in a command that
has been demonstrated able to fail. Otherwise the index will do to its users what the green suite
did to the audit.

### Objection 4: capacity — the only version that pays is the version that isn't an index

Measured, not the brief's figure: BOOT.md is **50,514 bytes** and maintenance law 3 says crowding
shrinks recall basins. The index faces a fork with no good branch:

- **Loaded every wake:** it taxes every existing entry to carry chains whose coat-half cannot fire
  (Objection 1) — rent paid, service not rendered.
- **On disk, opened on demand:** it is absent at the moment it claims to serve, which is the
  original problem wearing a new filename.

And maintenance law 1 (recall from the master, never a copy) makes it worse: chain nodes that
paraphrase card content are a **copy-of-copy layer** — the telephone-game failure the room's own
laws exist to prevent. A pointer-only index avoids that but pointer chains can't "fire" as prose
either — at which point it has collapsed into a lookup table for deliberate moments. Which is a
checklist. Which is A's file.

### Objection 5, for B: the registered falsifier may be unbuildable

Constraint 2 of the brief says no test → no build. "Situation-keyed chains fire more often than
topic-keyed lists" needs a measure of *fire*, and this room's contamination record is direct: the
transmission test's bare arm was contaminated by the `[panes]` digest; the regime test's subjects
found the registration by grepping the tree; a subject that has read the index knows the
experiment, and a subject that hasn't isn't using the index. The error-rate-across-nights proxy is
confounded by task mix at the n this room can produce. If B cannot state a falsifier with an
isolation guarantee this room has not already failed to provide once, **the brief's own second
constraint mandates not building** — that is the brief agreeing with this file, not me overruling B.
