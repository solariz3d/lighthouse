## What it is

A seat can't take in motion, but it can read images in order. So the tool records what is on his screen and turns it into numbered contact sheets that a seat reads like an animator's exposure sheet.

## Parts: one pane, E (check it; the capture guards are prove it)

1. **ffmpeg.** Install it with `winget install Gyan.FFmpeg` (or the official build), and record the version and path. Nothing else is installed.
2. **`consonance/tools/watch.js record`** captures the desktop with ffmpeg `gdigrab`.
   - Options: `--seconds N` (default 10, max 120), `--fps` (default 12), `--window "<title>"` to capture a single window, `--monitor`.
   - It runs at BelowNormal and never takes focus. He races while things run, so it must not steal frames from his game; the hand-back measures its CPU and GPU cost while recording.
3. **`watch.js sheets <video>`** turns any video file into contact sheets.
   - Each sheet is a 4×4 or 4×6 grid of frames, each frame stamped with its number and time.
   - A motion sheet sits beside each one: the difference between consecutive frames, bright where things moved.
   - Shot changes break the sheets (ffmpeg `select='gt(scene,…)'`).
   - It writes an index listing every sheet in order with its time range, for a seat to read top to bottom.
   - Optional: if the video has a subtitle track, its lines go next to each sheet's times.
4. **Where things go.** Recordings and sheets go only to `private\watch\` beside the instances folder: never a repo, never the board. The tool refuses an output path inside a git work tree, as lineage-rip does, and can reuse its check.

## The guards (prove it: a screen can show credentials)

- **On his command only.** Recording happens only when `record` is run, for a fixed length. Nothing runs in the background, there is no schedule and no continuous capture, and there is no hook that starts it. A test confirms the tool has no loop or daemon mode.
- **Private by default.** The output stays local. Its folder is outside every repo, and the in-repo refusal is tested.
- **Visible.** While recording, the tool prints the start, the end and the file path. It never records silently.
- **Removal.** `watch.js clear` deletes the private\watch folder's contents, but only when he says so, never automatically.

- `record` for 2 seconds of the screen, at the default and at `--window`: the file exists, its length is close to 2 s, and the process exits.
- The refusal of an in-repo output path. The cap on length.

## Amended, 12:53: Watch becomes part of Consonance, beside Listen

The keeper, 12:51: "I wonder if we make it apart of consonance itself, we have listen, now watch"

**The prior art, checked.** Consonance's ◍ Listen tab is THE COCHLEA (main.rs ~:4015–4040; wired end to end 2026-07-29, 81707a36): "listening to one application, as ratios rather than as a spectrum".
- It is optional and off until a source is picked.
- It captures one process's audio by loopback, so picking Spotify never delivers Discord.
- It refuses while an anti-cheat is present (`listen::anticheat_present`).
- The one source that could hear a voice call is flagged and offered last.

Watch copies that design point for point:
- **A ◍ Watch tab, off until a source is picked.** A source is one window by default, chosen from what is running. The whole desktop is offered last and flagged ("everything on your screen, including any password you type").
- **One window means one window.** Picking the Netflix window never captures his chat. This is the visual twin of per-process loopback.
- **The anti-cheat check is reused** (`listen::anticheat_present`). Watch refuses while one is present, as Listen does, since he races.
- **Start and stop are his.** A visible recording state, a length cap, no background capture, no schedule, no hook.
- **The output** is a clip in `private\watch\` and its contact sheets plus motion sheets. A seat reads them through `watch.js sheets` (part 3 above), which stays a tool so any video file works too.
- **The capture path:** a Windows Graphics Capture crate, or ffmpeg as a sidecar. Choosing one, and any new crate, comes back to the keeper as a dependency ask with a version, before it is added.

## Amended, 13:06: see change, not frames (the keeper's method)

The keeper, 13:04: "it shouldnt scan every frame one by one, rather measure what changes in a way between frames … if there is a static scene, it only takes what changes into account so its not analyzing the same image over and over."

This replaces the fixed-rate contact sheets in part 3. **Watch reads change, the way Listen reads ratios rather than a spectrum.**
- **A key frame** is taken at each shot change (scene detection), and once more when the accumulated change since the last key frame passes a threshold. The scene is shown whole only then.
- **Between key frames, only what changed:**
  - for each moment where change passes a floor, the crop of the region that changed, its box, and how much;
  - a still stretch collapses to one line, "held 3.2 s, nothing moved";
  - slow drift (a pan) is reported as motion of the whole frame, not as everything changing.
- **The motion picture of a burst** shows where things moved and how far between poses (frame differences, or optical flow if cheap). That is the spacing an animator reads, King moving like the wind.
- **Cost follows activity.** A still scene costs almost nothing; a fight costs what it shows. The index records how many frames were read against how many there were, so the saving is a measured number, not a claim.
- This is the same idea as video compression (key frames plus changes) and as an eye, which responds to change and not to stillness. The tool states both as its design, and the tests check it: a static synthetic clip yields 1 key frame plus a held line; a moving square yields crops that follow it.
