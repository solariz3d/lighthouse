## 1. THE FIX WAS RIGHT AND IT SHIPPED A ONE-BOX PATH

`25265ba` repaired a genuine bug: the hook's only-ever `compact/emitted` row was
`{"chars":105,"failed":true}` — `[state-block FAILED: generator not found on any known path]`. Not
landed-is-not-shipped; `md5` matched. `findGenerator()` simply missed on the desktop. `fromConfig()`
was added, reading `~/.consonance.json` → `room_path` → repo root. Correct, and it works.

**But the repair kept a third candidate: a literal `C:\Consonance\lighthouse\...` — the laptop's
checkout — "because it is correct there."** It is not correct there; it is *redundant* there, and it
is harmful everywhere.

## 2. MEASURED, NOT ARGUED — two mutations on temp copies, before touching the repo

    M1  strip the literal, run flat with the REAL home
        -> C:\Consonance\lighthouse\consonance\tools\state-block.js
        => fromConfig() already carries this laptop ON ITS OWN. The literal was dead weight.

    M2  strip fromConfig(), run flat with the REAL home
        -> C:\Consonance\lighthouse\consonance\tools\state-block.js
        => STILL resolves, via the literal.

**M2 is the finding.** `25265ba` registered a mutation proof for its own new test: *"delete the
`fromConfig()` candidate and this goes red while all ten tests above stay green."* **That proof holds
only on a machine where the literal is absent.** On the laptop, deleting `fromConfig()` changed
nothing observable — the literal answered in its place, and the test stayed green.

So the one literal disarmed **both** of the file's machine-independence tests, in opposite
directions:

| test | laptop | desktop |
|---|---|---|
| `a HOME with no .consonance.json degrades to null` | **FAILED** (literal exists, so not null) | passed |
| `resolves the generator when installed FLAT` | passed, but **could not go red** under its own mutation | passed, mutation-proven |

`js-suite` read **38 green · 1 failed** here against the **39 green · 0 failed** in `25265ba`'s
message. Both numbers were true on the machine that produced them. Neither was a property of the code.

**This is the same class as the bug being fixed, one layer up.** The journal entry shipped with that
commit says it plainly — *"A file written to be portable, carrying one box's layout inside it"* and
*"a test that cannot reach the machine cannot testify about the machine."* The fix for that defect
contained that defect.

## 3. WHAT CHANGED

The literal is removed. `findGenerator()` is now `[repo-relative, fromConfig()]` — with the reasoning
above in a comment beside it, so the next reader does not re-add it as a kindness. A machine with no
`room_path` returns `null` and the hook emits its **loud** FAILED notice, which is the designed
behaviour and strictly better than confidently naming another box's disk.

**Verified, in this order:**

- the previously-red test goes green; suite `exit 0`
- **the registered mutation now fires on this laptop, which it could not do before** —
  `node dev/mutation/mutate-sss-flat.js` → **2/2 killed**, and the red test is exactly *"resolves the
  generator when installed FLAT"*. Restored byte-identical after each mutant.
- `js-suite: 39 green · 0 failed · 0 crashed · 0 silent · 1 canary (of 40)` — the same number
  `25265ba` reported, now true on this machine too
- **shipped, not merely landed**: copied to `~/.claude/shell/`, `md5` parity confirmed
  (`becb1ed7…`), and the **installed** copy run end-to-end with `source=compact` →
  **1,216 chars, `failed:false`**, carrying real REPO/JOURNAL/INSTRUMENTS state. The 105-char failure
  notice is gone.
- the verification wrote its ledger row to a **temp `CONSONANCE_DATA`**, not the production ledger
  whose job is counting real compactions — that pollution was a real defect on 08-18 (~141 rows).

*Deliberately targeted rather than a full `install.ps1` sync:* the 11 drifted files and the one HELD

## 5. REGISTERED

    fallback answered for whichever candidate was deleted. The check is cheap and is now the rule for
